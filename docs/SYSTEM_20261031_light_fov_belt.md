# 2026-10-31 — 三个系统决策：环光、夹具没了怎么办、收窄视场怎么收（含传送带约束）

> 这份记录回答三个连在一起的问题，并给出各自的**实测依据**与**代价**。
> 结论一句话：**夹具没了不是问题，因为传送带的停机位就是夹具；但传送带会逼出两条硬约束——
> 要么停机拍照（停机重复性必须 <0.5 mm），要么把曝光压到 1 ms 量级（那才需要环光）。**

## 1. 传感器窗口（今天读的，部分寄存器读失败）

`ps_fft_dual/sensor_window_read_20261031.tcl`（只读，核停后读、读完恢复）：

```
camera0: 读出窗口 x 0..2623  输出 1280x720  HTS 1892  VTS 1200  ISP 偏移 0/0
camera1: 读出窗口 x 0..2623  输出 1280x720  HTS 1892  VTS 读失败(-80, 寄存器读错)
两路的 y 起止有一个字节读失败（读到 -1），(0x3800..0x380F 的个别字节在长线上不可靠)
```

可确认的部分：**传感器读的是全阵列（2624 宽），由 ISP 缩放到 1280×720**，不是 2×2 binning
（ISP step = 0）。所以：

- **收窄视场有两条路**，寄存器那条是通的（价：一个模式表 + 重标定）；
- 收窄后输出仍是 1280×720 → **PL 与固件的几何表不用改**；
- 代价是视场只覆盖板的约四分之一 → 要么分块拍、要么只查感兴趣区。

## 2. 三条路的判据与代价

| 问题 | 答案 | 依据 | 代价 |
|---|---|---|---|
| **现在加环光吗** | 加，**理由已更正为"压镜面高光"**，不是"光预算" | 初版写"为飞行拍摄的光预算"是自相矛盾的：飞行拍摄正是本文自己否掉的方案。低角度照明的用处是压掉直接镜面反射——划痕露铜，正面白光下铜会被镜面反射成蓝白，暖色签名被摧毁（此条为外部复核引用，**我在仓库里没找到对应的 R−B=−6.5 实测，见 §5**） | 装低角度；装完用同一套 5 次摆位复测缺陷响应与摆位散布 |
| **夹具做不了怎么办** | **传送带的停机位就是夹具** | 项目已有传送带骨架与"停在 550/站台 B"的主机侧代码，但**一次没上板** | 需要量**停机重复性**：同板、同停位、5 次，用 `place_area` 同一把尺 |
| **收窄视场怎么收** | 优先**寄存器裁剪**（1:1 窗口），其次换镜头/降相机 | §1：现在读全阵列再缩放，1:1 窗口可得 2× 放大且不动管线 | 模式表 + 重标定；视场只剩 1/4，需分块或 ROI |

## 3. 传送带带来的两条硬约束（**已更正，并现场实测**）

**先撤回两个错误的数**：本文初版写"行时 = 10 ms / (4331/16) = 36.9 µs"，
外部复核提出形式错误（10 ms 是快门锁周期、不是帧周期，正确应 `行时 = 帧周期 / VTS`），
**提得对**；但复核给的 21.5–24.7 ms 与本版的 20.0 ms **都不对**，因为**帧周期是会话量**。
2026-10-31 17:2x 现场实测：

```
frames 119214 -> 119282 over 6.03 s  ->  11.271 fps      （MB_FRAMES 计数）
fpsx10 字（固件自己的测量）           =  11.4 fps          ← 两个独立通道一致
VTS 字 529                            =  1200
行时 = 帧周期 / VTS = 88.72 ms / 1200 =  73.93 µs
曝光 541.4 行 × 73.93 µs              =  40.03 ms
带速 50 mm/s -> 2.0 mm = 40 px 的运动模糊
```

**为什么三个数都不一样**：项目自己记录过开机两种状态（快态 15.15 fps / 慢态 1.79 fps），
复核引用的 21.02/18.24 fps 是另一次会话的测量。**帧周期、行时、曝光时间都是会话量**，
传送带的运动模糊预算必须**当场量**，不能引用任何一次的数。

**这才是真正致命的**：按实测 40 ms，一条 1–3 px、约 58 灰的划痕在 40 px 的模糊里摊薄到
**每像素 1.4–2.1 灰**——低于 EG 的 14 灰门限，也低于幅度判据的 30 灰，差了 7–20 倍。
所以"停在位拍照"不是选项之一，是**唯一可行项**；飞行拍摄要把曝光压 40 倍（≈1 ms），
那需要约 40 倍的光。

## 4. 建议的顺序（互相不阻塞）

1. **装环光（低角度）**，然后用 `place_area` 的同一套 5 次摆位复测两个数：缺陷响应是否上升、
   摆位散布是否变差。10 分钟，不重构建。
2. **量传送带停机重复性**：同板、同停位 5 次，用同一把尺。这一步决定"夹具"问题是否自动消失。
   **它比收窄视场便宜得多，也可能把今天的结论整个翻过来**（摆位项降一个量级 → 现有统计量重新有意义）。
3. **收窄视场**：先做寄存器版（1:1 窗口），因为不动管线；分块拍/ROI 的设计随后。
   注意 HTS 变化会改行时，10 ms 闪烁锁与曝光梯级都要重新推导（固件运行时会读 VTS，但不是全部）。

**没有找到这条具体测量**。所以本记录把它标为"复核引用、待指认出处"，
并在下面给出一条便宜的独立验证路：

- 10-29 的 80 块板原始帧是三通道 24 位（`dl\sweep_frames\20261029_181623_sweep\*/frame.bin`，
  每像素 3 字节），所以 **R−B 可以在划伤板的候选格上直接量**：
  取该板 G 残差最大的 1% 格，比较其 R−B 与全板中位数。若确实偏蓝（R<B），
  这条引用就成立，环光的理由也成立；若不偏蓝，则"压镜面"这个理由不成立于本批样本。

## 7. 撤回：环光的"压镜面/把铜的颜色还回来"这条理由（2026-10-31 18:1x）

**结论作废**：本文件 §2 与 `dl/RINGLIGHT_20261031.md` 里采纳的"低角度环光压掉镜面、把铜的暖色签名还回来"这条理由。

**原因**：`dl/RB_CHROMA_20261031.md`（离线实测，12 划伤 + 40 良品）给出的结果是反的——
候选缺陷格的 R-B 相对板内中位数是 **+14.6（划伤）/ +18.2（良品）**，方向与"缺陷变蓝"相反，
而且**良品的效应更大**，不是划痕特有。被引用的那个 -6.5 在量级和符号上**可以复现**
（最亮 1% 给 -9.45 / -7.61），但它的 |R-B| 只有板子自身的 23–29%，即**高光把颜色洗向中性、不是洗向蓝**，
且良品板一样有。另有一条硬约束：采集链路是 RGB565，**R-B 的量化步长是 8 灰**，
所以"逐像素 -6.5"本身不可实现。

**影响**：环光现在只剩一条已被实测支持的作用——**同曝光下照度提高**（mean 368 对 245），
代价是**方向性微反差下降 5.4%**（FOCUS 88–89 对 93–94）。而后者正是划痕可见性所依赖的东西。

**已排除**：H(环光的价值来自压镜面/恢复暖色)。同时记一条：`dl/RINGLIGHT_20261031.md` §4
把它标为"未在仓库中找到出处"是对的——它确实只存在于对话里，直到这次被真正量了一遍。
