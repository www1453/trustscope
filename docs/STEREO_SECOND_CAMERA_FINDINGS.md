## 传感器无响应的两条独立证据

### 证据一：I2C 不应答

在 `axi_iic` 那条总线（`P14`/`W18`）上扫地址：

```
0x3C  0x3D  0x30  0x21  0x50  0x60  0x78   ->  全部无 ACK
```

对照（`PS I2C0`，`T15`/`T16`，用**完整读序列**扫，判据是读出已知的 `0x300A = 0x56`）：

```
0x3C  ->  0x300A=86  0x300B=64   **OV5640（ID=0x5640）**  <- 相机0 正常
0x3D / 0x3E / 0x3F / 0x30 / 0x21 / 0x50 / 0x60  ->  全部无器件
```

**排除了"两颗传感器挂同一条 I2C、用不同地址"这个假说。**

### 证据二：DVP 无输出（带对照组）

```
读通路自检：VDMA0 SR = 0x00015810（已知好值）      -> 测量方法有效
间隔 1.5 秒采两次：
  相机0 帧存 0x10000000:  24/32 个字不同          <- 对照组：在变
  相机1 帧存 0x11200000:   0/32 个字不同
VDMA2 的 SR 长时间为 0x00010000（无任何传输完成标志），
对照 VDMA0 的 SR = 0x00015810（有 IRQThreshold / FrameCount 位）
```

**对照组有效，所以"相机1 没有数据"这个结论成立。**

## 关于"是不是被我们烧坏的"

**找不到机制。** 逐条核对：

| 可能的烧毁途径 | 实际情况 |
|---|---|
| 数据线对顶 | `cmos_d_1` / `pclk_1` / `href_1` / `vsync_1` **全是 INPUT，我们从不驱动** |
| I2C 对顶 | `scl`/`sda` 是**开漏**，拉低/释放就是 I2C 协议本身；`axi_iic` 的 `scl_t`/`sda_t` 是三态控制 |
| 复位脚过压 | W14 是 3.3V 输出，**厂商自己的 `an5642.xdc` 就是把它当第二路复位用的** |
| 旧比特流误驱动这些脚 | 改动前那 16 个脚**在原 XDC 里没有任何约束**，旧比特流一根都没驱动过（原来未约束的只有 3 个 `vid_io_out_0_*`，被自动摆到了 J15/J16/K16） |
| 反灌电流（未上电时驱动其引脚） | 我们只在供电之后才驱动复位线 |

**但是必须说清楚不确定的部分**：
**我们从没有验证过"第二路以前是好的"。** 从项目开始到现在，只有相机0 是已知可用的。
所以**"它一开始就不工作"和"它后来坏了"这两种可能，现有证据分不开**。

## 建议的下一步（需要动手的部分）

1. **量 `P14` / `W18` 的静态电平** —— 正常 I2C 空闲时都应为高（3.3V）。
   如果一直是低，说明总线被拉死（短路或器件损坏）。
2. **量第二路的 `P15`（PCLK）** —— OV5640 在**未被 I2C 配置之前不会输出 PCLK**，
   所以 PCLK 静止是正常的，**不能用它判断传感器死活**；但如果有 PCLK 就说明传感器活着。
3. **检查模块在 J10 上的插接**（第二路信号在 PIN3~PIN18）。
4. **换一块 AN5642 模块对比** —— 这是最快的区分手段。
5. 若换模块后正常，则原模块的第二路损坏；
   若换模块后仍不正常，则要在板子的 J10 第二路走线上找问题。
