# DL 主线 · W1–W2 结果（2026-09-24）

> 全部数字由本目录脚本产生，可重跑。协议：**阈值只在 val 上定，test 只用一次**。

---

## 一、实验设计（先说清楚要验证什么）

**预测（实验前写下的）**：模型只见过正常照明；过曝/欠曝/失焦/遮挡是分布外输入，
预测它在这些条件下会退化。

- **训练/验证**：只用 normal 条件（3000 / 800 张）
- **测试**：五种条件各 400 张，共 2000 张，**只在最后用一次**
- 这个设计本身就是要测量的东西：若模型在四种条件下不退化，那"拒判"叙事就不成立，
  必须如实报告为"位移不难"

**数据**：程序合成背光工件图（256×256 渲染 → 64×64 网络输入，0.25 mm/px）
- 缺陷 = 缺口 ≥2.0 mm / 孔洞直径偏差 ≥0.5 mm（与《项目定义_收紧版》一致）
- **标签就是构造参数本身**，不是人工标注 → 标签/参数一致性检查 **0 不一致**

## 二、结果一：模型在两种条件下崩溃，且崩向危险方向

```
cond        准确率    缺陷被判合格(误放行)   正常被判缺陷
normal     0.9975            1                0
over       0.9975            0                1
occl       0.9900            0                4
under      0.5200          192                0
defocus    0.5000          200                0
-------------------------------------------------------
整体       0.8010          393/1000 (39.30%)   5/1000 (0.50%)
```
- val 最优 0.9988；normal 上泛化正常
- **过曝与遮挡扛得住；欠曝与失焦崩溃**
- 崩溃方向是**把缺陷判成合格**：1000 个缺陷工件里漏放 **392** 个

> 只输出"合格/不合格"的系统，在这两种条件下就是一台**静默放行缺陷的机器**。

## 三、结果二：这些条件是**可检测的**（这是"拒判"能不能成立的关键）

质量特征（都是 PL 可实现的廉价量）：均值、饱和点比例、暗点比例、梯度能量、拉普拉斯方差

| 条件 | mean (z) | sat (z) | grad (z) | lapvar (z) |
|---|---|---|---|---|
| over | **8.3** | **1241** | 0.5 | 3.6 |
| under | **-39.1** | -2.4 | **-13.8** | **-21.5** |
| defocus | **-0.05** ← 看不出 | -1.0 | **-5.7** | **-30.4** |
| occl | **-17.5** | -0.1 | 7.4 | 18.5 |

**只用亮度（mean ±3σ）做质量门**：normal 0% 误报 / over 100% / under 100% / occl 100%
/ **defocus 0% ← 漏掉**。

> 在失焦下模型把 **100% 的缺陷判成合格**，而"亮度门"完全看不见失焦。
> **单一指标的质量门是不安全的** —— 这是本阶段最有价值的一条负面结论。

**五特征联合门**（阈值取自 val 的 normal，评估在 test）：

```
normal    flagged   4.2%      ← 代价
over      flagged 100.0%
under     flagged 100.0%
defocus   flagged 100.0%
occl      flagged 100.0%
```

## 四、结果三：门到底买到了什么

| 条件 | 缺陷数 | 无门时的危险放行 | **有门后** |
|---|---|---|---|
| normal | 200 | 1 | 1 |
| over | 200 | 0 | 0 |
| under | 200 | 192 | **0** |
| defocus | 200 | 200 | **0** |
| occl | 200 | 0 | 0 |
| **合计** | **1000** | **393 (39.30%)** | **1 (0.10%)** |

> **危险放行从 393/1000 降到 1/1000，代价是 4.2% 的正常件被拒判。**
> 这是《项目定义》要求"误放行率与拒判率必须一起报"的第一个实测数据点。

## 五、模型与硬件预算（已核对）

```
结构   : Conv(1->16,3x3)-BN-ReLU-Pool / Conv(16->32)-BN-ReLU-Pool / Conv(32->32)-BN-ReLU-Pool
         / FC(2048->64)-ReLU / FC(64->2)
参数   : 145,394 (≈142 KiB as int8)
MAC    : 7,798,912  —— 解析计数值与 hook 实测值 **完全一致**
预算   : 15 GMAC/s 下约 0.52 ms/帧（DSP 利用率按 45%）
```

BN 在导出时折叠进卷积，推理零开销。

## 七、W3 结果：int8 量化与独立整数参考实现（2026-09-24）

**做法**：BatchNorm 折进卷积 → 逐输出通道对称 int8 权重 + uint8 激活（零点固定为 0，
因为校准的是 ReLU 后的张量）→ int32 累加 → 定点重量化 `(acc*M + (1<<(sh-1))) >> sh + z`
（**算术右移 = 向 +∞ 半数进位**，这是写死的契约，HLS/硬件必须一模一样）。

**参考实现是自己写的**（`int_reference.py`，纯整数运算），
**不允许调用任何框架的 forward** —— 否则就是"torch 证明 torch"。

| 检查项 | 结果 |
|---|---|
| BN 折叠等价性（torch vs 自写 float numpy） | max 差 **3.09e-06** |
| int8 vs float 预测一致率 | **1.0000** |
| float 准确率 → int8 准确率 | 0.8010 → **0.8010（损失 0）** |
| 逐条件误放行（int8 vs float） | **完全一致**（393/1000） |
| 导出包重载后 logits 逐行一致 | **200/200，最大差 0** |
| 舍入契约边界（含负数、半数、饱和） | 7/7 通过 |

> 量化在本模型上**零损失**：因为崩溃来自分布外输入，而不是来自量化噪声。
> 这是可报告的正面结论，但**不能外推**到更深的模型。

**导出物**（供 W6 上板对比）
- `runs/cnn_v1_int_params.npz`（158 KB：w_q / M / sh / b_int / sum_w / s_w）
- `runs/cnn_v1_int_meta.json`（尺度、零点、契约说明、逐条件指标）
- `runs/fpga_vectors.npz`（200 个测试向量 + 参考 int32 logits）

**已知边界**：量化参数由**合成训练集**校准；换真实数据必须重新校准。

## 九、B 组实验：把输入分辨率翻倍，能修好崩溃吗？（2026-09-24）

**动机**：《项目定义》要求检出 **0.5 mm** 的孔径偏差。在 64×64（0.25 mm/px）下只有 **2 像素**，
在 128×128（0.125 mm/px）下有 **4 像素**。所以"提高分辨率能提升检测能力"是一个合理的假设。

**做法**：物理模型完全复用（256 渲染 @0.0625 mm/px），只把下采样从 4× 改成 2×。
模型结构不变，但 3 次池化后是 32×16×16（原 32×8×8）→ 第一层 FC 变 8192→64。
MAC：7.8M → **31,195,264**（解析值与 hook 实测**完全一致**）。
训练/验证仍只用 normal，测试集五种条件各 400 张，**只用一次**。

### 结果：分辨率翻倍，崩溃没有修好，遮挡还变差了

| 条件 | 64×64 误放行 | **128×128 误放行** | 变化 |
|---|---|---|---|
| normal | 1 | 2 | ≈ |
| over | 0 | 1 | ≈ |
| **under** | 192 | **159** | 略好，**仍崩溃**（acc 0.52 → 0.60） |
| **defocus** | 200 | **200** | **一模一样，200 个缺陷全部放行** |
| **occl** | 0 | **39** | **明显变差**（acc 0.99 → 0.90） |
| **整体** | 393/1000 | **401/1000** | **没有改善** |

val 准确率 0.9962（64 版为 0.9988），normal 实测 0.9950。

### 结论（这条结论本身就是交付物）

> **崩溃不是分辨率问题，是分布外输入问题。**
> 失焦时模型把 **200/200** 的缺陷全判成合格，**像素多一倍完全没有帮助** ——
> 因为缺陷在该分辨率下本来就看得见，丢失的是"模型学到的那些特征在欠曝/失焦下不再成立"。
> 遮挡甚至变差：模型在 128 下有更多容量去拟合 normal 条件的细节，泛化反而更窄。

**所以正确的解法不是继续加分辨率，而是那套可信度质量门** —— 它在本实验里完全不受影响
（质量特征算在下采样后的 64×64 上，与网络输入分辨率解耦），四种偏移条件依然 100% 被标记。

**工程决定**：**保留 64×64 模型**（NEON 实测 40.1 ms），**显示仍用 256 渲染**。
两者已经解耦，所以"检测能力"和"观感"不再互相牵制 —— 这是当前架构的既定优势。

**如果要让模型本身也扛住偏移**，那要的是**在偏移条件下训练**（数据问题），
而不是分辨率，也不是更多算力；而那条路会与"用质量门拒判"的立项主线冲突，本版不做。
