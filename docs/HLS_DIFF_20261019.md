# HLS 差分/候选模块（2026-10-19，离线完成）

> 目的：让 **PL 承担真正的图像算法**（指南 §3.3.2 的"系统集成/接口设计"与"硬件加速"），
> 并把检测链里**与分辨率成正比的那一步**从 PS/PC 挪到 PL。
> 全部在电脑上完成：C 仿真 + C 综合，不需要板子。

## 1. 模块做什么

`dl/hls_diff/hls_diff.cpp`

```
输入：curr[]、tmpl[]（24 位像素，m_axi）
      width/height/thresh（s_axilite）
处理：逐像素求亮度 → 与模板相减 → 取绝对值 → 与阈值比较
      → 记录所有超阈值像素的包围盒 + 计数
输出：bbox[4]（xmin,ymin,xmax,ymax）、count
```

这正是 PC 侧耗时最大的一步（5 MP 下 209 ms / 458 ms，占 46%），也是随分辨率线性增长的一步。

## 2. 仿真结果（三个已知答案用例，全部 PASS）

```
identical frames             bbox=(0,0,0,0) count=0    PASS
16x16 patch at (100,80)      bbox=(100,80,115,95) count=256  PASS
1 pixel at (0,0)             bbox=(0,0,0,0) count=1    PASS
```

→ `dl/hls_diff/hls_diff_proj/solution1/sim/report/*.log`

**这三个用例是按项目技能包的规矩选的**：一个必须返回空、一个必须精确命中、一个是最容易写错的
角落（单像素且位于原点——如果包围盒初值写错，"只有一个候选"的情况会给出 (0,0,0,0) 以外的结果）。

## 4. 两个把 DSP 压低的过程（都记下来，因为都是真事）

1. **第一版用精确亮度权重**（77/150/29）⇒ **DSP = 12**。
   这块板子 DSP 已用 **219/220**（CNN 加速器），12 个新 DSP **根本加不进去**。
   ⇒ 改成无乘法器亮度 `(r + 2g + b) >> 2`：检测只需要两帧**用同一公式**度量，绝对准确性无关。
   DSP 从 12 降到 8。
2. **第二版地址写成 `y*width + x`** ⇒ 变量乘法又合成出乘法器。
   ⇒ 改成**递增索引** `idx++`。DSP 从 8 降到 **7**。

## 5. 仍然存在的阻塞（诚实）

**还剩 7 个 DSP，而板上只剩 1 个空位。** 这 7 个来自 m_axi 的地址算术/突发逻辑，
HLS 报告把它们归在 Instance 里，我没有进一步定位到具体表达式。

⇒ **这个模块现在还不能直接加进现有设计。** 三条出路：

| 方案 | 说明 | 代价 |
|---|---|---|
| A. 改流式接口（axis） | 用 `hls::stream` 替代 m_axi，去掉地址算术，DSP 通常归零 | 需要视频时序侧改造（要上板） |
| B. 腾出 DSP | 替换/裁剪 CNN 加速器的一部分 | 影响既有功能 |
| C. 接受现状 | 4 个 BRAM + 7 DSP，与加速器争资源 | 需要重新做资源规划 |

**建议 A**：与本项目的 AXI-Stream 采集链路天然契合，且能顺带证明"接口设计"这一价值点。

## 6. 边界（没做的）

- **没有上板**：时序余量（WHS 仅 +9 ps）、DDR 带宽、与 VDMA 的握手都未验证；
- **没有 RTL 协同仿真**：只做了 C 仿真 + C 综合，没有 `cosim_design`；
- **没有处理 stream 边界**：模块要求 width×height 与两块缓冲严格对应，未做行对齐检查；
- **没有多候选**：只输出**一个**包围盒（真实场景可能有多处缺陷，需要候选链表，属下一步）。

v3 的 `cosim_design` 输出：

```
INFO: [COSIM 212-1000] *** C/RTL co-simulation finished: PASS ***
```

**这条的意义**：不只是"C 代码算对了"，而是**综合出的 Verilog 与 C 行为逐用例一致**。
这正是指南 §3.3.5.1 要的"仿真或验证结果"，而且它是**离线可重放**的
（`vitis_hls -f run_cosim.tcl`，本机约 50 秒）。

### 三个版本各自为什么变

| 变化 | 原因 | 代价 |
|---|---|---|
| 12 → 8 DSP | 精确亮度权重（77/150/29）在本板（DSP 219/220）加不进去 ⇒ `(r+2g+b)>>2` | 亮度略粗略，但**两帧用同一公式**，差分不受影响 |
| 8 → 7 DSP | `y*width+x` 合成出变量乘法 ⇒ 递增索引 | 无 |
| 7 → 4 DSP | m_axi 输出口自带地址算术 ⇒ AXI-Lite 标量 | 输出从"一次突发"变成 5 个寄存器读写 |

**剩余 4 个 DSP 在接口/控制逻辑**（表达式明细表里数据通路为 0 DSP）。
本板只剩 1 个空位 ⇒ 仍需再让 3 个：可选"裁剪 CNN 加速器"或尝试 HLS 的
`-resource_style` 等选项。**这是集成前的最后一个技术障碍。**
