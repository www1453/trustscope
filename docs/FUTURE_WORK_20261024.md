## 1. STM32 传送带联动（已定义接口，未实施）

### 1.1 已确认的硬件事实（来自 ALINX AX7020 教程与 ps7_init）

| 事实 | 出处 |
|---|---|
| 板载 **CP2102** USB-UART，接 **PS_MIO48/49**（BANK501，**3.3V**），插 Micro USB 即 PC 上一个 COM 口 | 教程 pp.31–32 |
| PS 有 **12 针 PMOD 扩展口**，引出 MIO7/8/9/10/11/12/**14**/**15** | 教程 pp.48–49 |
| **PIN3 = MIO15**（C8）、**PIN9 = MIO14**（C5），PIN5/11 = GND，PIN6/12 = +3.3V | 同上 |
| **MIO14/15 就是 Zynq 的 UART0**（TX/RX） | Zynq-7000 TRM |
| **当前 PS 配置里 UART0 是关的**：`ps7_init` 只写了 UART1（`0xE0001000` 段），完全没碰 `0xE0000000` | `ps7_dual/GOOD_20261003_cdcfix/ps7_init_cdcfix_50m.tcl` |
| STM32 侧预留 **PA9 = USART1_TX、PA10 = USART1_RX**（当前未初始化）；PA6/PA7 驱动 L9110S | `电机控制交接_20261022.zip` 第 9 节 |

### 1.2 两条可行路径（都没有实施）

**路径 A：PC 做桥（推荐，风险最低）**
```
Zynq ──USB/JTAG──► PC ── 读判定（现成：dl/host_qc/）
STM32 ──USB-TTL 模块──► PC ── 发 STOP/RUN/GET_STATUS
```
- **不碰 Zynq 任何引脚**，因此不存在两个输出对顶的风险；
- **PC 侧已实现**：`dl/host_qc/stm32_link.py`（17 项离线自测通过，含重发幂等、心跳超时、非法参数拒绝）；
- **协议已定义**：`dl/STM32_LINK_PROTOCOL.md`（115200 8N1，6 字节帧，4 条命令，含五步台架验收）；
- **未做原因**：需要一块 **USB-TTL 模块**（约十余元），手头现无；且该功能不影响任何交付物。

**路径 B：Zynq MIO14 → STM32 PA10（不用模块，但要碰引脚）**
```
AX7020 PMOD PIN9 (MIO14) ──► STM32 PA10（配为输入）
AX7020 PMOD PIN5/11 (GND) ── STM32 GND
```
- 不用 USB-TTL、不用 PL、不用改 XDC、**不用重建位流**（SLCR 运行时配 MIO 复用即可）；
- **协议**：电平高 = 允许走、电平低 = 停；**每 200 ms 翻转一次作为心跳**，
  STM32 侧 **500 ms 无翻转即停**（防止 Zynq 死机后皮带继续跑）；
- **未做原因**：需要改 Zynq 固件访问外部引脚，存在接线风险（两端输出对顶、带电插拔、
  误插 PMOD 的 3.3V 针）。若将来实施，必须先**只用万用表量 PIN9 对 GND 是 0↔3.3V 方波、
  且不超过 3.3V**，确认后再断电接线，且 STM32 侧 PA10 必须配置为**输入**。

### 1.3 结论

演示不依赖该联动（皮带可手动停，或沿用现有"上电跑 10 s 自动停"的试转固件）。
将其列为**产线集成接口，已确认可用**。

## 2. 帧率（Stage 1 未通过验收，保持 6.4 fps）

- 现状：**6.39 fps**，撕裂（行检测器）**0.14%**。撕裂问题已解决，帧率是等"帧存奇偶沿"的代价。
- 曾尝试用两位（bit4 + bit15）直接解码帧存索引，可到 **11.3 fps**，但**撕裂升到 36–39%**：
  读取窗口约 65 ms，而解码最坏只保证 54.4 ms。
- 未能定论的原因：`bit15` 的格雷码映射**在 6 次探针里只有 2 次符合预期、2 次反相、2 次不可复现**；
  探针采样率约 90 ms，而信号周期 27.2 ms，**任何行为测量都会混叠**。
- 下一步（若要做）：在固件里用 **≥5 kHz 轮询** `0x41200008` 约 120 ms，记录每一次变化，
  才能确定两位的真实映射。文档：`dl/STAGE1_20261024_decode.md`。

## 3. 配准漂移（失败方向安全，但未闭环）

- 多帧平均（N=8）之后，噪声下降，**暴露**出原本被噪声掩盖的配准漂移：
  N=1 时一次 −0.20°/−3.5 px 的漂移跟随 `cells=0`（阈值以上其实 193 格），即**旧版会默默判合格**；
  现在同样的漂移读 **14–25 格 → 判 NG**，**失败方向安全**。
- 漂移发生率仍未定论：N=4 时 3 次跑出现 2 次，N=8 时 2 次出现 0 次（界 0–40%/2 分钟）。
- 下一步：用**平均后的网格**重新标定保持裕度（`REG_WARM_MARGIN 16` / `REG_JUMP_MARGIN 32`），
  并把漂移发布成独立可见状态（固件已有 state 3 UNSTABLE）。文档：`dl/STAGE2_20261024_average.md`。
