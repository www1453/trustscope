## 2. 三个最该改口的说法

1. **"全硬件加速流水线"** → 应写"采集与显示为硬件流水线，检测正在从 PS 下沉到 PL（已有 HLS 模块，协同仿真通过，尚未集成）"。
2. **"识别缺口与孔洞"** → 我们实测能检的是 **≥0.48 mm 的缺铜/桥连类缺陷**；细走线断口（0.2–0.3 mm）**低于采样率下限**。写成"识别微小缺口"会在答辩时被一问即破。
3. **"端到端低延迟"** → 没有任何延迟数据。要么补一次测量，要么改成"低延迟架构（各阶段已分段计时）"。

## 3. 建议保留并加深的那一条

简介里最有分量、也最像"这个队想清楚了"的，是这句：

> **把关键区域的曝光、局部对比度与参考图案状态映射为成像可信度，输出合格、不合格、无法判定三态，区分"坏工件"与"没看清"。**

它有三个好处：

- 和我们的实际问题（光照不均、反光、冻结、配准失败）完全对得上；
- **不依赖**"能检出多小的缺陷"这个尚未证明的能力；
- 我们已经有一半骨架（三态判定 + 质量指标 + 超时/未知一律停），补的是"可信度的定义与标定"。

**建议把这条提到主线位置**，其余（颜色分割、轮廓匹配）降为"扩展方向"。

## 4. 改后的简介（可直接替换，语气不变、承诺收窄）

> 本作品基于 ALINX AX7020 开发板，以 Zynq-7020 的 PS+PL 协同架构为核心，构建面向**固定姿态平面工件**的实时成像与缺陷检测系统。PL 完成双目 OV5640 的 DVP 采集、四帧存 VDMA、800×480 显示时序与探测信号汇聚；PS 完成帧管理、曝光调度、界面与判定。
>
> 针对"看不清就不能判"的工程需求，系统把**成像可信度**作为判定的前置条件：把关键区域的曝光水平、局部对比度、截顶比例、配准残差与帧连续性汇总为可信度，输出**合格 / 不合格 / 无法判定**三态，从机制上区分"坏工件"与"没看清"。判定不确定、超时、或判定与当前工件编号不符时，板端一律保持停带，绝不沿用上一次结果。
>
> 检测方面，系统在 PL 侧实现了基于模板差分的候选定位模块（已通过 C/RTL 协同仿真），在 64×44 mm 工件、1280×720 成像条件下可检出**约 0.5 mm 及以上**的缺铜、桥连类缺陷；更细的走线断口受采样率限制，明确列为能力边界，不作承诺。
>
> 交互上，电容触摸实现原图 / 检测结果 / 质量状态的多模式切换，OSD 叠加检测框、判定结果、可信度与实时帧率。系统给出分段耗时与端到端时延数据，并公开资源占用（LUT/FF/BRAM/DSP）与时序收敛情况，供低成本现场检测设备参考。
