# NG evidence snapshot (item 3), 2026-10-26

Firmware: `ps_ui/main.c` + `ps_ui/mmu.c`, build source hash `25666017`.
Host: `dl/host_qc/evidence.py`, and `record.py --evidence` uses it on NG.
Words: `MB_EVID_*` = 523..526.  MMU: three more 1 MB sections at 0x12800000.

## 0. What it is, in one paragraph

On an NG verdict the firmware copies ONE coherent capture store (the four-store ring means
one store IS one frame), the comparison's part mask, the per-cell difference grid and the
tolerance map into a static DDR buffer at 0x12800000, cleans the CPU cache (JTAG reads
bypass it), and raises `MB_EVID_STATE = 1`.  The host reads that static buffer at leisure,
writes `frame.bin`, `mask.bin`, `fine_deep.bin`, `fine_tol.bin`, `meta.json`, `row.json`,
appends one line to `evidence/rows.csv`, and clears the handshake.  A PASS writes nothing
to `evidence/` (only the session's own row log), so a long run cannot fill the disk.

## 1. The trap this is built not to repeat

A host `mrd` of one 2.7 MB store takes **~6.7 s** (measured), while a store is rewritten
every **27.2 ms** - a live dump splices **~28 frames** into one picture.  That trap is
documented in this repo and had already been hit once.  The copy is therefore done by the
firmware inside the store's safe window (the store is not rewritten for ~81 ms after it
completes), and the host only ever reads a static buffer.

## 2. The buffer, the trigger, the handshake

| block | address | bytes |
|---|---|---|
| `EVID_FRAME` | 0x12800000 | 2,764,800 (1280x720x3, one store) |
| `EVID_MASK` | 0x12AA3000 | 14,400 (`LIVE_MASK`, the comparison's part mask) |
| `EVID_FDEEP` | 0x12AA8000 | 14,400 (`FINE_DEEP`, per-cell `|d|`) |
| `EVID_FTOL` | 0x12AAC000 | 14,400 (`FINE_TOL`, the tolerance map that judged them) |
| `EVID_META` | 0x12AB0000 | 128 (32 words: magic, state, 24 metadata fields) |

* **Where it lives:** DDR above every buffer the design uses (the highest was `GREY_BASE`,
  ending 0x127F8400), in the board's 512 MB, mapped by three 1 MB sections in
  `ps_ui/mmu.c`.  Without them the first copy would data-abort at 0x12800000 - the same
  failure 0x11200000 produced before the camera-1 window was mapped.
* **Trigger:** the comparison can only SET a request, at the moment its own verdict is NG
  (`evid_arm()`, from the diff block).  The copy (`evid_copy()`) runs at the top of the
  NEXT loop, where a store has just been selected and invalidated, and the per-loop mask
  pass gives that one loop up so the copy owns the store's safe window.
* **What is copied with it:** the mask and the two fine grids are copied because the next
  comparison overwrites them within ~2.2 s and the host's dump takes seconds; they belong
  to the SAME comparison as the verdict.
* **Handshake:** `MB_EVID_STATE` (523) 1 = ready, the host writes 0 to ack;
  `MB_EVID_SEQ` (524) which comparison (`MB_DIFF_N`); `MB_EVID_TICKS` (525) the copy cost;
  `MB_EVID_SEQN` (526) snapshots taken since boot.  A second NG is NOT copied while the
  first is unread, so a slow host loses later NGs (countable in `SEQN`) instead of
  corrupting the one it is reading.
* **Cache:** every written range is `dcache_clean`ed before `MB_EVID_STATE` says ready.
  Without that the host would dump a frame the CPU still holds dirty with no error to show
  for it (the frozen-picture failure this project already had).

## 3. The metadata (the row's source)

24 words: `diff_n`, `diff_verdict`, `darea`, `limit`, `bx0`, `by0`, `bx1`, `by1`, `pts`
(the comparison's clustered count), `edge`, `inview`, `part_ref`, `fvalid`, `fcells`,
`diff_ok`, `reg_state`, `reg_scale`, the reference fingerprint (`ref_fingerprint()`, a
sparse FNV-1a over REF_BASE - computed at the NG, because no mailbox word carries it and a
row without it cannot say which reference the numbers belong to), `frames`, `store`,
three byte counts, and a layout version.

## 4b. The deliberate NG, and why it is not the contaminated board

THE CONTAMINATED BOARD COULD NOT BE JUDGED AT THIS STATION.  The operator placed it where
the good board had been, still, and the comparison refused every frame:

```
MB_DIFF_OK 5, MB_REG_STATE 2, MB_DIFF_FVALID 0, MB_DIFF_DAREA 0xFFFFFFFF,
MB_DIFF_VERDICT 2 (CANNOT JUDGE), MB_PART_PTS 700-731, MB_PART_REF 403,
MB_PART_INVIEW 1, MB_PART_EDGE 7, MB_PART_RULE 1, MB_BG_MEDD 3
```

i.e. the mask and the background were healthy, but the registration would not accept a
transform (mode 0, no measured error), so no comparison was made - the "surface change
defeats the registration" case of `dl/DEFECT3_20261025_structure_registration.md`.  Per the
rule for this session the registration was NOT touched and the board was NOT moved to make
it pass.

DETERMINISTIC NG INSTEAD: the firmware's own known-answer defect (MB_CMD = 15,
`stamp_reference()`).  A reference was taken at the station (`MB_CMD = 9`, `MB_PART_REF`
662, `MB_DIFF_OK` 1 - the comparison then judged PASS, DAREA 0, because the board was its
own reference), then a 48 x 48 px stamp of +120 grey was written into the REFERENCE at
lattice cell (53, 73), chosen from the live mask's densest 6x6 window.  The next
comparison judged NG:

```
MB_DIFF_OK 1, MB_DIFF_N 91, MB_DIFF_DAREA 28 >= limit 8, MB_DIFF_VERDICT 1,
MB_DIFF_FVALID 576, MB_REG_STATE 1
```

and the snapshot was dumped (`evidence/20261026_194318`, total 2,808,000 B):

| file | bytes |
|---|---|
| frame.bin | 2,764,800 |
| mask.bin | 14,400 |
| fine_deep.bin | 14,400 |
| fine_tol.bin | 14,400 |
| meta.json | 478 |
| row.json | 622 |

Row (`rows.csv` line):

```
2026-10-26T19:43:32+0800,item3-deliberate-ng,NG,28,8,0xFD971EE1,39,51,102,82,747,1,91,1,1,576,0,91,1,2764800,14400,14400,14400,saved
```

Cross-checks, which is what makes this evidence rather than a file dump:

* `mask.bin` has **747 set cells**, exactly the row's `pts` 747;
* `fine_deep.bin` has **28 cells with |d| > 30** - exactly the DAREA 28 - and its maximum
  is **122**, the stamped +120 plus noise; so the per-cell difference data really contains
  the injected defect and nothing else was over the threshold;
* `fine_tol.bin` is all 30 (the floor: no tolerance was learned);
* `frame.bin` renders as a sharp coherent 1280x720 frame;
* the firmware's copy cost `MB_EVID_TICKS` = 10,277,315 ticks = **30.7 ms** (2.88 MB of
  copying plus the cache clean, inside the store's ~81 ms safe window);
* after the dump `MB_EVID_STATE` read 0 and `MB_EVID_SEQN` stayed 1, so the slot was
  released and the next NG can reuse it.

A reference retake (`MB_CMD = 9`, `MB_PART_REF` 671) erased the stamp from REF_BASE; the
comparison returned to PASS (DAREA 0) and `preflight.py` reported PASS again.

**One metadata wart, stated:** the row's `fcells` is 0 while `fvalid` is 576 and the live
`MB_DIFF_FCELLS` read 30 a second later.  FCELLS is the count AFTER the 3x3/persistence
rules; on the first NG comparison the persistence counter had not accumulated, while
DAREA (a different rule) already saw the group.  DAREA and FVALID are the reliable fields
in the row; `fcells` should not be read as "no cells" without FVALID.

## 5. Retention

* The newest `--evidence-keep` directories are kept (default **20**; ~2.81 MB each, so
  ~56 MB worst case).  Older ones are deleted after each save; `rows.csv` is never pruned
  (~250 bytes per NG).  `prune()` is unit-tested offline (`evidence.py --selftest`).
* The directories are deliberately NOT tracked in git (`.gitignore`:
  `dl/host_qc/evidence/`); the code that produces and reads them is.

## 6. What remains unverified

* The contaminated board itself was NOT judged at this station: the registration refused
  it (`MB_DIFF_OK` 5, `MB_REG_STATE` 2) against the good board's reference, and the
  deliberate NG instead used the firmware's known-answer stamp.  Whether that board can be
  registered at a different placement is open and was deliberately not forced.
* One snapshot in flight only: a host slower than the NG rate loses snapshots by design
  (countable in `SEQN`), not an error.
* The buffer adds 2.81 MB of DDR and three MMU section descriptors; OCM cost is a few
  words of counters.  No PL, no VDMA, no existing buffer touched.
* The evidence frame is the first coherent store AFTER the NG verdict (next loop), not the
  comparison's own store - the comparison's store is 3 handovers old by the time its
  verdict is known.  The meta says which comparison it belongs to (`diff_n`); the frame is
  the scene within one loop (~150-250 ms) of it.
