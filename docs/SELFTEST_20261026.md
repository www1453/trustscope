# Boot self-test (item 2), 2026-10-26

Firmware: `ps_ui/main.c`, build source hash `25666017` (`MB_FWID1` 909522226).
Host: `dl/host_qc/preflight.py`, and `record.py` runs it before any judging.
Words: `MB_ST_*` = 516..522 (the map had no free index below 512; see
`dl/PART_MASK_PERFRAME_20261026.md` section 5).

## 0. What it is, in one paragraph

Four checks, each one a fault that cost a session, evaluated against the words the
firmware itself publishes - the self-test takes no new measurement, so it cannot disagree
with the state a host reads.  Each check answers PASS / FAIL / **NOT MEASURED**, and the
aggregate is FAIL if any check failed, INCOMPLETE if one could not be measured, else PASS.
It runs once at boot (as soon as a comparison exists and the AEC has converged, or after
200 loops) and on demand with ONE host write, `MB_CMD = 20`.

| code | check | passes when | the incident it exists for |
|---|---|---|---|
| 1 REF | reference present and >= `PART_MIN_PTS` 400 | `MB_PART_REF` >= 400 and a reference exists | a reference captured at 394, every comparison refused `MB_DIFF_OK` 5 |
| 2 BG | background valid, used, and matching | background rule ran (`RULE` 1), `MB_BG_MEDD` <= 8, and on a part-free mask `MB_BG_CELLS` < 32 | an adopted background (`STATE` 4) that no longer matched the scene read 951..1192 empty-belt presence cells |
| 3 AEC | exposure converged | camera-0 `MB_AEC_STATE` 1 and `MB_CLIP_GATE` 0 | an AEC latched at state 3 while everything else looked normal |
| 4 MASK | mask and presence agree | `MB_PART_PTS` >= 400 iff `MB_BG_CELLS` >= 32 (three-valued: not measured is not agreement) | a host word everyone read as UNK because nothing wrote it |

## 1. The design decisions that were measured, not assumed

**(a) The mask count the checks use.**  The first version used `g_part_pts`, the
comparison's CLUSTERED count.  On the board that failed a state that was fine: with the
good board a few cm off its reference placement the comparison's count read 385 (below
the 400 floor) while the per-loop mask on the same scene read 492 and the presence count
2456, so checks 2 and 4 both fired:

```
PREFLIGHT FAIL code=2 fail=0x0A first=BG | ... mask=479 vs presence=2475 failed=BG,MASK
MB_ST_RES 0x44  (check 2 = fail, check 4 = fail)
```

The comparison's mask is built against the reference's transform, so a part that is
merely displaced can read under the floor.  Checks 2 and 4 ask about THE CURRENT FRAME,
so they now use the per-loop mask count - the number a host reads as `MB_PART_PTS` - with
the comparison's count as the fallback when the per-loop publisher is switched off
(`MB_PART_TK_ON = 0`).  The comparison's arithmetic, the AEC's `g_part_pts` input and the
comparison's audit words are untouched; only the self-test's input changed.  A check that
fires on a good state is worse than no check, so this is recorded rather than tuned away.

**(b) Three outcomes, not two.**  A presence count that reads `0xFFFFFFFF` ("not
measured", the adopted-background state before the next comparison) is NOT MEASURED, not
PASS and not FAIL.  The aggregate then reports INCOMPLETE (2) and the host prints it as
such; `preflight.py` additionally cross-checks the firmware's verdict against its own
per-check bits and refuses to call a "PASS next to a failed check" a pass.

**(c) `MB_BG_MEDD <= 8` is the host preflight's own stale-background bound** (the live
preflight refuses when `MB_BG_MEDD > 8`; a fresh background reads 1-4, the stale one 13;
`dl/host_qc/README.md` section 13).  The self-test reuses it instead of inventing a second
number.

## 2. What was measured on the board

All quotes are the words as read by `dl/host_qc/preflight.py` (which also runs the test)
and by `qc_mailbox` reads, from the 2026-10-26 bench session.

**Good state - PASS, all four checks.**  On demand (`preflight.py`, exit 0):

```
PREFLIGHT PASS code=0 fail=0x00 | ref=403/400 bg(medd=3 cells=2452 rule=1 why=0 state=4) aec=1 clip=0 mask=478 vs presence=2452
```

`MB_ST_VERDICT` 0, `MB_ST_CODE` 0, `MB_ST_FAIL` 0, `MB_ST_RES` 0, `MB_ST_RUN` 3,
`MB_ST_TICKS` 159 ticks = **0.475 ms**, `MB_ST_AT` 1568.  The boot run passed on its own
too (`MB_ST_RUN` 1, `MB_ST_AT` 144, ticks 154), i.e. the boot trigger fires and does not
need a host.

**Bad state 1 - FAIL code 1 (REF), the reference-below-floor fault.**  Produced for real:
after a reflash the automatic reference read 391 (below 400), and three deliberate
`MB_CMD = 9` retakes at the same framing read 379, 380 and 370.  `preflight.py`, exit 3:

```
PREFLIGHT FAIL code=1 fail=0x01 first=REF | ref=380/400 bg(medd=3 cells=2448 rule=1 why=0 state=4) aec=1 clip=0 mask=474 vs presence=2448 failed=REF
```

`MB_ST_VERDICT` 1, `MB_ST_CODE` 1, `MB_ST_FAIL` 0x01, `MB_ST_RES` 0x01, `MB_PART_REF` 380.
This is the same class of fault as the 394 that refused every comparison in the previous
session; here it is named in one line instead of being inferred from `MB_DIFF_OK` 5.

**Good state again.**  A retake that reached `MB_PART_REF` 403 (the same board, the same
framing; the mask count varies by +-20 between frames) made the same state PASS again -
so the verdict follows the measured words, not a latch.

**Bad state 2 - FAIL code 2 (BG), the obstructed view.**  The operator stood a large
sheet of cardboard in front of the camera, covering more than half the picture, and left
it there (the belt and the board untouched).  `preflight.py`, exit 3:

```
PREFLIGHT FAIL code=2 fail=0x0A first=BG | ref=403/400 bg(medd=None cells=None rule=0 why=2 state=4) aec=2 clip=1 mask=0 vs presence=None failed=BG,MASK
```

Firmware words in the same session: `MB_ST_VERDICT` 1, `MB_ST_CODE` 2, `MB_ST_FAIL` 0x0A,
`MB_ST_RES` 0x44 (check 2 fail, check 4 fail), `MB_ST_RUN` 4, `MB_ST_TICKS` 143 = 0.43 ms,
`MB_ST_AT` 3845; `MB_PART_RULE` 0 (was 1), `MB_PART_BGWHY` **2** (was 0), `MB_BG_STATE` 4
(still says "adopted"), `MB_PART_PTS` 0, `MB_PART_PTS_C` 0, AEC state 2, clip gate 1,
`MB_READY` 0, `MB_DIFF_OK` 4.

WHY `BGWHY` IS 2 AND NOT 3 (the area refusal was expected).  A cover over more than half
the view does not only add area - it removes the light, so the ratio of the live lattice
median to the background's left the 0.5..2.0 band and the compensation refused BEFORE the
area test.  That is the same condition the comparison reports as `MB_DIFF_OK` 4
("conditions changed too far").  Both are "the background rule did not run", and check 2
catches either.  The interesting part is check 4: it failed as well - at the test instant
the presence count was a real number >= 32 while the mask was 0, i.e. the two detectors
disagreed about a large occlusion, exactly the failure mode this check exists for.

**The quote has one limit, stated.**  `MB_BG_MEDD` and `MB_BG_CELLS` read 0xFFFFFFFF in
the host's read even though check 4 used a real presence count, because the NEXT
comparison (every ~2.4 s here) overwrote them between the firmware's run and the host's
read.  The verdict words and `RULE`/`BGWHY` are consistent with the verdict; the two
counts are not a frozen copy of what the checks used.  The firmware does not publish a
per-check value snapshot - that is a limitation, not a claim.

**Check 3 (AEC) in the failing direction was not produced.**  The AEC has no host command
to latch it, and it only reports 3 when the camera cannot expose the frame; the bench
camera converges at exposure 8698.  Check 3 is verified in the passing direction (state 1,
clip 0, in every PASS above) and its failing expression is one line of C
(`g_aec_state != 1 || g_clip_gate != 0`).  This is stated, not hidden.

## 3. Cost

`MB_ST_TICKS`: 154-159 ticks = **0.46-0.48 ms** per run, measured by the global timer
(334.8 ticks/us).  It runs once at boot and once per `MB_CMD = 20`.  No new buffer; seven
words of mailbox (516..522); no OCM beyond a few bytes of counters.

## 4. Host side

* `python dl\host_qc\preflight.py` - send `MB_CMD=20`, wait for `MB_ST_RUN` to advance
  (6 s default), print ONE line, exit 0 PASS / 3 FAIL / 4 INCOMPLETE / 2 error.
  `--no-trigger` reads the last verdict; `--json` prints the whole decode.
* `record.py` runs it BEFORE any judging (skip with `--no-preflight`) and refuses to
  record when it FAILS unless `--force-preflight` is given.  An INCOMPLETE preflight is
  printed and recording continues.
* `--selftest` (offline, no board): 8 cases - pass, each named failure, "not measured is
  not PASS", and "never run is not PASS".

## 5. What remains unverified

* The AEC failure path is not demonstrated on the board (no way to latch it without
  touching the camera).
* The boot trigger's 200-loop timeout was not exercised (every boot here converged).
* The checks use the per-loop mask count when `MB_PART_TK_ON` is 1 and the comparison's
  count when it is 0; the A/B arm's self-test was not separately measured.
* The per-check input values are not frozen: a comparison that runs between the self-test
  and the host's read can overwrite `MB_BG_MEDD`/`MB_BG_CELLS`/`MB_PART_PTS` (observed
  above).  Publishing a 5-word snapshot of the inputs each check used is the obvious next
  step and is NOT done.
