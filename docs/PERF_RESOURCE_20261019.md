> 数据来源：Vivado 2023.1 在 2026-10-18 20:59 生成的实现后报告 + 板端运行时实测。

## 1. 资源占用（器件 xc7z020clg400-2）

| 资源 | 已用 | 可用 | 占比 | 出处 |
|---|---|---|---|---|
| Slice LUTs | **32,815** | 53,200 | **61.68%** | `utilization_placed.rpt` |
| ├ LUT as Logic | 31,022 | 53,200 | 58.31% | 同上 |
| └ LUT as Memory | 1,793 | 17,400 | 10.30% | 同上 |
| Slice Registers | **53,908** | 106,400 | **50.67%** | 同上 |
| Block RAM Tile | **109.5** | 140 | **78.21%** | 同上 |
| └ RAMB36E1 | 85 | 140 | 60.71% | 同上 |
| └ RAMB18E1 | 49 | 280 | 17.50% | 同上 |
| **DSP48E1** | **219** | 220 | **99.55%** | 同上 |
| Bonded IOB | 62 | 125 | 49.60% | 同上 |
| BUFGCTRL | 5 | 32 | 15.63% | 同上 |
| MMCME2_ADV | 0 | 4 | 0% | 同上 |

### 这张表说明什么（判断依据，不只是数字）

1. **DSP 已经 99.55% 用满**：CNN 加速器把 220 个 DSP 占了 219 个。
   ⇒ **"把整网推理搬到 PL"这条路在当前设计里没有 DSP 空间**，除非先砍掉现有加速器或改架构。
   这是"电脑承担推理"最硬的技术理由，比"板子算不动"这种含糊说法有力得多。
2. **LUT 还有 38%、FF 还有 49%**：说明**加逻辑**（状态机、帧管理、差分/阈值流水线）是可行的，
   而加**乘法密集**的东西（卷积）不可行。
3. **BRAM 78%**：还有约 30 个 tile（≈1 MB）余量，够放模板图（1280×720 灰度 = 900 KB 需要压缩或分块）。
4. **IO 49.6%**：J10/J11 两组相机 + LCD + 触摸占 62 个，以太网如果走 MIO 不占 PL IO（PS 内部）。

## 5. 运行时时序（板端实测）

| 模式 | 帧周期 | 循环周期 | 帧率 | 出处 |
|---|---|---|---|---|
| 单曝光（VTS 740） | 53 ms | ~55 ms | **19 fps** | `ps_probe_now` / `ps_liveness` |
| 融合（VTS 1700） | 121 ms | 126 ms | **8 fps** | `ps_probe_now` |

循环各阶段（融合态，32 次平均）：

| 阶段 | 耗时 | 占比 |
|---|---|---|
| sync（等交接） | ~2–3 ms | 2% |
| class（发布+失效+分类） | 7 ms | 6% |
| qual（质量度量） | 0.5 ms | <1% |
| **cam（渲染相机区）** | **54 ms** | **43%** |
| panel（UI 面板） | 1 ms | <1% |
| tail（底栏+清缓存+翻页） | 8 ms | 6% |

**结论**：渲染是绝对热点（43%）。任何"再快一点"的努力都应该从这里开始，而不是从 UI 或同步。

## 11. 基线对比为什么拿不到（2026-10-19 实测）

试跑厂商原始工程 `D:\BaiduNetdiskDownload\23_ov5640_dual\Vivado\auto_create_project\create_project.tcl`：

```
WARNING: [IP_Flow 19-2162] IP 'design_1_v_osd_0_0' is locked:
* IP requires one or more mandatory licenses but no valid licenses were found
ERROR: [Common 17-39] 'create_bd_cell' failed due to earlier errors
```

**结论：厂商例程依赖 `v_osd`（Xilinx OSD IP，需 license），本机无许可，基线工程无法复现。**

这本身是一条值得写进报告的事实：

| 项 | 说明 |
|---|---|
| 厂商例程的 UI 方案 | 用 `v_osd` 硬件叠层（需 license） |
| 我们的方案 | **PS 直接在帧缓冲里画 UI**（无 license 依赖，可复现） |
| 代价 | 占 PS 的渲染时间（`cam` 阶段 54 ms，占循环 43%） |
| 收益 | 换掉了许可依赖，整条链路可被任何人重建 |

### 那基线怎么给？

没法给"厂商例程 vs 我们"的对照，但可以给**我们自己的两组对照**：

1. **AUTO 视图 vs 相机视图**：前者只渲染一路、后者两路，能直接量出"每多一路的渲染代价"；
2. **单曝光 vs 融合**：19 fps vs 8 fps（已有实测），代价明确。

这两组比"厂商例程"更能说明**我们的增量做了什么**，而且都能在板上复现。
