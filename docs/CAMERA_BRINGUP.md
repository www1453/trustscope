## 0. 权威依据（全部可逐条复核，不是推测）

### 0.1 模块是"整块插满 J10"的形态

官方 `an5642.xdc`（单目 + 双目两版）逐条列出相机占用的 FPGA 引脚。
把它与 ALINX 官方 J10 引脚表对齐后：**AN5642 占用 J10 的 PIN3–PIN35 中的 32 根 IO，
外加 PIN1/2/37/38/39/40 六根电源地**。也就是说 ——
**模块插上去 = 整个 J10 被占满**，只剩 **PIN19、PIN36 两根 IO 空着**（§0.4）。

### 0.2 J10 引脚表（`vendor/alynx_doc/j10_j11.txt`，ALINX 官方教程 p.55）

```
J10 = 40pin 2.54mm 双排
  PIN1  GND        PIN2  +5V
  PIN3 .. PIN36    34 路 IO（EX_IO1_1N .. EX_IO1_17P）
  PIN37 GND        PIN38 GND
  PIN39 +3.3V      PIN40 +3.3V
```

原文（逐字）：

> "扩展口上包含 **5V 电源 1 路，3.3V 电源 2 路，地 3 路，IO 口 34 路**……
> IO 口的信号连接到 ZYNQ PL 的 BANK35 上，**电平默认为 3.3V**……
> **切勿直接跟 5V 设备直接连接，以免烧坏 FPGA**。
> 如果要接 5V 设备，需要接电平转换芯片。"
> "在扩展口和 FPGA 连接之间串联了 **33 欧姆的排阻**，用于保护 FPGA
> 以免外界电压或电流过高造成损坏。"
> "**扩展口的 Pin1，Pin2 和 Pin39，Pin40 已经在板上标示出。**"
> ALINX 对着 J10 提供的模块包含："**500W 双目视觉摄像头模块**"

### 0.4 相机在位时 J10 仍然空着的两根 IO

| J10 脚 | FPGA 引脚 | 官方信号名 | 相机占用？ |
|---|---|---|---|
| **PIN19** | **U17** | `EX_IO1_9N` | 否 |
| **PIN36** | **C20** | `EX_IO1_17P` | 否 |

（依据：`cmos2_*` 到 PIN18 结束，`cmos1_*` 从 PIN20 开始；PIN36 两版 XDC 都没有出现。）

**这是我们自己的产品信号可以用的两根线**——触发输入 / 背光 PWM / 光源同步，
都在这里，**不需要为了它们动相机占用表**。记下来，后面 F1/F2 那批功能会用到。

### 0.5 相机链路里**既没有 XCLK，也没有 PWDN**

官方 XDC 与 `pl_config.tcl` 的相机端口只有
`cmosN_d / pclk / href / vsync / i2c / cmos_rstn`。

**含义（对本题）**：AN5642 **自带晶振**、**PWDN 在模块上已处理**。
→ 上一版的"陷阱 A（缺 XCLK）""陷阱 B（PWDN 悬空）"**对 AN5642 不适用**，已删除。
→ 但反过来说：**这颗模块没有留给我们任何时钟使能的余地**，
若它不出 PCLK，原因只可能在 ①供电 ②复位 ③模块自身故障 三处。

### 0.6 视频格式（对接我们自己的采集通路时必须知道）

厂商教程原文：

> "AN5642 模块使用 **DVP** 传输视频，PCLK 为像素时钟，HREF 为行同步信号，
> 当 HREF 为高时视频数据有效，VSYNC 为场同步信号。数据线为 **10Bit**，
> 我们的程序**只使用其中的 8Bit**。在开发板中我们配置为 **RGB565** 输出，
> 因为数据总线是 8Bit，所以 **2 个时钟周期传输一个像素**的数据，
> 在 FPGA 接收端再拼接成完整的像素数据。"

→ 我们的 CNN 要 64×64 灰度；从 DVP 8bit/RGB565/2clk-per-pixel 到灰度要**自己写**。
厂商 `alinx_ov5640` IP 里的 `cmos_8_16bit` 就是干这个的，**可参考、不要当现成积木塞进 w6f**。

### 0.7 两张卡不要混：手写 RTL 那张**不接 J10**

| 比特流 | 是否驱动 J10 | 相机在位时 |
|---|---|---|
| `dl/w6/w6f/.../design_1_wrapper.bit`（TrustScope CNN 核） | **完全不接**（BD 无任何对外封装引脚） | 结构上安全 |
| `ps_fft_dual/vivado` 的相机+显示工程 | **接满 J10** | 会与相机争引脚 |

**所以"第一次点灯"必须用厂商那套已验证的相机工程**，不要一上来就把相机挂到 `w6f` 上。

## 1. 上次到底怎么坏的：两个并列假设 + 各自的判别测量

### 1.1 已实测的事实（来源：`vendor/返修故障说明_可打印.md`、`相机问题技术说明.md`）

| # | 事实 | 数值 |
|---|---|---|
| 1 | 模块**单独**装在板上时，I2C 空闲电平被拉低 | PIN20 / PIN23 = **1.7–1.79V**（不插模块时 3.3V） |
| 2 | LVCMOS33 的 VIH ≈ 2.0V | **1.7V < 2.0V** → FPGA 必然识别不到高电平 |
| 3 | 模块上 **2.8V（AVDD）轨测不到** | — |
| 4 | 板侧供电正常 | PIN2 = 5V、PIN39 = 3.3V、PIN40 = 3.3V |
| 5 | 同一块板、同一条 I2C 总线，换插备用 OV2640 **完全正常** | PID/VER 四次读全部一致 → **板侧完好** |
| 6 | 芯片 ID 全地址、全复位状态无应答；PCLK 恒为 0 | — |
| 7 | 模块 PCB 上 **+5V 走线烧断** | 物理损伤（`HARDWARE_SAFETY.md` 记录） |
| 8 | 故障报告称"相机在**任何重新插拔之前**就已无法工作" | → 排除"重新插拔/热插拔" |

### 1.2 假设 H1 · 模块内部电源树故障

模块从 **J10 PIN2 取 +5V**，在板上自己产生 3.3V/2.8V/1.8V/1.5V 各轨。
若这条链上任何一处短路或 LDO 失效：

```
5V 轨过流 → +5V 走线烧断（事实 7）
          → 全部板载轨死掉 → 2.8V 测不到（事实 3）
          → 传感器无电 → 无 PCLK、无 I2C 应答（事实 6）
          → 模块侧 SCCB 上拉失去 3.3V 参考 → 总线被拉到 1.7V（事实 1）
```

**一个机制同时解释全部现象**，且与"板侧完好"（事实 5）完全自洽。

### 1.3 假设 H2 · 第一次插入时插反 / 错位

官方引脚表让这一条的后果**可以精确算**（§3）：
反插会同时造成 **+5V→GND 死短**、**+3.3V→GND 死短**、**+5V 灌进模块 +3.3V 轨**
三处。**"烧 +5V 走线"正是这个后果该有的样子。**

**但我要如实说明**：事实 8 只排除了"重新插拔造成的损坏"，
**并没有排除"第一次就插反"** —— 如果第一次就是反的，它当然"从未工作过"。
所以 **H2 仍然活着**，上一版把它写成"最可能的机制"是过强，但完全丢掉它也是错的。

### 1.4 判别测量（区分 H1 / H2）

**手上还有那块坏模块的话，做这一条，成本几分钟，能直接定案：**

- [ ] 看坏模块的**物理损伤范围**：
  - **只有 +5V 路径**（走线/焊盘）受损，**+3.3V 输入脚与 3.3V 路径完好**
    → 指向 **H1**（模块内部 5V 下游短路）
  - **+5V 与 +3.3V 两侧都有损伤**，或 +3.3V 输入脚附近有烧痕
    → 指向 **H2**（反插：+3.3V 被直接怼到 GND）
- [ ] 坏模块**单独**（不插板）量 **模块 PIN2(+5V) ↔ 模块 PIN1(GND)** 电阻：
  - ≈0Ω 且不回升 → 5V 入口死短（H1 的内部短路，或 H2 烧出的桥连）
  - 高阻/缓慢上升 → 5V 入口正常，损坏在别处

> **这条决定"以后每颗模块都要不要先量电阻"**：若定案 H1，则**每颗模块上板前必须量**；
> 若定案 H2，则**对位/方向是唯一的关键**，电阻检查仍保留（免费）。

**不管定案哪个，§2 的闸门都要全过**——两套闸门本来就是为两个假设各挡一半。

## 2. 闸门流程（每道不过就停，不要"再看看"）

> 📋 **照着做的版本**在 `dl/CAMERA_BRINGUP_CHECKLIST.md` ——
> 带空白格可以边做边填数，做完直接抄进 `HARDWARE_SAFETY.md`。
> 下面这节讲的是**每道闸门为什么这么设计**。

### 闸门 0 · 断电、模块**单独在桌上**（零风险，**本次唯一的事前保护**）

> 因为**没有限流电源**，这一道从"建议"升级为"**必做**"。
> 好在它零风险，而且正好对准上次的失效模式：
> **烧断 +5V 走线 = 5V 入口短路** —— 死短用万用表看得一清二楚。

**0a · 先解决"我量的是哪个孔"（不依赖丝印）**

模块连接器是母座，探针伸不进去：插两根细排针/杜邦线再去夹表笔。
但**先别信丝印** —— 用**导通性**自己把电源脚找出来，这一步同时就是**方向确认**：

| 预测（由"模块第 n 脚 ↔ J10 第 n 脚"推出） | 量法 | 应该看到 |
|---|---|---|
| 模块 **PIN1 / PIN37 / PIN38** 三个都是 GND | 两两互量 | **≈0Ω（导通）** |
| 模块 **PIN39 / PIN40** 两个都是 +3.3V | 互量 | **≈0Ω（导通）** |
| GND 组 ↔ +3.3V 组 | 互量 | **不导通**（LDO 输出对地不是 0Ω） |

**做完这一步，模块的朝向就唯一确定了**，不需要看清丝印。

> ⚠️ **如果三个 GND 脚之间不是 ≈0Ω，说明我的推导错了 → 停下来，不要通电，
> 把实测结果告诉我。** 这是**可证伪的预测**，不是"应该差不多"。

**0b · 真正的短路检查**

- [ ] **模块 PIN2(+5V) ↔ 模块 PIN1(GND)**：读数应**缓慢上升**（去耦电容充电）后到几十 kΩ 以上
      - **几欧 / 蜂鸣 / 不回升 → 停止，不上板**
- [ ] **模块 PIN39/40(+3.3V) ↔ 模块 PIN1(GND)**：同样
- [ ] **把这几个数写进 `HARDWARE_SAFETY.md`** —— 新模块的基线，以后换模块就靠它对照

### 闸门 1 · 对位（**不要靠手感**，这是 H2 的唯一杀手）

- [ ] 在**板上**找 J10 丝印：**PIN1(GND) / PIN2(+5V) / PIN39,40(+3.3V)**
      （ALINX 明说这四个脚在板上已标示）
- [ ] 在**模块上**找它自己的 **PIN1 / PIN2 标记**
- [ ] 两侧**同一朝向**才算对；模块丝印看不清就用闸门 2 的电阻测量替代判断
- [ ] 逐脚核对 §0.3 表：`cmos1` 的 D0–D9、PCLK、HREF、VSYNC、SDA、SCL、复位
      分别落在 J10 的哪几脚上

### 闸门 2 · **插好之后、通电之前**（断电测，把错插堵死在通电之前）

- [ ] **J10 PIN2 (+5V) ↔ J10 PIN1 (GND)**：几十欧以上 → 通过；**几欧/短路 → 拔下重插，不要通电**
- [ ] **J10 PIN39 (+3.3V) ↔ J10 PIN1 (GND)**：同上
- [ ] **J10 PIN40 (+3.3V) ↔ J10 PIN1 (GND)**：同上

> 为什么要量三组：反插时 **PIN2↔PIN1** 和 **PIN39/40↔PIN1** 会分别变成
> 模块 GND→板 +5V、模块 +3.3V→板 GND 的直通（§3），三组一起量覆盖得更全。

### 闸门 3 · 首次通电（**没有限流电源的版本**）

> 前提：闸门 0 与闸门 2 都已通过。
> **没有限流手段，所以"通电后的头 30 秒"本身就是保护。人不要走开。**

**上电前**：手放在电源开关上；**确认 B20 ↔ V12 跳线未插**（§4.1）。

**上电后按顺序做 —— 任何一步异常立刻断电：**

| 顺序 | 动作 | 期望 | 异常 → 立刻断电 |
|---|---|---|---|
| 1（+3s） | 目视 + **手背靠近**模块 LDO 区域（不要用手心按） | 常温 | 明显发热 |
| 2（+5s） | 量 **J10 PIN2** 对 PIN1 | 5V | 掉压 / 跳动 |
| 3（+10s） | 量 **PIN39 / PIN40** 对 PIN1 | 3.3V | 掉压 |
| 4（+20s） | 量 **PIN20 (SDA)** 对 PIN1 | **3.3V** | **≈1.7V → 故障** |
| 5（+25s） | 量 **PIN23 (SCL)** 对 PIN1 | **3.3V** | **≈1.7V → 故障** |
| 6（+30s） | 看板上电源指示 / 听有无异响 | 正常 | 任何异常 |

**第 4、5 步是关键**：PIN20/PIN23 掉到 ≈1.7V **就是上次那颗模块的指纹**，
出现即判定模块侧故障 —— **断电，不要继续去调软件**。

**残余风险（如实说明，不粉饰）**

没有限流手段时，**若模块是在通电瞬间才短路（闸门 0 量不出来），头几秒仍会过流**。
可依据的**实测**事实是：上次那颗模块烧的是**它自己的 +5V 走线**，
而板侧事后被证明完好（同板换插 OV2640 完全正常）
—— 也就是说**模块的细走线充当了保险丝，代价上限主要是模块，不是板子**。
这降低了板子的风险，但**不等于零**。

**如果愿意花十几块钱把风险再降一档**（本次唯一值得买的耗材）：
在 +5V 通路里串一只 **自恢复保险丝（PPTC，5V/0.5A）** 或 **5.1Ω / 5W 水泥电阻**再上电。

| 红表笔 | 期望 | **异常值 = 上次那种故障** |
|---|---|---|
| PIN2 (+5V) | 5V | 掉压 → 立刻断电 |
| PIN39 (+3.3V) | 3.3V | 掉压 → 立刻断电 |
| PIN40 (+3.3V) | 3.3V | 掉压 → 立刻断电 |
| **PIN20 (SDA)** | **3.3V** | **≈1.7V → 模块侧故障，立刻断电** |
| **PIN23 (SCL)** | **3.3V** | **≈1.7V → 模块侧故障，立刻断电** |

> **PIN20/PIN23 = 1.7V 就是上次那颗模块的指纹。**
> 这条只需万用表、30 秒，并且是**当前唯一能区分"好模块/坏模块"的即时判据**
> —— 把它当成新模块的验收测试，比任何软件调试都早。

### 闸门 4 · 诊断按证据链，**电源优先、软件最后**

1. [ ] 模块端 3.3V 轨
2. [ ] 模块板上 LDO 输出的 **2.8V / 1.5V 轨**（就是上次缺失的那条）
3. [ ] **PCLK 是否跳变**（接 PL 计数器做长时间统计——相机出图最硬的证据）
4. [ ] SCCB 空闲电平（闸门 3 已量）
5. [ ] **最后**才读芯片 ID、写初始化寄存器

> **顺序反了，就会把电源/时钟问题当成软件问题。**
> 上次的代价就在这里：看到"ID 读 0x00、302 条寄存器全失败、PCLK 不跳"，
> 先按软件链路查了数天，最后才发现模块端 **2.8V 轨都测不到**。

### 闸门 5 · 一次只改一处

上电阶段**严禁**同时换方向 + 换工程 + 改代码——否则出错无法归因。

## 3. 反插的精确后果（从 §0.3 表算出，不是猜）

反插 180° 时，模块第 *n* 脚对上 J10 第 *(41−n)* 脚。代入 §0.3：

| 模块脚 | 模块上是什么 | 对上 J10 脚 | J10 上是什么 | 后果 |
|---|---|---|---|---|
| PIN1 | GND | PIN40 | +3.3V | **+3.3V 直通 GND** |
| PIN2 | +5V | PIN39 | +3.3V | **5V 灌进模块 3.3V 轨** |
| PIN39 | +3.3V | PIN2 | **+5V** | **5V 灌进模块 3.3V 轨** |
| PIN40 | +3.3V | PIN1 | **GND** | **模块 3.3V 轨直接对地** |
| PIN37/38 | GND | PIN4/PIN3 | IO | IO 被拉地 |
| PIN3–18 | `cmos2` IO | PIN38–PIN23 | 地 / `cmos1` IO | IO 对顶或对地 |
| PIN20–35 | `cmos1` IO | PIN21–PIN6 | `cmos2` IO / 地 | IO 对顶 |

**结论**：反插不是"可能有点问题"，而是**三处电源轨同时故障**——
其中 **J10 PIN2(+5V) → 模块 PIN1(GND)** 是**电源对地的纯短路**，
**"烧断 +5V 走线"正是它该产生的结果**。
33Ω 排阻在这条路径上**完全保护不到**（排阻串在 IO 上，不在电源上）。

> 所以：**反插能完美解释事实 7，但解释不了"2.8V 轨测不到"为什么不伴随 3.3V 侧损伤**
> —— 这正是 §1.4 要问坏模块的原因。

## 4. 仍然存在的隐患与未知

### 4.1 ⚠️ 隐患 1 · B20 ↔ V12 跳线，相机在位时必须拔掉（**保留，且现在就要拔**）

- `B20` = J10 **PIN35** = `cmos_rstn_tri_o[0]` = **相机复位**（官方定义，§0.3）
- `V12` = J10 **PIN28** = `cmos1_d[0]` = **相机的输出脚**
- 跳线把"我们的输出"接到"相机的输出脚" → **只有相机在位时才对顶**
- **未插是唯一在有相机/无相机两种配置下都正确的状态** → 不要为任何用途插回去

**另附一条本工程已核对的结论**：本项目 `submission/board/two_fft.xdc` 里
**`lcd_blen` = F16（J11 屏背光），B20 = `GPIO_0_tri_o[0]`（相机复位）**。
所以"我们的应用把 B20 当背光使、以致把相机按在复位里"这个担心在**本工程不成立**——
B20 本来就是复位。但**复位必须先释放**，见 4.2。

### 4.2 复位脚：`cmos_rstn` 是**三态输出**

官方端口名是 `cmos_rstn_tri_o[0]`（`axi_gpio` 的 `tri_o`）。
上电后第一件事就是确认 **GPIO 方向 = 输出**、**复位已释放（拉高）**。
方向没配对 → 引脚悬空 → 复位状态不确定 → 症状又是"无 PCLK、ID 读 0"。

### 4.3 ⚠️ `cmos1_pclk`（T11）**不是时钟专用脚**

官方 XDC 里有一句：

```tcl
set_property CLOCK_DEDICATED_ROUTE FALSE [get_nets cmos1_pclk_IBUF]
```

依据 J10 表：PIN31 = T10 = `IO_L1N_T0_34`、PIN32 = T11 = `IO_L1P_T0_34`
—— 这是一对差分对的 P/N，**T11 不是 MRCC/SRCC**。
→ **我们自己接相机时，PCLK 打进 BUFG/BUFIO 会撞 DRC**；
用不用这个属性、还是改走别的时钟资源，要**在实现阶段就知道**，不要在 DRC 报错时才现查。

### 4.4 对焦：**必须先确认 AN5642 的镜头是定焦还是自动对焦**（未确认）

- `camera_doc` 里的 `CV-5021G2规格书` 描述的是 **OV5640 模组**，带 `AF-VCC (PIN23)`、
  `AF-GND (PIN24)` 和 VCM —— 但那是**另一块板**，**不能直接套到 AN5642 上**。
- 若 AN5642 也带 AF：**AF 一动镜头，放大率就变 → mm/px 标定被污染**。
  经典路径要测"缺口 ≥2mm、孔径偏差 ≥0.5mm"，**mm/px 必须恒定**。
- [ ] 看模块上**有没有音圈马达/VCM 器件**、镜头能否被软件推动
- [ ] **锁死焦点**，锁焦后**重新标定 mm/px**，并记录工作距离

### 4.5 视场角（FOV）：**必须实测，不能引用规格书**

我们产品定义依赖"**16mm 视场、0.25mm/像素**"。
`CV-5021G2` 写的 **焦距 3.2mm / 视场 68°** 是**那块单目板**的数，
AN5642 的镜头是它自己的——**没有任何理由沿用**。
- [ ] 相机通了以后，在固定工作距离上放**已知尺寸**的靶标，量出 **mm/px 与 FOV**，
      写进设计报告的标定章节

### 4.6 透射背光：模块自带 LED 替代不了

产品要的是**透射背光**（工件暗、缺料亮）；模块上的 LED 是**正面补光**。
- [ ] 透射背光要**单独做**，且**可调亮度**（那是后面"光源闭环"功能的前提）
- [ ] 需要引控制线时，用 **PIN19 (U17) / PIN36 (C20)** —— 相机没占这两根（§0.4）

### 4.7 双目 ≠ 三维

AN5642 的**两颗传感器固定在同一块 PCB 上并排**，**无法分别指向两个方向**
（`项目定义_收紧版.md` line 122）。准确说法是"**双视角**"，
**在没有立体匹配与标定之前不要写成"双目三维检测"**。
