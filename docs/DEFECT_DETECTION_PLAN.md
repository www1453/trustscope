（P1 标签集、加速器通路）都还不具备。

## 2. route A：现有链路上的手工特征

### 2.1 特征清单

| # | 特征 | 目标类别 | 怎么算（尽量用已有量） | 需要新写什么 |
|---|---|---|---|---|
| A1 | 亮连通域的**数量 / 面积 / 长宽比 / 主轴方向** | `bridge` | 阈值分割亮像素 → 连通域 → 形态统计；"细长 + 跨越两个高光中心"是桥连的形态 | 连通域统计（板上有 `MB_BB_*` 的先例，规则是"跨焊盘"） |
| A2 | **高光形状与碎裂度**：大高光数量、总高光面积、最大高光面积占比 | `cold_joint` | 好焊点 = 一个连续大高光；冷焊 = 多个小亮斑、总面积下降 | 高光分割（阈值偏高） |
| A3 | 焊料区面积 / 焊盘面积 | `insufficient_solder` | 焊盘区域由**参考图**给出（`pcb_check.py` 的比对思路），露铜（高亮/金属色）比例上升 | 需要一个"焊盘掩膜"来源：参考图或人工框 |
| A4 | 与**已知好板参考图**的差分面积、差分连通域数 | `missing_part` `offset` | 项目已有相位相关配准 + 差分 + 连通域 | 复用 `app/pcb_check.py` |
| A5 | 高光中心相对**焊盘中心**的偏移向量 | `offset` | 先配准，再算两个质心之差 | 配准复用 |
| A6 | 差分连通域的**竖直长条 + 一端缺失** | `tombstone` `bent_lead` | 顶视下"一个焊盘全空 + 另一端有料"是高风险的形态提示（不是判据） | 需要侧视图才可靠，顶视只能提示 |

**要写的预测（改任何东西之前先写下来）**：A1~A5 里哪些量在该类上的
**类间差 / 噪声地板**比值大于 3？写下预测再跑，跑完不改判据。

### 2.2 判据纪律（本项目已经付过代价的部分）

1. **阈值来自零分布，不是拍脑袋。** 先在**无缺陷**焊点上跑同一个特征，得到中位数 + 3σ 作为检出阈值
   （`dl/LIGHTING_DECISION.md` 里就是这么做的：噪声地板 6.49、阈值 7.18）。
2. **判据要能暴露目标缺陷。** 项目已有一条教训：判据选错时"现象不存在"是假象
   （"缺陷区均值"对沟槽天生不敏感）。焊点这边同构：**只取均值会把桥连与走线平均掉**，
   所以 A1 用**连通域形态**而不是区域均值。
3. **必须有归零检查。** 在**已知无缺陷**的图上，每个新特征必须回到零分布区间内；
   不跑这一步，任何"检出率"都不可信。
4. **弃权不进分母。** `miss`（漏检）与 `fa`（误报）的分母分开，`abstain` 单独报
   （`app/pcb_check.py` 已经是这个格式，沿用它）。
5. **平凡基线必须一起报**：全判"合格"→ miss 100%；全判"无法判定"→ 看着完美，其实没干活。

### 2.3 P0 实验（预注册模板，先写再跑）

```
目标：判断这 7 个缺陷类在**本机成像**下是否具备可分性（不是测检出率）
样本：每类 5~10 个**不同焊点**（不是同一焊点多拍）
对照：每个坏焊点配一张同批同位号的好焊点图
量：A1~A5 的特征值（每类一个分布）
判据：类间中位数差 / 零分布 σ  ≥ 3 记"可分"；< 1 记"不可分"；中间记"需更多光照/角度"
弃权条件：剪切、失焦、遮挡的帧不参与（单独计数）
允许的结论："特征量在该类上有可测差异"
不允许的结论：任何"检出率 %"
```

### 2.4 route A 的诚实边界

- 没有标签 → 阈值无依据 → **不能给检出率**。这一步能做的只是一句"这个量动没动"。
- **原理性不可分**要敢于说出来。项目已有实测：单光源下"划了"与"脏了"区分不了
  （形状与反照率混在一起）。冷焊与助焊剂残留是同一类问题：
  灰度上两者都可能"发暗且不反光"，**颜色**才是主要线索。
- 别用调参把误报压下去换一个好看的数 —— 那是把 `unsure` 藏起来，不是把问题解决。

### 2.5 落点

- 特征计算：新增到 **PC 侧**（`app/` 或 `dl/`）先跑离线；板上只保留已经验证过的量。
- 需要上板的量：先想清楚**归零检查怎么做**（当前场景是不是无缺陷），再决定要不要上板。

## 3. route B：用现有 CNN 加速器

### 3.1 不可协商的 I/O

| 项 | 值 | 出处 |
|---|---|---|
| 输入 | 64×64×**uint8**（单通道，4096 B） | `ps_ui/cnn_drv.h` `CNN_IMG_BYTES` |
| 输出 | **2 个 int32 logit** | `cnn_run(const uint8_t *img, int32_t *out2)` |
| 控制/参数寄存器 | `0x43C20000` / `0x43C30000` | `ps_ui/cnn_drv.h` |
| 单次推理时间 | 记录里 150 MHz 下 4.813 ms；**实际频率下的值待测** | 交接文件 + `dl/CNN_INTEGRATION_RECIPE.md` 约束 4：`FCLK_CLK0` 设计值 50 MHz，且实测寄存器曾只有 16.67 MHz |
| 通路状态 | **不工作**（控制寄存器写不进） | `cnn_drv.c` 自述 + 任务背景 |

**推论（必须写进任何方案）**：2 个 logit 只够**二分类**。10 类外观分类在本硬件上
不是一个模型能一次给出来的结果。

### 3.2 把 10 类映射到"只能二分类"的三种做法

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| B-a 任务级联 | 任务1：缺陷/正常；任务2：桥连/其它；任务3：虚焊/其它…… 每次一个二分类 | 每次推理都要一次前向；类别越多越慢；**每个任务的权重与训练集都要单独管** | 误差沿级联累积；前面的任务错，后面全错 |
| B-b one-vs-rest | 10 次二分类取最大分 | 10 倍推理时间；判据简单，报告最好写 | 时间预算紧；分数之间不可比时需要校准 |
| B-c 改造 HLS 扩输出维度 | 重写 IP 输出为 N 类 | **要重综合**，有翻车风险与时间成本 | 本项目在 BD/综合上付过代价，非必要不做 |

**建议**：先用 **B-a 的两级形式**（第一级只做"外观异常 / 未见异常"），
因为本项目现有的三态判定与看板已经围绕"正常/异常/无法判定"长了出来；
对具体类别先只做**归因展示**（哪一类像），不承诺每一类都有独立置信度。

### 3.3 数据需求与切分纪律

- 规模：见 README 第 5.2 节的 **P1**（缺陷类各 ≥100 个不同焊点、`ok` ≥300、
  `lookalike` 每个子类 ≥30）。
- 切分单位是**采集批次 / 板号**，**不是随机行号**：同一块板的相邻焊点在图像上高度相关，
  随机切分会让训练与测试"见过彼此"，把检出率抬成假的高。
- **前瞻留一只用更早的数据**（本项目已有纪律，见 skill 里的 `agent-experiment-discipline`）：
  任何"以后也能用"的结论，留出验证只能用**时间上更早**采集的数据；
  用随机切分支撑面向未来的结论是不成立的。
- 每一类的样本数、来源板数、采集批次**必须与结果一起报**。
- `lookalike` 与 `unsure` **不计入"缺陷检出率"的分母**，但必须单独报。

### 3.4 预处理契约（最容易翻车的一条）

64×64 uint8 是单通道，而且裁剪会丢掉位置信息。所以必须把下面三件事**写死并共享**：

1. **裁剪框的坐标系**：标注时记下的 `box` 是**图像文件的像素坐标**。
   推理时的裁剪必须用**同一个坐标系**、同一套缩放（建议先裁剪再缩放，不要先缩放再裁剪）。
2. **灰度公式**：彩色帧 → 单通道必须用**同一个固定公式**（建议 BT.601 luma）。
   不一致 = 训练输入与推理输入不同分布。**这是最难发现的失败模式之一**，
   必须在代码里写两遍（产生端与消费端各写一遍），并在报告里写出公式。
3. **裁剪框是否跟着元件走**：
   - `bridge` / `cold_joint` / `insufficient_solder` / `lookalike`：可以跟着焊点裁；
   - `offset` / `missing_part` / `tombstone` / `bent_lead`：**必须相对焊盘/板固定**，
     否则"偏移了多少"在裁剪那一刻就没了。固定就需要**配准**（项目已有相位相关配准）。

### 3.5 时间预算（必须实测，不要沿用别处的数）

- 记录值：150 MHz 下 4.813 ms/次。
- 若实际 `FCLK_CLK0` = 50 MHz：约 **14.4 ms/次**；B-b（10 次）≈ **144 ms/件**。
- 单件预算 200 ms（来自项目记录）→ 理论上够，但**余量很小**，
  而且"挂在这个时钟域上跑出来的是多少"**从来没有实测过**。
- 结论：**先实测一次真实频率下的单次推理时间，再决定 B-a 还是 B-b。**
  不要用 150 MHz 的数字写报告（`dl/CNN_INTEGRATION_RECIPE.md` 里已经写明这一条）。

### 3.6 面板与看板该显示什么

**规则（一条，写死）**：任何地方都只能显示「**疑似**〈类别〉〈分数〉」，
不显示"开路/短路/通断"。分数是**分类器分数**，不是电气量，标签与单位都不得暗示电学含义。

- 面板（800×480）：`疑似桥连 0.83`。
  现有 5×7 字库缺 W/Z（项目已记录），中文需走 `dl/ts_cn_font.h` 的中文字库，文案要短。
- 邮箱：现有 `MB_CNN_CLS`(129) 只有 0/1。
  要显示具体类别与分数，需要**新增邮箱字**（例如 131 = 类别号、132 = 分数×1000；
  新增前必须逐个核对地址确实空闲，当前 0~130 的占用情况见 README 第 7 节）。
- **`MB_CNN_OK != 1` 时这些字不是结论**：看板与面板必须显示「**不可用**」。
  看板既有的 `stale` 规则就是这样（数值 `null`、不显示 0），缺陷字段沿用同一规则。
- 主机侧建议新增字段（**尚未实现**）：`classifier.defect_label_zh`、
  `classifier.defect_score_pm`、`classifier.defect_model_version`、`classifier.defect_note`，
  并让 `dl/check_status_feed.py` 多覆盖一条"缺陷字段缺失时必须显示不可用"的断言。

### 3.7 阻塞项

| 阻塞 | 影响 | 谁来解 |
|---|---|---|
| 加速器控制寄存器写不进 | route B 无法运行 | 另一个未解决的问题（`cnn_drv.c` / BD），**不属于本目录范围** |
| 没有标签集 | 无法训练、无法评估 | 本目录（采集 + `dl/label_defects.py`） |
| 输出只有 2 类 | 10 类装不下 | 方案设计（B-a / B-b / B-c） |
| 灰度丢颜色 | 冷焊 vs 助焊剂残留可能不可分 | 预处理契约 + 也许需要第二路颜色通道（超出当前 IP） |

## 4. 两条路线的关系与建议顺序

```
① route A 的 P0（每类 5~10 张）
        │
        ├── 特征量"可分" ──→ 采 P1 数据 ──→ 修好 CNN 通路 ──→ route B 训练+评估(按板/时间切分)
        │                                            └── 与 route A 的特征做基线对比：谁更好、差多少
        │
        └── 特征量"不可分" ──→ 先解决成像（换光照/加角度/加侧视），
                              不要用 CNN 硬分 —— 那只会得到一个在测试集上好看的假象
```

**两条路线必须打同一场对比**：同一份 P1 数据、同一套切分，
route A 的特征分类器与 route B 的 CNN 各报一组 `miss / fa / abstain`。
只报一个模型、没有基线，等于没有结论（本项目已有这条纪律）。

## 5. 明确不做的事

1. **不用合成图像冒充焊点样本。** `dl/synth_defects.py` / `build_dataset.py` 造的是
   **平面工件的光照/形状实验数据**，它们服务的是另一条主线；
   把它们当作本目录的样本是伪造数据。本目录的 `manifest.json` 现在就是 **0 行**。
2. **不改冻结的 HLS 交付物**（`dl/hls/ip_v12_verified`），除非明确选择 B-c 且单独评估代价。
3. **不在没有标签的情况下宣布任何检出率**，包括在报告、看板、面板文案与演示里。
4. **不把"无法判定"当失败**，也不把它藏进分母。
5. **不把绝对路径（会带个人账户名）写进 manifest / 文件名 / 文档**；
   本目录的 `rel_path` 必须是相对路径，校验器会拒绝其它形式。
