# 2026-10-31 18:0x — 环光（调暗一半）的结果：预注册判据未通过，但良品侧确实变干净，且暴露出"残差在变、位姿不变"

> 预注册见 `dl/RINGLIGHT_PREREG_20261031.md`（看数之前冻结）。判据是**同一会话内**的
> `separation = min(d30) − max(g7) > 0`，由 `null_floor.py` 机械判定。

## 1. 判决（E2）

```
null   g7  : 0.767  0.833  0.800  0.800  1.400   -> max 1.400   median 0.800
signal d30 : 1.567  1.600  0.900  1.033  1.367   -> min 0.900   median 1.367
separation = 0.900 − 1.400 = −0.500            -> FAIL
```

**H1（灯让这个统计量第一次可用）被推翻。** H2（只改变几何）的**前半成立、后半不成立**：
良品侧的中位数从今早的 1.367 降到 **0.800**（同会话内、n=5），
但**两侧各出现一个离群值**（g7_r5 = 1.400 且 darea = 6；d30_r3 = 0.900 且 darea = 0），
判据是由离群值决定的。

## 2. 灯的作用：把"典型情况"变干净了（E2，但不可跨会话比）

| 量 | 今早（旧光，exp 8662） | 现在（环光，exp 4331） |
|---|---|---|
| g7 五次 max_z 中位 | 1.367 | **0.800** |
| g7 五次 darea | 1 / 3 / 1 / 1 / 1 | 0 / 0 / 0 / 0 / **6** |
| 参考掩膜 cam0 / cam1 | 791 / 745 | 972 / 798 |

**不能把这张表直接读成"灯把残差减半"**：曝光同时从 8662 降到 4331，而残差是灰度差、
会随信号按比例缩小，而 `z` 的分母是固定 30 灰（`tol_used=0`）——**这个 z 不是尺度不变的**。
所以跨会话只能看方向，不能看幅度；判据之所以只用同会话内的 separation，就是这个原因。

## 3. 判决之外发现的一件事：残差在变，位姿没变

十次摆位的注册状态**全部是 `reg_mode = 2 (hold)`**，而 `pose_dx` 十次里有九次恒为 **−164**
（= −10.25 源像素 ≈ 0.5 mm）。操作者每次按指示把板挪了 **2–5 mm（40–100 px）**，
位姿字却没跟着变，而 max_z 从 0.767 变到 1.400。

**两个后果：**

1. 今早记的"摆位噪声 0.23–0.57 z"**不是纯粹的手放重复性**，而是"手放 × 注册行为"的合成量。
   夹具只能压掉手放那一半。
2. 一个良品板在 g7_r5 上读到 **darea = 6**（限值 8）——**离误判 NG 只差一格**。
   这一格的来源还没有说明白，但对产线来说它是"良品被判 NG"的唯一通道。

**我还没有说清 `reg_mode = 2` 到底是"搜索跑了、旧解仍然胜出"还是"搜索被跳过"**。
词表写的是 "how the last search answered: 1 warm, 2 hold, …"，按字面是前者；
但 2–5 mm 的位置变化不该让旧解胜出。**这一条需要读代码才能定，我不在这里下结论。**

## 4. 结论与下一步

- **灯：装上、调暗到一半可用（clip 1‰），它把良品的典型残差从 1.367 降到 0.800**（E2，同会话）。
- **格级统计量：仍然不可用**（预注册判据 FAIL，separation −0.500）。脊线/色度/长度继续封存。
- **下一个该查的不是统计量，是注册**：一个良品板能被读到 6 格，说明问题在"残差为什么会跳"，
  而不在"怎么把残差变成判决"。要查的是 `reg_mode = hold` 的判据：它在什么条件下才重新搜索，
  2–5 mm 的位移为什么不足以触发。
