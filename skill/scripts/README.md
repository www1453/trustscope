# `scripts/` — 校验脚本（可复用，离线，自带自测）

> **这一项目录解决的是"判据本身不可信"**：脚本永远返回"通过"、闸门读了一个它没读的字、
> 统计量的地板比信号还高。每一条都有真实代价，见 `../pitfalls/` 的 D2 / D6 / M53。

## 三条硬约束（本目录的每个文件都遵守）

1. **不需要项目树**：没有一个脚本硬编码本项目路径。路径都是参数或当前目录。
2. **离线**：不需要板子、不需要工具链、不需要网络。全部只依赖 Python 3 标准库。
3. **有已知答案的自测**：`--selftest` 用的是**故意的坏输入**（两个名字撞同一地址、
   null 高于信号、GBK 编码的针……）。**没有在坏输入上失败过的检查器，不算检查器。**

一条命令跑完：

```bash
python skill/scripts/run_selftests.py        # 6/6 passed 才算可用
```

## `readset_lint.py` — 闸门必须读它判断的那个字段

**适用场景**
工具先把一批字段读进一个结果对象，再由若干"闸门"读这些字段决定放行/拒绝。
读取集合是一份**手写名单**，而闸门是后来加的 —— 两边一旦不同步，闸门读到 `None`，
把"我没读"翻译成"被测对象是坏的"。

**使用方法**

```bash
python skill/scripts/readset_lint.py my_tool.py
python skill/scripts/readset_lint.py my_tool.py wordtable.py     # 读取集合在另一个模块时
python skill/scripts/readset_lint.py my_tool.py --decl ROW_WORDS --strict
python skill/scripts/readset_lint.py my_tool.py --attr value,get # 读取函数叫别的名字时
```

识别三种形状：`NAME = ("a","b")` 的命名集合、`read(("a","b"))` 的**行内**集合、
以及 `obj.value("a")` 的使用点。读参数不是字面量时它**明说"无法解析"**，不假装通过。

**已验证的效果**
- 自测三例：命名集合干净→0、命名集合缺字段→1、行内集合缺字段→1。
- 在本项目两台验收工具上跑：修复后 **0 findings**（`accept_range.py` 与 `accept_enter.py`）。
- 它的第一版在正确的代码上报了 8 条假警（把普通 dict 的 `.get("ok")` 也算读取），
  **这正是它要防的那类错误**——所以默认只认 `value(`，见脚本内的 SCOPE 注释。

**失效条件**
- 字段名在运行期拼出来（f-string、读配置、循环变量）→ 它看不见，会漏。此时仍要靠
  "闸门拒绝时先打印它的输入"（案例 D6 的做法）。
- 读取集合与判据混在同一个循环里、没有可识别的集合字面量 → 它没有可对照的东西，
  需要先把手写名单提出来（这件事本身通常就能发现不同步）。

## `null_floor.py` — 先量地板，再花样本

**适用场景**
你有一个新统计量，准备采一批正常样本定阈值。**先做 null**：同一个对象对自己、
摆位不变、正确答案已知为"无缺陷"，看统计量读出多少。

**使用方法**

```bash
python skill/scripts/null_floor.py rows.csv --value out_area --class kind \
    --null-label selfnull --defect-label chip
python skill/scripts/null_floor.py rows.csv --value eg_cells --class kind \
    --null-label same --known-defect-max 11     # 还没有缺陷样本时用规格值
```

输出 `max(null)` / `min(defect)` / 分离度，判据是 `分离度 > --margin`（默认 0）。
退出码 0=PASS、1=FAIL、2=证据不足（**证据不足不算通过**）。

**已验证的效果**
- 自测两例：可分（null 3–7，缺陷 20–41）→ PASS；不可分（null 141–150，缺陷 3–7）→ FAIL。
- 第二例的数字**就是本项目真实的 null**：轮廓面积 141/150/149，而它要抓的角缺是 3–7 格；
  同一天另一个统计量的 null 是 44–80，修好后 20，而划痕的最大读数是 11。
- 这两个统计量因此被判死，**没有**被投入 population —— 这正是它存在的意义。

**失效条件**
- null 不是真 null（两块同型号板子、两次不同摆位）→ 结论无效。必须是**同一个对象**。
- `--known-defect-max` 是规格值而不是实测值 → 判决继承了那个假设，要写明。
- 它只看**一个统计量**。通过了地板检查，仍可能在 population 上死在阈值/分布上；
  这条只负责拦住"最贵的那一种失败"：样本花完了才发现地板在信号上面。

## `wordmap_check.py` — 编译器检查类型，不检查地址

**适用场景**
任何"名字 → 地址/索引"的映射：邮箱字、寄存器偏移、CSV 列号、配置键。

**使用方法**

```bash
python skill/scripts/wordmap_check.py ps_ui/main.c --format define --prefix MB_
python skill/scripts/wordmap_check.py map.csv --format csv --gaps
python skill/scripts/wordmap_check.py words.tcl --format kv
```

`--prefix` 很重要：一个固件源文件里同时有**地址**（`0x43C00000`）和**槽位号**（`408`），
不圈定命名空间会得到一屏噪声（这也是它的第一版行为，已修）。

**已验证的效果**
- 自测三例：干净 0、撞号 1、同名不同值 1。
- 在本项目固件头上跑：`--prefix MB_` → **414 个定义、413 个地址、0 findings**；
  另外报出一条"同名同值重复定义"的 note（噪声，不是缺陷）。
- 撞号类错误在本项目发生过：一个新计数器和已有的焦点值落在同一个字上，读到 192 并被当真。

**失效条件**
- 它比较**名字与数字**：混合单位（字节偏移 vs 字索引）的地图会给出假警，先统一单位。
- 同一个名字在不同函数里当局部变量 → 会被当成"同名不同值"，只喂**实际交付的那份地图**。

## `casebook_index.py` — 索引会腐烂，所以数它

**适用场景**
维护任何"按症状反查"的清单（踩坑集、FAQ、运维手册）。手写的覆盖率和手写的行号一样会腐烂。

**使用方法**

```bash
python skill/scripts/casebook_index.py skill/pitfalls
python skill/scripts/casebook_index.py skill/pitfalls --min-coverage 30
```

数三件事：条目数（`## ` 开头的 ID 标题）、索引里被引用到的 ID、
**指向不存在条目的"幽灵引用"**（比漏索引更糟：告诉读者答案存在，然后找不到）。

**已验证的效果**
- 自测：3 条条目、索引引用 2 条 + 1 条幽灵 → 条目数/覆盖率/幽灵三项全对。
- 在本项目案例集上跑：**144 条条目、索引覆盖 52 条（36.1%）**，与原来的专用脚本数字一致。
- 本项目历史上索引两次落后于文件（一次只索引了 36 条而文件有 139 条），
  两次都是**手写数字**造成的。

**失效条件**
- 条目标题不以 ID 开头 → 数不到。要么统一格式，要么接受它只数一部分。
- 正文里提到一个 ID 也算"已索引" → 它量的是**索引的触达范围**，不是索引的质量。

## `leak_scan.py` — 一次"扫了，零命中"可能是编码的锅

**适用场景**
提交前扫描"不能出现的机构/身份信息"，以及交付文件名里的个人绝对路径。

**使用方法**

```bash
python skill/scripts/leak_scan.py skill report
python skill/scripts/leak_scan.py . --needles my_exclusion_list.txt
python skill/scripts/leak_scan.py . --no-path-scan
```

每个文件按**字节**读，用 utf-8 / utf-8-sig / gbk 三种方式解码，**每种成功的解码都搜一遍**。
二进制按扩展名跳过（并计数报告），不会因为解码失败被当成"干净"。

**已验证的效果**
- 自测：一个 **GBK 编码**的针在 UTF-8 解码失败的情况下**仍然被找到**；
  一棵干净树报零命中。（这两个方向都要测 —— 只会报命中的扫描器会把干净树也报脏。）
- 第一次在本目录上跑时，它**命中了自己**（针表里的一个英文词出现在源码里）。
  修法是把那个词拆成 `"advi" + "sor"` 这样的拼接，并在注释里说明原因 ——
  这条自命中值得留在这里：一个扫描器最容易漏掉的文件就是它自己。

**失效条件**
- 没有对应的针就找不到对应的泄漏。**用你自己赛事的排除清单跑一遍**，不要只用默认针。
- **针是子串匹配，所以会命中合法的文件名/函数名。** 本仓库自带的那支扫描器，
  文件名里就含有针表中的一个英文词 —— 于是任何提到它的文档都会被判为"命中"。
  实测处理：**改文档措辞**（用角色描述代替文件名），而不是关掉这条针；
  因为关掉之后，真正的机构名也会一起漏掉。
- 压缩包/PDF/DOCX 按扩展名跳过 → 打包件里的泄漏在这里是**不可见**的；
  要么解包再扫，要么在打包流程里单独扫。
- 它是"读这一行"，不是"判这一行"。命中输出的是原文，由人判断。

## `tcl_lint.py` — 跑 Tcl 之前的三十秒

**适用场景**
任何 xsdb / Vivado Tcl 脚本，尤其是在**中文 Windows** 上（工具可能按 GBK 读脚本）。

**使用方法**

```bash
python skill/scripts/tcl_lint.py path\to\script.tcl [more.tcl ...]
```

三件事：非 ASCII 字节（会吃掉引号/括号）、括号/花括号配平、
**行尾 `#`**（Tcl 只在命令开头认注释，`CMD 0x0  # note` 是"多传了一个参数"）。
退出码 0 = 干净，1 = 有发现。

**已验证的效果**
- 原样副本，SHA-256 与 `ps_fft_dual/tcl_lint.py` 相同；`run_selftests.py` 用一对夹具
  （干净脚本 → 0，含一个非 ASCII 字节 → 1）验证它在新位置仍然工作。
- 对真实脚本跑过一次：`ps_fft_dual/stereo_both.tcl` 有 **1620 个非 ASCII 字节**（中文注释）。
  它今天能跑，但**违反本项目自己写的"脚本只用 ASCII"规则**，属待清理项。

**失效条件**
- 它是**文本检查，不是解析器**：花括号在字符串里的写法、Tcl 的 `{*}` 展开等极端情况可能误判。
- 括号规则只对 `.tcl` 生效（对 PowerShell / Python / C 里的 `#` 行尾注释是合法的，
  在那些文件上报警纯属噪声 —— 见脚本内的 SCOPE 注释）。

## 怎么把这些脚本用到别的题目上

1. **先跑 `run_selftests.py`**。6/6 通过，说明这套工具本身在这台机器上是好的；
   不通过就先修工具，不要拿它去判你的系统。
2. **接上你自己的数据源**：`null_floor.py` 只认 CSV（两列就够：值、类别），
   `wordmap_check.py` 认 `#define` / `k=v` / CSV，`leak_scan.py` 认你自己的针表。
3. **一次只改一个判据**。这五个脚本都是"给一个输入、给一个判决"的形状，
   不联网、不隐藏状态，适合放进 CI 或 pre-commit。
4. **它们不判断你的系统对不对**，只判断"你的判据有没有先把自己否掉"。
