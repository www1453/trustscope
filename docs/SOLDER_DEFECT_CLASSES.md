## 0. 边界（先读这一条，它决定了本文里每一个字的写法）

这台设备的成像链路**只能看到外观**。

- 它**没有**任何测量通断的手段：没有探针、没有测试点接入、没有电气回路，
  也没有把"通/断"变成像素的任何物理机制。
- 因此本目录里每一个类别名、每一条出现在板上、面板上、看板上的文案，
  都只能是「**疑似**桥连」「**疑似**虚焊」这种**外观判断**，
  **永远不能**写成「检测到开路」「测得短路」「实测通断」。
  这条规则在 `labels_zh.json` 里被写成机器可检查的约束：
  凡 `is_defect = true` 的类别，其 `panel_label_zh` 必须以「疑似」开头，
  且不得包含"开路/短路/通断/实测/测得/测量"这些词 —— 由校验器逐条断言。
- 这不是措辞洁癖。把"看起来像桥连"写成"测得短路"，
  等于让操作员在**没有任何测量**的情况下对一个电气结论负责；
  而本项目三态判定（合格 / 不合格 / **无法判定**）本来就是为这种不确定性准备的：
  说不出来的时候，输出「无法判定」是正确结果，不是失败。
- 类别名只描述外观。分类器的输出是「**这张图更像哪一类外观**」，
  **不是**「这个焊点是通的还是断的」。
- 反过来说：真值（ground truth）可以来自**人**的电气测量（例如人拿万用表量同一个焊点），
  那是**人的测量**被记录下来当作标签，**不是**本设备测到了通断。
  区分这两件事，是本目录 `basis` 字段存在的唯一理由。

## 2. 类别总表

10 个类别：7 个缺陷类、1 个合格类、1 个"形似非缺陷"类、1 个弃权类。

| 键 | id | 中文名 | 是缺陷？ | 它**提示**的电气后果（不是测量结果） | 上线时的面板文案 |
|---|---|---|---|---|---|
| `o` | `ok` | 合格（外观未见异常） | 否 | 无 | 未见异常 |
| `1` | `bridge` | 连锡（桥连） | **是** | 提示短路：两个本应独立的网络被焊料连通 | 疑似桥连 |
| `2` | `cold_joint` | 虚焊（冷焊） | **是** | 提示间歇性开路/高阻接触 | 疑似虚焊 |
| `3` | `insufficient_solder` | 少锡（焊料不足） | **是** | 提示强度不足、开路风险 | 疑似少锡 |
| `4` | `missing_part` | 缺件 | **是** | 提示该网络开路（或按设计是跳线时相反） | 疑似缺件 |
| `5` | `tombstone` | 立碑（元件立起） | **是** | 提示一端开路 | 疑似立碑 |
| `6` | `offset` | 偏移（贴装偏移） | **是** | 提示接触面积不足 → 开路/间歇，严重时短路 | 疑似偏移 |
| `7` | `bent_lead` | 引脚弯曲 | **是** | 提示引脚未落在焊盘上 → 开路；相邻引脚压到一起时短路 | 疑似引脚弯曲 |
| `8` | `lookalike` | 形似非缺陷（助焊剂残留/锡珠/氧化等） | 否 | 无。**专门用来装"看起来像缺陷、其实不是"的样本** | 疑似形似物 |
| `u` | `unsure` | 无法判定（标定者自己也不能确定） | 否 | 未知 | 无法判定 |

> **`ok` 与 `unsure` 必须分开。** 失焦、欠曝、过曝、遮挡、抖动、分辨率不足的图
> 都属于 `unsure`，不要为了"凑一个合格类"把它们塞进 `ok`。
> 本项目的三态设计的价值就在这里：**弃权是一个结论，不是一个失败**。

## 3. 逐类定义

每一类给四件事：**外观特征**（能不能看出来）、**电气后果**（它提示什么，不是测到了什么）、
**常见混淆**（最容易混进来的是什么）、**采集要点**（拍的时候要注意什么）。

### 3.1 `bridge` 连锡（桥连）

- **外观特征**：相邻两个焊盘/引脚之间出现一条**连续的焊料带**，把本该分开的两块金属连成一片；
  焊料表面通常比两侧焊点更光滑、高光连成一条；桥连常出现在引脚间距最小的位置（IC 引脚、排针、0402 之间）。
  在灰度图上的典型形态是**细长的亮连通域，跨越两个独立的高光中心**。
- **电气后果（提示）**：两个网络被短接 → 短路。可能的后果从"功能异常"到"上电即烧"，属于最危险的一类。
- **常见混淆**：
  1. **走线/铺铜**本身在图上横跨两个焊盘之间（这是设计，不是缺陷）→ 所以要**与已知好板比对**（本项目的 `pcb_check.py` 就是这条思路），单看一张图分不出来；
  2. **助焊剂拉丝**：半透明、颜色偏黄/棕、边缘不锐利，且通常**不反光**；真桥连是金属反光；
  3. **锡珠**搭在两点边缘但并未连通 → 这一档要谨慎，实在不行标 `unsure`；
  4. 相邻焊点的高光**在斜视角度下视觉重叠** → 顶视采集可以消除这一条。
- **采集要点**：必须顶视（斜视会让相邻焊点的高光重叠）；必须让两个焊盘**同时**在画面内，
  否则无法判断"连"还是"没连"；框画在**整条焊料带**上（两端各留 2~3 px）。
  被桥的两个网络之间的间距是判据的一部分，所以**记录板号与位号**比记录"感觉"重要。

### 3.2 `cold_joint` 虚焊（冷焊）

- **外观特征**：焊点表面**粗糙、发乌/发暗、呈颗粒或橘皮状**，没有好焊点那种镜面感；
  焊角（fillet）**不呈凹面**、边缘塌陷或呈球状；引脚与焊料之间可能有一条**深色缝隙**（缩孔/开裂）。
  高光**碎成多个小亮斑**而不是一个连续的大亮斑，这是灰度图上最可用的特征。
- **电气后果（提示）**：焊料与焊盘/引脚之间没有形成金属间结合 → 提示**间歇性开路或高阻接触**，
  振动与温度循环后会失效。这类缺陷的麻烦之处在于**出厂时可能是通的**。
- **常见混淆**（本类是最容易混的一类）：
  1. **深色助焊剂残留**：有清晰轮廓、位于焊点**外围**、颜色偏棕黄、表面不反光但有薄膜感；
     冷焊是**焊料本体**发暗粗糙。颜色线索（棕黄 vs 灰暗）是最好用的，但**灰度化会丢掉它**（见第 7 节 route B）；
  2. **焊盘氧化/发黑**：暗的是焊盘不是焊料；
  3. **阴影**：阴影有方向性，换个照明或稍微转一下板子就变，冷焊不会；
  4. **失焦**：整幅图都发软 → 标 `unsure`，不要标冷焊。
- **采集要点**：对焦必须准（这是本类唯一能自己控制的变量）；曝光不要过曝
  （过曝会把"粗糙"直接抹平成一个大白斑，等于把本类最重要的特征删掉）；
  单个焊点的焊料跨度目标 ≥ 128 px（这样 64×64 截取还有 2 倍余量，见 5.3）。

### 3.3 `insufficient_solder` 少锡（焊料不足）

- **外观特征**：焊料**填充量明显不足**，焊盘有大片裸露（金属色），没有形成完整焊角；
  引脚与焊盘之间呈"薄薄一层"或"缺一个角"；端头处可能露出元件本体。
- **电气后果（提示）**：机械强度不足 + 开路风险（热循环后开裂）。属于"现在也许能通、以后不一定"的一类。
- **常见混淆**：
  1. 本来就用**小焊盘**的元件（0201/0402）看起来"就没有多少焊料"→ 必须用同类元件的**好板对照**；
  2. **角度遮挡**：只看到焊料的一部分；
  3. 反光角度让焊料边缘看不见 → 环光比单方向光更能稳定复现焊角；
  4. 焊盘上的**丝印/阻焊**反光也可能被当成"裸露焊盘"。
- **采集要点**：同一个位号**同时**拍好板与坏板（这是唯一能把"本来就少"与"确实少"分开的办法）；
  框覆盖**整个焊盘**而不是只框露铜区，因为"少多少"只能相对于焊盘面积来算。

### 3.4 `missing_part` 缺件

- **外观特征**：焊盘上**完全没有元件**，两个焊盘都露着（可能还有已固化的焊料）；
  或者只有一侧有残留焊料。
- **电气后果（提示）**：该网络开路（若该位号按设计是短路跳线，则相反 —— 但这属于 BOM 信息，图上没有）。
- **常见混淆**：
  1. **DNP（本来就不贴）**的位号 → 这是设计，不是缺陷；必须**对着 BOM/位号图**标；
  2. **立碑的元件**：元件还在，只是立起来了 → 归 `tombstone`，不要归缺件；
  3. 元件被**遮挡**（旁边高的元件挡住、或者元件掉到画面外）→ `unsure`；
  4. 丝印框与实物位置对不上，让人以为"没件"。
- **采集要点**：必须能同时看到**两个焊盘与丝印框**；记录位号（丝印）；
  采集时要拍一张"位号可见"的对照图 —— 否则事后没人能证明这块板该贴什么。

### 3.5 `tombstone` 立碑（元件立起）

- **外观特征**：元件**一端翘起**、立起来，一端还搭在焊盘上；顶视下看到一个**竖立的矩形/端面**，
  常伴一道明显阴影；另一个焊盘通常空的或只有少量焊料。
- **电气后果（提示）**：翘起的那一端开路。
- **常见混淆**：
  1. 元件本身**侧向**被拍到（相机不是顶视）→ 这是采集问题；
  2. 高元件在顶视下的**投影与被遮挡部分**看起来像立起来；
  3. 反光把元件与背景糊在一起 → 调照明，别猜。
- **采集要点**：顶视；让**两个焊盘都在画面内**；曝光不要过曝（翘起一端的阴影是重要线索）。

### 3.6 `offset` 偏移（贴装偏移）

- **外观特征**：元件端头/引脚**只部分落在焊盘上**，超出焊盘边缘；
  一侧焊料多、另一侧几乎没有；严重时端头压在**阻焊**上而不是焊盘上。
- **电气后果（提示）**：接触面积不足 → 开路或间歇失效；偏移足够大时会碰到相邻焊盘 → 短路。
- **常见混淆**：
  1. **透视角度**造成的"看起来偏"→ 必须顶视；
  2. 丝印框与焊盘**本来就不对齐**的设计 → 以**焊盘**为基准判，不以丝印为基准；
  3. **整块板的定位偏差**：整个视场里的元件都往一个方向偏 → 先做配准（本项目已有相位相关配准），
     再判个体偏差；否则会把"没对好位"当成"每颗元件都偏了"。
- **采集要点**：**必须固定裁剪框位置**（相对于板/焊盘），不能"跟着元件裁剪" ——
  跟着元件裁，偏移这个信息就消失了（这条对 route B 尤其重要，见第 7 节）。

### 3.7 `bent_lead` 引脚弯曲（引脚变形）

- **外观特征**：引脚明显偏离焊盘/引脚孔，压到旁边或翘起；本体可能被顶起。
- **电气后果（提示）**：引脚未落在焊盘上 → 开路；相邻引脚被压到一起 → 短路。
- **常见混淆**：
  1. **插装件本来就弯的引脚**（有些工艺故意弯脚固定）→ 不是缺陷，需要工艺信息；
  2. 焊接后正常的弯脚；
  3. 投影与高光造成的"弯折感"。
- **采集要点**：顶视 + 侧向各拍一张（弯曲是三维形状，顶视可能看不出来）；
  侧视图要记录角度（否则不同角度的图不可比）。

### 3.8 `ok` 合格（外观未见异常）

- **外观特征**：焊角完整、呈凹面、表面光滑有金属光泽、高光连续；元件位置正、无偏移；
  焊料量适中；无桥连、无裸露大片焊盘。
- **采集要点**：**同类元件、同一光照、同一曝光**下的好焊点。`ok` 必须来自同一套采集条件，
  否则模型学到的是"光照差异"而不是"缺陷差异"。

### 3.9 `lookalike` 形似非缺陷

- **外观特征**：外观上非常像某个缺陷，但（经人核对）不是：
  助焊剂残留（像冷焊/像污染）、锡珠（像桥连）、焊盘氧化（像冷焊）、丝印反光（像露铜）、
  元件本体颜色（像烧焦）。
- **为什么要单独一类**：这些是最容易产生**误报**的东西。把它们标出来，
  才能测"误报率"这个数 —— 而误报率是产线真正在乎的两个数之一（另一个是漏报）。
- **采集要点**：`note` 里写清"像什么、为什么不是"（这是这类样本唯一的附加价值）。

### 3.10 `unsure` 无法判定

- **外观特征**：不适用 —— 这一类**不是一种外观**，而是一个**结论**：
  "这张图不足以支撑任何判断"。
- **典型来源**：失焦、欠曝/过曝、剪切（饱和门限触发）、遮挡、运动模糊、
  焊点被画面边缘截断、分辨率不足（焊点跨度 < 64 px）、以及**标注者之间意见不一致**的图。
- **采集要点**：不要试图把这类图"救回来"当成缺陷样本。它是**校准数据质量的标尺**：
  如果 `unsure` 占比很高，问题在采集，不在模型。

## 5. 采集规范

### 5.1 拍什么

- **工件**：同一批次的印刷电路板（裸板或被贴装的板）。宁可**少量多类**，不要"一块好板拍 300 张"。
- **对象**：**一个焊点 / 一组相邻焊点**（元件一个端头、一颗 IC 的两个相邻引脚）。
  每张图要有明确的**主体**，并记录**位号**（丝印）。
- **同一缺陷不同视角**：桥连/少锡/冷焊至少各拍 1 张顶视；
  引脚弯曲/立碑**另加 1 张侧视**（弯曲与立起是三维形状）。
- **"坏件"从哪来**：优先用**真实的坏板**（返修件、报废件）。
  拿烙铁自己造的桥连/少锡**可以用，但必须单独统计**：自造缺陷的形态分布与产线缺陷不同，
  把它混进训练集会让"检出率"这个数失去意义。自造缺陷必须在 `basis` 里写明方式
  （例如 `self-made bridge with soldering iron, flux type recorded`）。
- **对照图**：每一个"坏焊点"都要拍一张**同一位号的已知好焊点**（同批、同光照、同曝光）。
  没有对照，`少锡` 与 `本来焊盘就小` 在原理上分不开。

### 5.2 每类要多少

分两档，**不要把两档混起来说**：

| 档位 | 规模 | 用途 | 允许下的结论 |
|---|---|---|---|
| **P0 成像可行性** | 每个缺陷类 **5~10 个不同焊点**（不是同一焊点拍 10 次） | 验证"这个类在图上到底有没有可测差异"、验证工具链 | 只能说"特征量上有可测差异"，**不能说检出率** |
| **P1 首个可训练集** | 缺陷类各 **≥ 100 个不同焊点实例**、`ok` **≥ 300**、`lookalike` 每个子类 **≥ 30**、`unsure` 不限（但占比要报） | 训练 + 验证 + 测试 | 可以报每一类的检出率/误报率，**必须带每类样本数** |

P1 的附加要求（不是可选项）：

- **来源多样性**：每一类至少来自 **3 块不同的板**、**2 种不同朝向**（或 2 种不同光照配置）。
  只来自一块板的 100 张图，训练出来的模型学到的是**那块板**。
- **切分按"板"与"时间"，不随机切**。同一块板的相邻焊点在图像上高度相关，
  随机切分会让训练集与测试集"见过彼此"，把检出率抬成假的高。
- **本项目已有的实验纪律**（`agent-experiment-discipline` 里那条
  **"前瞻留一只用更早的数据"**）：任何"这个模型在**以后**也能用"的说法，
  只能用**时间上更早采集**的数据来做留出验证，不能用随机切分去支撑一个面向未来的结论。
  因此本目录的切分单位是**采集批次**，不是随机行号。
- **`unsure` 与 `lookalike` 不进"缺陷检出率"的分母**，但**必须单独报**：
  弃权率和误报率被藏起来的那一刻，这份数据就不能用了。

### 5.3 光照 / 角度 / 对焦 / 曝光（与本机现状一致）

本机现状（来自项目记录）：相机 AN5642，采集 1280×720；零件**平放在台面上**；
面板 800×480；当前是**环形光 ×1**、固定手动曝光（`0x18000`），不是自动曝光。

| 项 | 要求 | 理由 |
|---|---|---|
| 视场 | 相机光轴尽量**垂直于板面**（顶视），同一条数据里允许 ±10° | 斜视会让相邻焊点的高光重叠 → 桥连误判；也会让"偏移"变成透视假象 |
| 焊点尺度 | 目标：单个焊点的焊盘/引脚跨度 **≥ 128 px**；**下限 64 px** | route B 的输入是 64×64；≥128 px 时 64×64 截取还有 2 倍余量 |
| 对焦 | 用项目已有的 **focus sweep** 流程取最清晰帧；判据用**图像梯度能量最大**，不要用肉眼"看着挺清楚" | 肉眼在屏幕上判断失焦的能力很差，冷焊与失焦会混 |
| 曝光 | **固定手动曝光**，整批不变；先跑一次曝光扫描确定不剪切的工作点 | 过曝会把焊料的粗糙表面抹平成一个大白斑，等于删掉冷焊的主特征 |
| 剪切 | 任一通道饱和比例超过本项目已有的饱和门限时，该帧**不进正样本**，标 `unsure` | 剪切像素上没有信息；本项目已有 `MB_CLIP_*` 这一整套门限 |
| 光照 | 环形光做基准；若要做第二配置，另起一个 `view` 编号并**单独统计** | 单方向光对弱缺陷有朝向依赖（项目已实测），混着采集会让模型学到光照而不是缺陷 |
| 背景 | 台面保持干净、无强反光物；不要有会移动的杂物 | 背景反光会被当成亮斑 |

每张图（或每个采集批次）必须记录的量：**分辨率、曝光值、光照配置、镜头到板的距离、
相机角度、板号、批次**。这些量决定模型能不能迁移到另一套条件；
不记录，日后就说不清"这个 0.9 的准确率是在什么条件下测的"。

### 5.4 命名与目录

- 目录：图像统一放在 `submission/data/solder_defects/images/`。
  **图像必须放在 manifest 的同级目录之下** —— manifest 里的 `rel_path` 是相对路径，
  校验器会拒绝绝对路径与 `..`（绝对路径会把个人账户名带进仓库，这是本项目的硬红线）。
- 命名：全 ASCII 小写，用下划线分隔，例如
  `b03_u12_pin7_top_01.png`（板号_位号_视角_序号）。
  **不要**在文件名、目录名、`note`、`labeler` 里写任何可识别个人的信息。
- 多缺陷同图：当前 schema 规定**一张图一行**（`rel_path` 唯一，重复即报错）。
  如果一张图里有多个缺陷，请**裁剪成多张图**（每张一个主体），并在 `note` 里说明它来自同一张原图。
- 原始帧是 1280×720 的彩色帧，建议**连同裁剪图一起保留原图**（原图不在 manifest 里，
  但事后重新标框时要用它）。

### 5.5 防止"采样假象"的三条

1. **不要连续拍同一个焊点**：同一焊点拍 20 张会被当成 20 个样本，把一类的有效样本数虚增 20 倍。
2. **不要把好板拍很多、坏件拍很少**：类别不平衡本身不是错，但必须**在报告里给出每类的样本数**。
3. **不要先看模型结果再回去补样本**：那是用测试集调参。采集计划与判据先写下来，再采。

## 6. 真值（ground truth）怎么记录

manifest 的每一行都必须回答两个问题：**谁决定的**（`labeler`）、**依据什么**（`basis`）。
两者都是必填，`dl/label_defects.py` **拒绝**在缺失时开工，也**不会**替你编一个。

| 字段 | 写什么 | 不写什么 |
|---|---|---|
| `labeler` | 一个**可追溯的代号**，例如 `OP-A`、`REV-2`、`L1` | 真实姓名、工号、任何单位或集体的编号 |
| `basis` | **判据的类型 + 具体做法**（见下表） | 空、`n/a`、"看着像" |
| `note` | 这张图上**看到了什么**、为什么拿不准、与哪个位号/板号对照 | 任何可识别个人的信息 |

允许的 `basis` 写法（能写具体就不要写笼统）：

| `basis` | 含义 | 强度 |
|---|---|---|
| `multimeter continuity on the same joint` | 人用万用表在同一个焊点上量通断 | **最强**。注意：这是**人的测量**，不是本设备的测量能力；标签的可信度高于设备的可测性，两者不要混为一谈 |
| `known-good board comparison` | 与同批已知好板的同一位号对照 | 强（能分开"本来就少锡"与"确实少锡"） |
| `rework record / repair log` | 这块板的返修记录 | 强（有独立的书面依据） |
| `IPC-A-610 visual criterion, no electrical check` | 只按外观判据判 | 中（**必须写明没有电气核对**） |
| `self-made defect with soldering iron, mechanism recorded` | 自造缺陷 | 中（形态与产线缺陷不同分布，必须单独统计） |
| `visual inspection by second reviewer` | 第二人复核后的结论 | 中 |

其它规则：

1. **不确定就标 `unsure`。** 标错一个 `ok`/缺陷，比多一条 `unsure` 的代价大得多。
2. **盲标与复标**：至少 **10%** 的图由**第二个人盲标**（看不到第一个人的标签），
   记录**不一致率**。复标结果写到**另一份 manifest**（`dl/label_defects.py --manifest` 指向另一个文件），
   这样同一张图不会在同一个 manifest 里出现两次（重复行是校验错误）。
   **不一致率 > 10% 时，问题在类别定义，不在数据** —— 回到第 3 节重写定义。
3. **标注者不能只看到自己标的那一类。** 只盯着桥连找桥连，会把走线也标成桥连。
4. **原始标签不可覆盖式修改**：`dl/label_defects.py` 会替换同一张图的旧行；
   所以每次改动前请保留一份 manifest 副本（`dl/backup.py save` 可复用）。
5. **设备的结论与标签的关系**：标签是"人怎么判"，设备的输出是"外观像什么"。
   两者不一致时，**先怀疑设备的判据，再怀疑标签**；但如果标签本身来自万用表，
   那么不一致恰恰是**最有价值的样本**（外观像、电气却不是）—— 这类样本要单独统计。

## 7. 两条实现路线与它们的代价

> 详细工程计划见 `detection_plan.md`（同一目录）。这里给出对比与**诚实的强弱判断**。

### 7.1 route A：不用 CNN，在现有链路上手工做特征

现有链路已经有的东西：每帧的**面积 × 对比度分数**、**饱和门限**（`MB_CLIP_*`）、
**饱和包围盒**（`MB_BB_*`）、逐相位计时、以及主机侧的**参考图比对**（`pcb_check.py`）。
route A 就是在这上面加统计量：

| 特征 | 对应类别 | 怎么算 |
|---|---|---|
| 亮连通域的数量/面积/**长宽比** | `bridge` | 细长亮带跨越两个高光中心 |
| **镜面高光的形状与碎裂程度** | `cold_joint` | 好焊点是一个连续大高光；冷焊碎成多个小亮斑、总面积下降 |
| 焊料区域面积 / 焊盘面积 | `insufficient_solder` | 焊盘区域由参考图给出，露铜比例上升 |
| 与**已知好板参考图**的差分面积 | `missing_part`/`offset` | 项目已有配准 + 差分 + 连通域的比对式检测 |
| 高光中心相对焊盘中心的位置 | `offset` | 需要先配准，再算偏移向量 |

- **代价（低）**：不需要新硬件、不需要动 FPGA、不需要 CNN（这一点很重要：
  **CNN 通路目前不通** —— 控制寄存器写不进去是另一个未解决的问题）。
  可以完整复用现成的三态判定与看板。
- **诚实的弱点**：**没有标签，这些阈值全是猜的。**
  本项目自己的纪律是"阈值必须来自零分布（噪声地板），不能拍脑袋"。
  所以在 P0 之前，route A 只能给出"这个特征量在该类上动了吗"这样的**定性**结论，
  **不能**给出任何检出率。任何"route A 能检出 X%"的说法，在标签集出现之前都不成立。
- **原理性风险**：桥连与**走线**、冷焊与**助焊剂残留**，在单一灰度特征上**可能原理上就不可分** ——
  项目已有实测结论：单光源下"划了"与"脏了"区分不了，那是形状与反照率混在一起的结果。
  焊点这边同构：**该说"分不开"的时候要说分不开**，不要用调参把误报压下去换一个好看的数。
- **route A 真正该做的第一件事**：用 P0（每类 5~10 张）去量**特征量的可分性**
  （类间差 / 噪声地板），把结论写成"可分 / 不可分 / 需要更多光照"。这一步便宜且有用。

### 7.2 route B：用现有 CNN 加速器

硬件约束（已固定，不是我们能选的）：**输入 64×64 uint8（单通道），输出两个 int32 logits**。

- **数据需求**：第 5.2 节的 P1；切分按**板/时间**，遵守
  **"前瞻留一只用更早的数据"**；每类的样本数必须与结果一起报。
- **输出维度是硬约束**：两个 logit 只够**二分类**。要覆盖 10 个类别，只有三条路：
  (a) 用**任务级联**（先"缺陷/正常"，再在缺陷内做"桥连 vs 其它"……每级一次推理）；
  (b) 做 **one-vs-rest**，10 次推理取最大分；
  (c) 改 HLS 增加输出维度 → **要重综合**，代价高且有翻车风险（本项目在 BD 上付过代价）。
- **时间预算**：记录里 150 MHz 下单次推理 4.813 ms；实际 `FCLK_CLK0` 设计值 50 MHz
  （实测寄存器还曾低到 16.67 MHz，见交接文件第十九节）→ 单次约 14.4 ms 量级。
  one-vs-rest 10 次 ≈ **144 ms/件**，仍在 200 ms 预算内但**很紧，必须实测**，不能照抄 150 MHz 的数。
- **灰度会丢掉颜色**：冷焊与**深色助焊剂残留**主要靠**颜色**区分，而 64×64 uint8 是单通道。
  所以必须：**固定一个灰度公式**（例如 BT.601 亮度），标注时记录的裁剪框坐标与推理时用的
  裁剪框、灰度公式**完全一致**；否则训练输入与推理输入不是同一个分布 —— 这是最容易发生、
  也最难发现的失败模式。
- **定位信息会被裁掉**：`offset`、`missing_part` 依赖**元件相对焊盘的位置**。
  如果裁剪框"跟着元件走"，偏移这个信息在裁剪那一刻就消失了。
  这类类别要求**裁剪框相对于焊盘/板固定**，也就要求先做**配准**（项目已有相位相关配准）。
- **现状**：`ps_ui/main.c` 里**已经有**"每帧尝试推理、把 logits/类别/周期写进邮箱"的代码，
  但**加速器本身不工作** —— `cnn_drv.c` 的控制寄存器**写不进去**（另一个未解决的问题）。
  也就是说：代码在，通路不通，**连一次成功的推理都还没有发生过**。
  route B 因此现在不具备可用性。**本目录的类别与数据布局刻意与它解耦**：
  数据先采、标签先标，等通路修好后直接喂进去，不需要重标。
- **面板与看板该显示什么**：`疑似桥连 0.83`（类别 + 分类器分数），
  **绝不出现**"检测到开路/短路"。分数是**分类器分数**，不是电气量，单位与含义都不要暗示成电学量。
  看板上新增字段的建议（**尚未实现**，只是计划）：
  - `classifier.defect_label_zh`（如"疑似桥连"）、`classifier.defect_score_pm`（×1000 的整数）、
    `classifier.defect_model_version`、`classifier.defect_note`；
  - **陈旧时这些字段必须是 `null` 并显示"不可用"，不能退化成"合格"** ——
    看板现在已经这么处理其它字段（`stale` 时数值一律为 `null` 而不是 0），保持同一套规则；
  - 板载面板 / 邮箱：**邮箱里已经有 CNN 的遥测字**，但它的形状承载不了本目录的类别表：
    `MB_CNN_L0`(127) / `MB_CNN_L1`(128) 是最近一次推理的两个 logit，
    `MB_CNN_CLS`(129) 是"哪个 logit 大"（**0 或 1，即只支持二分类**），
    另有 `MB_CNN_RUNS`(126) / `MB_CNN_CYC`(130) / `MB_CNN_OK`(124) / `MB_CNN_PASS`(125)。
    → **要显示 10 类，必须新增邮箱字**（例如从 word 131 起放"类别号"与"分数×1000"，
    新增前先逐个核对地址没有被别的消费者占用），或者把 10 类压成**任务级联**（每级一次二分类）。
  - **这些字现在读出来不是结论**：`cnn_drv.c` 的控制寄存器写不进去（另一个未解决的问题），
    所以 `MB_CNN_OK` 不为 1 时 `MB_CNN_CLS` 只是默认值。
    看板与面板遇到这种情况必须显示「**不可用**」，
    **绝不能把"没有数据"显示成"合格"** —— 这与看板既有的 `stale` 规则是同一条：
    "读不到"和"读到 0"必须分开。
  - 面板字体：`main.c` 现有的 5×7 字库**没有 W 和 Z**，中文要走路 `dl/ts_cn_font.h` 的中文字库；
    面板 800×480，一行文案要短。

### 7.3 对比

| | route A（手工特征） | route B（CNN） |
|---|---|---|
| 需要新硬件 | 不需要 | 不需要（加速器已在设计里） |
| 需要重综合 | 不需要 | **可能需要**（若选 (c) 扩输出维度） |
| 依赖当前不通的 CNN 通路 | **不依赖** | **依赖**（现在不通） |
| 起步所需数据 | P0：每类 5~10 张 | P1：缺陷类各 ≥100、`ok` ≥300 |
| 能给的结论 | 定性"可分/不可分" | 每类检出率/误报率（须带样本数） |
| 可解释性 | 高（每个量对应一条物理直觉） | 低（需要额外做归因） |
| 主要风险 | **阈值无依据**、原理上不可分 | 灰度丢颜色、裁剪丢位置、通路不通 |
| 建议顺序 | **先做**（便宜、能立刻判"值不值得做 route B"） | 通路修好、且 P0 证明可分之后再做 |

**一句话：先用手工特征和 P0 数据回答"外观到底分不分得开"；
分不开就不要用 CNN 去硬分 —— 那只会得到一个在测试集上好看的假象。**

```powershell
# 1) 看数据现状：真实 manifest（当前 0 行）
python dl\check_defect_data.py

# 2) 看格式示例（3 行占位，明确不是样本）
python dl\check_defect_data.py submission\data\solder_defects\manifest_example.json

python dl\check_defect_data.py --for-training

python dl\label_defects.py --images submission\data\solder_defects\images `
    --labeler "OP-A" --basis "known-good board comparison"
```
