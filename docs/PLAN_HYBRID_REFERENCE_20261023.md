# 参考帧策略：批次基线 + 每件就绪（规划）2026-10-23

> 现状：差分检测用**一张**参考帧，`MB_CMD=9` 重取；打光一漂就 `MB_DIFF_OK=2` 永久拒绝，
> 于是带 `MB_DIFF_ARM` 的系统一直报"无法判定"（实测 25 秒窗口内 0 次比对）。
> 纯粹的"每批一次"会被光照漂移打死，"每件一次"又退化成变化监测。
> 本文是把两者结合的设计，**未实现**。

---

## 一、先分清两种参考回答的是不同问题

| 参考 | 回答的问题 | 用途 |
|---|---|---|
| **批次基线**（存的、跟良品比） | "这件和标准件不一样吗" | **符合性判定**（这才是质检） |
| **每件就绪**（不存的、相邻帧自比） | "这一件现在静止了吗，可以判了吗" | **判定前提**（不是判定本身） |

**关键点：每件那一路不需要存第二张参考图。** 它比的是"这一帧和上一帧"，只用来判断
工件是否已就位、曝光是否已稳定。所以两者占用的资源不冲突。

---

## 二、设计：三层

### 第 1 层 · 就绪门（每件，无存储）

- 工件放上后，用**相邻帧时间差分**（复用现有网格，`DIFF_THRESH 14`、`DIFF_NEIGH 3/3`）
  算"画面还在动多少"。
- 连续 K 帧低于就绪阈值 → 认为工件已就位、可判。
- 超时（例如 3 s 仍不稳）→ 判"无法判定"，并在面板提示"请放稳工件"。
- **同时吸收 AEC 调整期**：`MB_AEC_STATE != 1` 期间本来就不该判。

### 第 2 层 · 符合性判定（每批，存储基线）

- 就绪后，把稳定帧与**批次基线**比对，`cells > MB_DIFF_LIM` → NG。
- 复用代码里已有的两件东西：
  - `MB_DIFF_DX/DY`（201/202）：**平移搜索**，吸收工件位置的小幅偏差；
  - `MB_DIFF_SCALE`（200，256 = 1.0）：**增益补偿**，吸收整体亮度漂移。
- **补偿优先于拒绝**：先按 scale 补偿再比；只有当所需补偿超出界限（说明真的换灯了）
  才拒绝，并且拒绝时**明确提示"需要重取基线"**，而不是永远沉默地报"无法判定"。

### 第 3 层 · 基线生命周期

- 基线由**操作员显式重取**：触摸屏一个"取参考"按钮 → 走已有的 `MB_CMD=9` 通道。
- 取基线时**记录**：时间、当时曝光/增益、操作员动作（谁在什么时候换的基线）。
- 连续 N 件都因"补偿超界"被拒 → 面板提示"光照已变，请重取基线"，并置一个邮箱标志。
- **不做**"固件偷偷自动重取"：那会让基线跟着灯光漂，缓慢变化就再也检不出来。

## 三、状态机（每个工件一个周期）

```
IDLE ──工件放入──> SETTLING ──连续K帧稳定──> JUDGE ──> PASS / NG  ──工件取走──> IDLE
                     │                                       │
                     └─超时──> CANNOT JUDGE                  └─结果+补偿量+基线id 一起记录
```

|---|---|---|

| 229 | `MB_GOLD_EXP` | 取基线时的曝光（供事后核对） |

## 五、分阶段实施与工作量

| 阶段 | 内容 | 估计 | 验收判据 |
|---|---|---|---|
| **P1** | 就绪门（相邻帧差分）+ `MB_READY/SETTLE_MS` | ~1.5 h | 放上工件后 1 s 内 `MB_READY=1`；晃动时保持 0 |
| **P2** | 触摸屏"取参考"按钮 + 基线元数据记录 | ~1 h | 按一下 `MB_DIFF_REFEXP` 更新，`MB_GOLD_EXP` 同步 |
| **P3** | 补偿优先（用 `g_diff_scale`）+ 超界才拒绝 + `MB_REBASE_REQ` | ~1.5 h | 缓慢调暗灯光：仍能比对（`ok=1`）且不误判 NG；开大灯：给出"请重取基线" |
| **P4** | 主机侧记录循环（总数/合格率/每件明细）+ 填 `TSC1` | ~1.5 h | 面板"总数/合格率/帧率"不再恒为 0 |
| **P5** | 已知好 + 已知坏对照验证 | ~1 h | 良品 PASS、缺陷品 NG，各 10 次，`RESULT` 稳定不抖 |

**合计约 6.5 小时**（不含意外）。**这是"真实质检"这套说辞能不能成立的最小闭环。**

## 六、风险与前置条件

1. **必须先确认 `MB_DIFF_SCALE` 到底有没有参与比对**：今天只看到它在发布，没读实现。
   如果它只是诊断量，那"补偿优先"这一层等于要新写。
2. **工件位置重复性**：如果每件放的姿态差异大于平移搜索范围，批次基线仍会大面积误判。
   这属于工装问题，不是软件能完全吸收的。
3. **判定时间预算**：当前 15 fps、单次比对若干毫秒；加了就绪门后每个周期会多花 0.5–1 s，
   节拍要事先算进去。
4. **不能解决的**：光照缓慢漂移本身与"工件变暗"在单帧里不可区分。这是差分法的固有
   局限，必须靠"固定光源 + 定期重取基线"的制度来兜，报告里要写明。

---

## 七、与交付物的关系

这套东西 **P1–P5 全部做完也只是一个"能演示的单工位质检"**，而交付物（报告/视频/
GitHub/RAR）一项都还没做。若时间只够一头，建议：
- **P1 + P2 + P5**（约 3.5 h）做出"能judge、能重取、有对照"的最小可信闭环；
- P3/P4 写进报告的"后续工作"，并说明为什么（补偿与统计属于产线化，不属于作品演示）。
