# skill/ — 可复用技能包

> 本目录是参赛作品的一部分，对应竞赛指南的「技能包（Skill）」一项。
> **它面向的不是本项目的题目，而是"下一个题目"** —— 包括一支完全陌生的队伍。

## 指南原文（本目录按它逐条对齐）

> **3.3.3.1**：「允许使用任意公开大模型……**须提交体现大模型协作过程的交互记录，
> 含提示词、模型回答与自我纠错轨迹**」；「须将协作过程中沉淀的可复用经验提炼为
> **技能包（Skill）**，随作品一并提交」。

> **3.3.5.2 技能包**：「置于 `skill/` 目录，含 README.md 说明每一项的适用范围、
> 使用方法与失效条件」。内容可为 **提示词工作流 / 案例模板 / 校验脚本 / 踩坑清单**
> 之一或其组合。「**评价标准是可复用性：一支陌生队伍拿到该目录，能否直接用在
> 自己的题目上。**每一项须写明适用场景、使用方法与已验证的效果，
> 并说明是从哪些失败或观察中总结得出。」

> **3.3.5.3 设计报告**须含「大模型协作记录：提示词、模型回答、自我纠错轨迹、
> 智能体工作流设计（如有）」与「**技能包的提炼过程**：从哪些失败或观察中总结、
> 如何验证有效、边界如何确定」。

> **3.3.5.4 推荐目录结构**：`README.md src/ sim/ build/ board/ data/ skill/ report/`，
> 「**仓库内所有目录名与文件名须使用纯英文（小写字母、数字、下划线或连字符），
> 不得出现中文、空格或特殊字符**」—— 中文只出现在**文件内容**里。

> 关于"大模型协作过程"的完整叙事（提示词、模型回答、自我纠错轨迹）**不在本目录**：

## 一、这个包解决什么问题（以及它不解决什么）

**它解决的问题只有一个：**

> **看起来做完了，其实没生效。**

四类具体形态，全部来自本队的真实经历，不是从网上整理的：

| 形态 | 一句话 | 在哪 |
|---|---|---|
| **判据自己不可信** | 闸门读了一个它没读的字；统计量的零假设比信号还大 | `pitfalls/` D6 / M53 |
| **测量被骗** | 抓到的是残留、读到的是别人的值、同一个文件读了两遍 | `pitfalls/` M1 / M45 / M46 |
| **工具链说"成功"** | 构建链接过期缓存、脚本打印 done 但没改、Tcl 被中文吃掉引号 | `pitfalls/` T6 / B1 / T5 |
| **并行工作互相踩** | 两个 agent 改同一个文件、两个调试会话插同一根线 | `pitfalls/` T48 |

**它不解决：**

- **算法与架构的正确性**（那是你自己的题目）；
- **Xilinx 工具的使用方法**（官方文档与 UG 系列比任何二手总结都准）；
- **你的板子会不会烧**（那是电气与安全规范，本包只有"上电前先做什么"的形状）。

**为什么值得单独做一个包**：上面四类失败里，**没有一条是"不会用工具"**。
卡住的全部是"**信了一份不该信的证据**"，或者"**判据本身没有先被检验**"。
这类经验换一个题目、换一块板子仍然成立 —— 这正是它可复用的原因。

## 四、一个陌生队伍怎么用（15 分钟路径）

1. **0–3 分钟**：读本文第二节的速查表，找你现在最像的那个处境。
2. **3–10 分钟**：读对应的 `pitfalls/` 条目。**只读那一条** —— 索引就是为反查设计的，
   通读 146 条是第二天的事。
3. **10–15 分钟**：跑一次脚本的自测，确认这套工具在你的机器上是好的：
   ```bash
   python skill/scripts/run_selftests.py      # 期望 6/6 passed
   ```
   然后把它接到**你自己的**数据上（CSV / `#define` 地图 / 你的针表）。
4. **之后**：把 `templates/` 里对应的骨架复制进你的 `report/`，逐格填。
   **填不出来的格子就是还没做的事。**

> **不要一次全上。** 这个包的价值在于"遇到症状时能查到"，不在于"读完了"。
> 一次只引入一件，并且**先让它在你手上失败一次**（`--selftest` 就是干这个的）。

**这批素材的共同点**：没有一条是"不会用工具"。四条是"信了一份不该信的证据"，
一条是"连证据的来源都被别人同时改着"。所以整个包的形状是**判据的判据**，
而不是工具手册。

### 5.2 如何验证有效

| 验证方式 | 具体做了什么 | 结果 |
|---|---|---|
| **在坏输入上失败** | 每个脚本的 `--selftest` 都喂一个**故意错**的输入（缺字段、null 高于信号、两个名字同地址、索引指向不存在条目、GBK 编码的针） | 6/6 通过：即"该失败的都失败了" |
| **在真实输入上不误报** | `readset_lint` 跑本项目的两台验收工具；`wordmap_check` 跑 414 个 `MB_*` 定义；`casebook_index` 跑真实案例集 | 依次为 0 findings / 0 findings / 146 条 52 索引，与原来的专用脚本数字一致 |
| **复现历史上的失败** | `null_floor.py` 用本项目的真实 null（141–150 vs 3–7）当夹具 | 判 FAIL，正是当时该发生而没发生的那句话 |
| **修过一版假警** | `readset_lint` 第一版把普通 dict 的 `.get("ok")` 也当成字段读取，在正确代码上报 8 条假警；`wordmap_check` 第一版不圈命名空间，在固件头上报 68 条噪声 | 两处都收窄了作用域，并**把这件事写进脚本注释** —— "会喊狼的检查器会被关掉"，这是案例 D2 的教训 |
| **人在真实流程里用过** | `PRE_BURN_CHECKLIST.md` 来自同一天两次事故之后的实际执行；`claim_ledger.md` 的撤回格式被用于两次真实撤回 | 沿用至今；两次撤回的记录都保留在提交树里 |

### 5.3 边界如何确定

边界不是猜的，是**每次失败之后问一句"这条经验在什么情况下不成立"**问出来的。
三条判据：

1. **能写出反例 ⇒ 写"失效条件"**。写不出来 ⇒ 这条经验还没被真正理解，先别收录。
   例：`tcl_lint.py` 的括号规则只对 `.tcl` 成立，对 PowerShell / Python / C 是噪声 ——
   写错了那三种文件会被它误报，所以规则按文件类型分派。
2. **验证只在一个器件/版本上做过 ⇒ 明确写出来**。
   例：`zynq-cache-dma-traps.md` 的 PYNQ 段落是**按机制推导**、未在 PYNQ 上实测，
   文件头就这么写。宁可显得薄，也不要把推导写成实测。
3. **它是"代理指标"而不是"目标指标" ⇒ 标出等级**。
   例：索引覆盖率 36.1% 只能说明"入口触达范围"，不能说明索引质量；
   脚本自测通过只能说明"检查器是好的"，不能说明"被检查的系统是好的"。
   **每份 README 都有一句"看到 `TRUSTWORTHY` 才允许把那个探针的结果写进结论"** ——
   这就是等级意识在文字上的样子。

## 六、诚实的边界（这一节本身也是可复用资产的一部分）

- **本包不覆盖设计正确性。** 它只覆盖"工程操作与证据纪律"。
- **绝大多数条目来自 Xilinx 7 系列 + Vivado/Vitis 2023.1 + 裸机**。
  换到 UltraScale+/Versal/PetaLinux 上症状会变，但**排查思路与纪律不变**。
- **`pitfalls/` 的索引只覆盖 36.1%**，这是刻意的：它是**高频与高代价条目的入口**，
  不是全量索引。未列出的按各文件的 `## ` 标题查（`scripts/casebook_index.py` 会告诉你
  还有哪些没被索引）。
- **提示词部分的效果依赖模型能力与"能否读到工程文件"**。同一段提示词在不同模型上
  差别很大，所以每篇都写了"怎么判断它给的答案是编的"。
- **`zynq-cache-dma-traps.md` 里的 PYNQ 段落未实测**，按机制推导。
  这是本包唯一一处"推导而非实测"的内容，位置与理由都写在文件头。
- **本目录的一切"已验证"都指在本项目的环境里验证过**，不是通用承诺。
  换环境请先跑 `scripts/run_selftests.py`。
