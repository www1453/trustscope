# 2026-10-31 — cam1 掩膜只有 8 行的真因：ROI 带把板体上半切掉了（不是亮度）

> 交接第 1 条的前提是"cam1 暗 → 掩膜死"。今天实测否证了它：
> **同一批残差、只改一个宿主字（`MB_CAM1_ROI`），cam1 的掩膜从 110 格/7 行变成 580 格/21 行。**
> 板体在 cam1 里落在格行 37..57，而 ROI 带从行 50 开始——带切掉的是板体的上半 13 行。
> 站台上验证：关带并重取参考后 **cam1 pts 134 → 728、判格 80 → 716、行段 36..62（27 行）、
> `cam1_medge` 37 → 0**。

## 1. 机制（代码）

`cam1_roi_zero()`（`ps_ui/main.c:6250`）在阈值与腐蚀**之前**把带外的格清零；带由
`MB_CAM1_ROI`（字 614）给出，上电默认 `0x00590032` = 格行 50..89 = 源像素行 400..719，
宿主编程 `0xFFFFFFFF` = 无带（整帧，即改动前的规则）。cam0 没有带，忽略该字。

被判格数由**参考的**掩膜决定（`ref_part_ok()`，`main.c:10728` 只认 `BASE_MASK`），
所以关带之后必须重取参考，否则旧参考仍然是带内的 110 格——这一步今天实测过：
关带后、重取参考前，`fvalid` 只从 80 涨到 92；重取参考后到 716。

## 2. 证据（同一批字节，只改一个数）

用 `python dl\maskfloor_20261031.py` 从 dump 的 `LATT1_BASE` + `BG_GRID1` 重算
`|latt*scale/256 − bg|`（scale 用固件自己的中位数比，实测 256/260），再按固件的
阈值 24 + 3×3 腐蚀 + 聚类规则复算：

| cam1 掩膜 | raw | 聚类后 | 行范围 | 列范围 |
|---|---|---|---|---|
| 带 50..89（默认） | 129 | **110** | 51..57（7 行） | 65..118 |
| 无带 | 580 | **580** | **37..57（21 行）** | 65..118 |

第一行**复现了固件发布的掩膜**（`cam1_pts` 100–130、bbox 行 51..58），所以这个重算通道
是被已知答案校验过的；第二行是同一批残差上唯一变动的结果。

站台实测（g0 在位，同一曝光 8662）：

```
关带前: cam1 pts=134 ref=116 fvalid=80  行段 51..58  medge=37   ← medge>0 = 固件自己说"掩膜撞在带边界上"
关带后(未重取参考): pts=747 fvalid=92
重取参考后: cam1 pts=728 ref=745 fvalid=716 行段 36..62(27 行) medge=0
```

`cam1_medge` 就是为这个问题造的：掩膜落在带边界上的格数，>0 是截断的直接证据。

## 3. 这条改动为什么比"改门限"安全

- **不重构建、不重烧**：写一个字，再写回旧值就是回滚（脚本会打印旧值）。
- **不动任何已发表的数**：cam1 的掩膜不参与判决（`verdict_decision()` 只读 cam0），
  所以报告里的 1/41、19/35 与它无关。"把 `BG_MASK_THR` 改成相对门"则会让 cam0 的规则一起变，
  那批数就要重扫——这是两条路的根本差别。
- **不持久（必须写清楚）**：带值是固件每次启动写进邮箱的默认（`main.c:16492`），
  重载就回到 50..89。要永久生效得改源码默认值再重构建；今天没有为此单独冒险重载。

## 4. 空带安全性（改动的另一侧）

`dl/maskbuff_20261031/empty`（空皮带、带放松门采）上按行带统计残差、并按固件同一套
阈值+腐蚀+聚类复算：

```
floor | raw(eroded) | clustered pts
   24 |           0 |             0
   16 |           0 |             0
    8 |           0 |             0
```

空带残差在 8 像素格距上是**空间不相关**的，3×3 全部过门的腐蚀把它全清掉，
所以在 24 及以下任何候选门限上，空带都读 0 个格。也就是说：**这条带对今天的空带安全
没有必要**——它当初大概是为一摆位/一段光照设的。这一条只证明了"今天这个场景、这个光照"，
不是永久保证；带值是会话量，不是常数。

## 6. 撤回与更正

- **交接第 1 条"提亮 cam1"**：预注册预测 k=3 时 clip 0..15‰，实测 **115–118‰**（门限 10‰），
  AEC 因此把它压到 k=1。亮度的路被削顶否决；而它本来也救不了这条带（带切的是几何位置）。
- **本文件配套的 `dl/AND_SIGN_20261031.md` §7 第 1 条**（"要动的是掩膜门限，不是曝光"）
  随之作废：真正的门是 ROI 带，不是一个更低的阈值。那条建议保留在原文里，这里点名撤回。
- **交接第 5/6 条关于"cam1 只有 cam0 的 62% 亮度预算"**：亮度差是真的（mean 435 vs 427、
  沿画面从 145 掉到 20 左右），但它不是掩膜只有 8 行的原因；这一段因果今天被替换。
