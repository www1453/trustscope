## 时间块（按顺序，每块都有可提交产物）

### 块 1（09:00–11:00）可复现工程包 —— 文档与可复现 15 分的主项

**做什么**
1. 新建干净目录 `submission/fpga_prize/`（全英文小写命名，符合 §3.3.5.4）；
2. 把依赖收齐：`ps_ui/*.c|h`、`startup.S`、`lscript.ld`、`build.ps1`、`check_layout.py`、`dl/ts_cn_font.h`、`ps7_init.*`、BD 的 `write_bd_tcl` 导出、`two_fft.xdc`；
3. 写 `build/rebuild.ps1`：**先检查每个依赖是否存在，缺一个就明确报错**（不要静默跳过）；
4. 本地编译一次（`arm-none-eabi-gcc` 不需要板子），记录 ELF 的 SHA256；
5. 写 `README.md`：一条命令重建 + 目录对照表 + 工具版本说明（我们是 2023.1，指南推荐 2026.1/2025.2，**必须写明理由**）。

**验收**：删掉 `submission/fpga_prize/build/` 后，只运行 `rebuild.ps1` 能生成 ELF；SHA256 与记录一致。

### 块 2（11:00–12:30）性能与资源表 —— 20 分

**做什么**（全部来自已存在的报告，不需要板子）
1. 从 `design_1_wrapper_utilization_placed.rpt` 抽 LUT/FF/BRAM/DSP/IO 与占位率；
2. 从 `design_1_wrapper_timing_summary_routed.rpt` 抽 WNS/WHS/TNS/THS、时钟频率、跨时钟域路径数；
3. 从 `power_routed.rpt` 抽总功耗；
4. 从 `clock_utilization_routed.rpt` 抽各时钟域负载；
5. 做成**基线对比表**：厂商原始例程（若有报告）vs 我们改动后；
6. 附上我们已有的运行时数据：单曝光 19 fps / 融合 8 fps、相位耗时（sync/class/qual/cam/panel/tail）。

**验收**：一张表，每个数字都能指向某个报告文件的具体行。

### 块 3（13:30–15:00）技能包重写 —— 15 分

**做什么**：按 §3.3.5.2 的四类（提示词工作流 / 案例模板 / 校验脚本 / 踩坑清单）重排 `skill/`：
1. 每个条目写四件事：**适用范围 / 使用方法 / 失效条件 / 从哪个失败总结出来**；
2. 补 `skill/README.md` 的**可迁移性说明**（换题目、换板卡还能用在哪）；
3. 补一份 `skill/checks/` 的自动校验脚本说明（我们已有 `check_repo_hygiene.ps1`、`check_ddr_layout.py`）；
4. 补"大模型协作记录"：提示词 → 模型回答 → 自我纠错轨迹（从本会话的真实记录里提炼，**不要编**）。

**验收**：陌生队伍拿到 `skill/` 能直接照着用；每条都有失效条件。

### 块 4（15:00–17:00）检测原型 v2 —— 创新与应用价值

**做什么**（用已 dump 的真实帧，不需要板子）
1. 亚像素配准（当前差 1 像素就产生 20 个误报）；
2. 板掩模（只比铜箔/走线区域，排除元件、丝印、背景）；
3. 形态学过滤 + 最小面积按"缺陷像素尺度"参数化；
4. **做一张扫描表**：合成缺陷边长 2/4/8/16/32 像素 × 对比度低/中/高 ⇒ 检出率与误报数；
5. 结论写成"这套镜头能看到多小的缺陷"，这是应用价值的硬证据。

**验收**：一张 `尺寸 × 对比度 → 检出/漏检/误报` 表 + 四张示例图。

### 块 5（17:00–18:30）设计报告骨架 —— 文档 15 分的另一半

按 §3.3.5.3 的七节写骨架，把已有数据填进去，缺的标 `TBD(需上板)`：
选题背景与创新点 / 原理与框图 / 软硬件划分与接口 / 优化过程与前后对比 / 大模型协作记录 / 技能包提炼过程 / 复现说明。

**验收**：七节齐全，每个 `TBD` 都写明"需要哪块板子上的哪次测量"。

## 明天的风险

1. **`ts_cn_font.h` 在 `dl/` 下**——要确认它是最新版本（构建脚本会校验它的哈希）。
2. **Vivado 报告是 2023.1 生成的**——报告里要写明工具版本，并说明为什么不升级。
3. **技能包的"大模型协作记录"**必须有真实提示词记录；我可以从本次会话里提炼，但不能虚构。
4. **检测原型的结论可能是"看不到"**——如果合成缺陷在 4 像素以下就检不出，那要**如实写**，并把结论转成"需要换镜头/缩视野"的建议。这比编一个漂亮的数字强。
