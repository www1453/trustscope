# 缺陷报告：相机 VDMA 停摆（cam0 或 cam1 交替出现）

> 2026-10-18 夜间，两次独立发生，现象与证据如下。**尚未定位根因。**

## 现象

- 一旦发生：那一侧的**画面冻结**（屏幕停在最后一帧），另一侧正常。
- 程序本身仍在跑（帧计数在走、`faultcode` 从 0 变为非 0，曾见 `0x00000083`）。

## 已测证据（两次不同的观测对象）

### 第一次：cam1 冻结

| 项 | 读数 | 判读 |
|---|---|---|
| cam1 VDMA | `CR=0x00010003`、`SR=0x00011810`（bit12 = DMA 内部错误） | 通道"在跑"但不搬数据 |
| 重配 VDMA | `SR 0x11810 → 0x10000` | 错误清掉了，数据仍不动 |
| 传感器寄存器 | `VTS=0x0303`（应为 `0x06A4`） | **传感器被写坏** |
| 写 `0x4202=0x00` | `0x3503` 跟着从 `0x03` 变 `0x00` | **写 A 寄存器、B 寄存器跟着变**（落点错乱） |

### 第二次：cam0 冻结（本轮）

| 项 | 读数 | 判读 |
|---|---|---|
| cam0 VDMA | `CR=0x00010003`、`SR=0x00015810`（bit12） | 同上 |
| 重配 VDMA | `SR → 0x00010000`，`CAM0_A` 中部像素仍 `18101418` 不变 | 数据仍不动 |
| 传感器寄存器 | ID `0x5640`、`VTS 0x06A4`、`0x3503=0x03` | **传感器看起来正常** |

⇒ 两次的表象相同（VDMA SR bit12 + 数据不动），但一次传感器坏、一次传感器好。
**所以"VDMA 停摆"与"传感器被写坏"是两个独立缺陷，可能同时发生。**

## 怎么恢复（已验证两次）

1. 整机冷断电上电（必须，不是热重启）；
2. **等传感器就绪再引导**：读 `0x300A/0x300B`，看到 `0x5640` 才算就绪。
   （冷启动后立刻引导会失败：`*** FATAL: camera 0 has no id (-1)`）
3. `xsdb stereo_bringup_byname.tcl`（重推两张 303 条表 + 配 VDMA）；
4. `xsdb ps_run.tcl`。

## 给静态审查者的具体问题

1. **`i2c_wait` 的失败语义**：调用方用 `(i2c_tx(...) & 0x004) == 0` 判成功；实测健康转移的状态是
   `0x00000003`（106 次完成 OR 起来），所以 bit1 也属正常。真正的致命位集合应当是什么？
   超时怎么表示才不会与"成功"混淆？
2. **写入落点错乱**：多次观察到写一个寄存器、另一个寄存器跟着变（`0x4202 → 0x3503`、
   曝光半写 `0x27EE`）。怀疑 STOP 条件缺失或数据/指针字节沉积。请核对 `i2c_tx` 的
   CR 写入序列与 Zynq I2C 的 STOP 语义。
3. **VDMA `SR` bit12（DMAIntErr）** 在什么条件下出现？4 个 frame store（cam0）与
   A,B,A,B 别名（cam1）的配置是否可能触发？
4. **`faultcode=0x83` 的含义**：代码里 fault 枚举的定义与触发点。

## 本报告的边界

- 所有寄存器读数都是 XSDB 直读得到的**瞬时值**，没有示波器/ILA 佐证；
- "数据不动"的判据是**同一地址两次采样（间隔 700–800 ms）**，采样点在图像中部——
  曾用 word0（左上角）判定过，那是错的（静态场景下本来就不变），已修正；
- 未测得 `0x4202` 的真实值（我改诊断脚本时把寄存器列表写坏了，输出标签错位，不可用）。
