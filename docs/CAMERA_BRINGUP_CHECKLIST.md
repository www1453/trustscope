## 阶段 A · 模块单独在桌上，不碰开发板（零风险）

> 这是**本次唯一的事前保护**，因为没限流电源。好处是零风险。

### A1 · 先认脚（**不要信丝印**）

模块母座探不进去 → **插两根细的实心导线/排针**进对应的孔，表笔夹住导线。
然后用导通档自己把电源脚找出来：

| # | 量哪两个孔 | 期望 | 实测 | 判定 |
|---|---|---|---|---|
| 1 | 候选 A ↔ 候选 B | ≈0Ω 导通 | ____ | 若导通，这两个都是 GND |
| 2 | 再找第三个 | ≈0Ω 导通 | ____ | **应能凑出「三个互相导通」的 GND 组** |
| 3 | GND 组 ↔ 另两个孔 | ≈0Ω 导通 | ____ | **应凑出「两个互相导通」的 +3.3V 组** |
| 4 | GND 组 ↔ +3.3V 组 | **不导通** | ____ | 必须不导通 |

**为什么这样能定方向**：J10 是
`PIN1 GND / PIN2 +5V … PIN37 GND / PIN38 GND / PIN39 +3.3V / PIN40 +3.3V`。
模块第 n 脚对 J10 第 n 脚，所以模块上必然也是
**「三个 GND」在一端、「两个 +3.3V」在另一端**。用导通性找出这两组，朝向就定死了。

> 🔴 **如果凑不出「三个互相导通的 GND」** → **我的推导错了 → 停下，不要通电，告诉我实测结果。**
> 这是可证伪的预测。（若模块上只有 2 个 GND 孔导通，也要停下。）

- [ ] 把认出来的孔用**胶带做标记**：`GND 端 = ______`（写下它在模块丝印哪一侧）
- [ ] 在纸上画一下：**J10 的 PIN1 要对着模块的哪个孔**：`PIN1 → ______`

### A2 · 短路检查（这一步对准上次的失效模式）

| # | 量哪两个孔 | 期望 | 实测 | 判定 |
|---|---|---|---|---|
| 5 | 模块 **PIN2(+5V) ↔ PIN1(GND)** | 读数**缓慢上升**，最后 ≥10kΩ（去耦电容充电） | ______ | **< 数十 Ω 或蜂鸣 → 停！不上板** |
| 6 | 模块 **PIN39(+3.3V) ↔ PIN1(GND)** | 同上 | ______ | 同上 |
| 7 | 模块 **PIN40(+3.3V) ↔ PIN1(GND)** | 同上 | ______ | 同上 |

**A3 · 判定**

- [ ] 三条都"上升 / ≥10kΩ" → **通过，进入阶段 B**
- [ ] 任何一条**几欧 / 蜂鸣不回升 / 恒定低阻** → **停止**，模块不上板，
      先把这个读数记下来发给卖家（这就是上次那颗的故障形态）

## 阶段 B · 板侧基线（**不插模块**、仍然断电）

> 这一步是必须的：不先量一次，阶段 C 就没有可比对象。
> 而且这时量到的读数是**开发板自己的 5V/3.3V 轨阻抗**，与模块无关。

先确认真的没电：

- [ ] 直流电压档量 **J10 PIN2**（对 PIN1）：应为 **0V**（若还有电压，等它泄放完）

| # | 量哪两个脚（模块**不插**） | 档位 | 实测（记形状：上升？稳定值？OL？） |
|---|---|---|---|
| 8 | J10 **PIN2 (+5V)** ↔ PIN1 (GND) | 电阻 | ______ |
| 9 | J10 **PIN39 (+3.3V)** ↔ PIN1 (GND) | 电阻 | ______ |
| 10 | J10 **PIN40 (+3.3V)** ↔ PIN1 (GND) | 电阻 | ______ |

> 形状关键词：**"OL"（超量程）= 很高阻，正常**；**"缓慢上升后停在某值" = 电容在充，正常**。

## 阶段 C · 插上模块（**仍然断电**，手放在电源开关上之前不要通电）

- [ ] 按 A1 的结论把模块**朝着正确方向**插到底（**认标记，不要靠手感**）
- [ ] 确认没有**错位一格**（两侧都数一遍引脚数：每排 20 个，应完全对齐）
- [ ] 目视：模块没有压到别的元件

**仍然断电**，重做阶段 B 的三条：

| # | 量哪两个脚（模块**已插、仍断电**） | 期望 | 实测 | 判定 |
|---|---|---|---|---|
| 11 | J10 **PIN2 (+5V)** ↔ PIN1 | **与 #8 接近，或更高** | ______ | 明显掉到低阻 → **拔下，不通电** |
| 12 | J10 **PIN39 (+3.3V)** ↔ PIN1 | 与 #9 接近或更高 | ______ | 明显掉 → **拔下，不通电** |
| 13 | J10 **PIN40 (+3.3V)** ↔ PIN1 | 与 #10 接近或更高 | ______ | 明显掉 → **拔下，不通电** |

**C 判定**

- [ ] #11–13 都与基线接近 → **通过**
- [ ] 任何一条**塌到几欧 / 蜂鸣** → 说明**插反了**（反插时模块的 +3.3V 会直接对地，
      模块的 GND 会直接怼到板的 +5V，见 `CAMERA_BRINGUP.md` §3）
      → **拔下来，重新对方向，再做一次 C**

## 阶段 D · 首次通电（**头 30 秒就是保护，人不要走开**）

**通电前最后确认**

- [ ] **B20 ↔ V12 跳线仍未插**
- [ ] 手放在**电源开关 / 电源插头**上（拔插头比找开关快）
- [ ] 准备好万用表，**已切到直流电压 20V 档**，黑表笔接 PIN1

**上电，然后按这个顺序做：**

| 时刻 | 动作 | 期望 | 实测 | 异常 → 立刻断电 |
|---|---|---|---|---|
| +3s | 目视 + **手背**靠近模块的 LDO 区域（不要用手心按下去） | 常温、无味 | ______ | 明显发热 / 异味 / 变色 |
| +5s | 量 **J10 PIN2** 对 PIN1 | 5V | ______ | 掉压 / 跳动 |
| +10s | 量 **J10 PIN39 / PIN40** 对 PIN1 | 3.3V | ______ | 掉压 |
| +20s | 量 **J10 PIN20 (SDA)** 对 PIN1 | **3.3V** | ______ | **≈1.7V → 故障，断电** |
| +25s | 量 **J10 PIN23 (SCL)** 对 PIN1 | **3.3V** | ______ | **≈1.7V → 故障，断电** |
| +30s | 看板上电源指示 / 听有无异响 | 正常 | ______ | 任何异常，断电 |

> ⭐ **PIN20 / PIN23 = 1.7V 就是上次那颗模块的指纹**（LVCMOS33 的 VIH≈2.0V，1.7V 必然通信失败）。
> 出现它就**判定模块侧故障，断电，不要再去调软件**。

**D 判定**

- [ ] 六行全部正常 → **相机侧供电与总线是健康的，进入阶段 E**
- [ ] 出现 1.7V 或掉压 → 断电，**停止**，记录数值（这就是要走返修/换货的形态）

## 阶段 D′ · **不给相机 5V** 的版本（用户选择，2026-09-26）

> 动机：上次烧掉的正是**模块自己的 +5V 走线**。把 5V 去掉，
> 就**整类**消除了"5V 路径过流"这个失效模式，而不只是降低概率。

**为什么这个选择有道理（新证据，不是保险起见）**

反插时电流走的是 **板 +5V(PIN2) → 模块 PIN39(+3.3V) → 模块 3.3V 轨 → 模块 PIN40 → 板 PIN1(GND)**，
—— **模块的 +5V 走线根本不在那条回路里**。
所以"烧断 +5V 走线"**不能由反插解释**，最可能是**模块内部 5V 路径过流**（H1）。
既然怀疑的就是 5V 路径，那么**切断 5V 的针对性是最强的**。

**怎么做（可逆、不损伤板子）**

- [ ] 断电、拔 USB
- [ ] 用一小段**热缩管**（内径约 1.0mm）套住 **J10 PIN2**，加热收缩；没有热缩管就用**Kapton 胶带包严**
      - PIN2 在一排的**端头**（与 PIN1 相邻的那一端），好操作
      - 套好后**目视确认整根针都被覆盖**
- [ ] 插上模块，**目视确认热缩管还在针上、没有移位**
- [ ] 仍断电，量 **J10 PIN2 ↔ PIN1**，与"不插模块"的基线比较：
      - **≈ 基线** → 5V 已断开 ✅（之前带模块是 20 kΩ）
      - **≈ 20 kΩ** → 绝缘没生效，5V 还连着 → 重做

**这条缓解措施的好处：失效方式是良性的。**
热缩管若脱落/移位，结果只是**回到原厂配置（5V 照常供给）**，
**不会引入新的短路** —— 所以它值得做，且没有额外风险。

**可证伪的预测（这次实验的科学价值）**

| 观察 | 结论 |
|---|---|
| 断电复位已释放后 **PCLK 跳变**、I2C 有 ACK | 模块**不需要 5V** → 以后永久按 3.3V 供电，**从设计上根除**该类故障 |
| PCLK 恒 0、I2C 无 ACK | 模块**需要 5V** → 这才是真正的取舍：要么接受 5V，要么换模块 |

> ⚠️ **要如实记账**：如果模块在 3.3V 下不工作，**不能据此判定"模块是坏的"**，
> 只能说"它在 3.3V 下不工作"。这个区别在跟卖家交涉时很关键。

**另外**：如果 3.3V 下不工作、最后还是得接 5V，那在这一步之前**必须先做**：

- [ ] 量 **J10 PIN2 ↔ PIN1**（带模块、断电）应仍在 **20 kΩ 量级**（≠ 死短）
- [ ] 通电后**手不要离开电源**，先量 PIN2 是否仍在 5V、PIN20/PIN23 是否仍 3.3V

## 阶段 E · 让相机真的出图（**不需要重新构建任何东西**）

### E1 · 首选路线：SD 卡启动厂商单目镜像（最省事）

现成材料：
`D:\BaiduNetdiskDownload\22_ov5640_single\Bootimage\BOOT.BIN`（1.84 MB，2026-07-31）
—— 它在厂商 `22_ov5640_single` 工程的标准 `Bootimage` 目录里，
是"**单目相机 → HDMI 输出**"的完整启动镜像（含 FSBL + 比特流 + 应用）。

- [ ] 找一张 **FAT32** 格式的 SD/TF 卡
- [ ] 把 `BOOT.BIN` 复制到卡**根目录**（文件名必须是大写 `BOOT.BIN`）
- [ ] 插卡，**把启动方式拨到 SD 卡启动**（具体拨码位置看板子丝印/手册，**别凭记忆**）
- [ ] 接一台 **HDMI 显示器**（该工程的 `hdmi_out.xdc` + `rgb2dvi` 是 HDMI 输出）
- [ ] 串口线接上（可选，用于看打印）
- [ ] 上电

**预期**：显示器出现相机实时画面。

- [ ] 出图 → **相机链路打通**，记下分辨率（应为 1280×720 或 1920×1080）
- [ ] 黑屏 → **进入 E2，不要立刻怀疑软件**

> ⚠️ 我**没有开箱验证过这个 BOOT.BIN 的内容**（只看到它在官方工程的 `Bootimage` 目录、
> 大小 1.84 MB，与客服给的**双目**版 2.19 MB 明显不同）。若它不起作用，
> 按 E2 的硬件判据走，再回头查镜像。

### E2 · 用 PCLK 计数器做**硬件级**判断（黑屏时的第一动作）

材料：`23_ov5640_dual\Vivado\two FFT\two FFT.runs\impl_1\design_1_wrapper.bit`（09-22）
—— 这版比特流里**已经内置了 `cam_pclk_cnt` / `clk_probe_cnt` 两个自定义 IP**，
就是当时做"把 `cmos1_pclk` 接进计数器长时间统计"用的。

- [ ] 用 Vivado 下载这个 `.bit`（JTAG）
- [ ] 读出计数器（该工程目录下**没有**找到现成 `.elf`，读计数器需要**写/跑一个小程序**，
      或临时接 ILA 看 `design_1_cam_pclk_cnt_0` 的计数值）

**判据（这条最硬，且不依赖上层软件）**：

| 现象 | 结论 |
|---|---|
| 计数器**在跳** | 相机**已上电、已起振、在输出像素时钟** → 问题在 I2C/配置/数据格式，不在供电 |
| 计数器**恒为 0** | 相机没有输出 → 回到 **供电 / 复位 / 模块** 三处查（别查软件） |

### E3 · 复位脚确认（E2 恒 0 时的第一嫌疑）

官方端口名是 **`cmos_rstn_tri_o[0]`（三态输出）**，落在 **B20 = J10 PIN35**。

- [ ] 确认该 GPIO **方向 = 输出**
- [ ] 确认复位**已释放（拉高）**
- [ ] 量 J10 **PIN35** 对 PIN1：应是 **3.3V**（被按在复位里时是 0V）
