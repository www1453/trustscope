## 真正的根因

**第二颗传感器一直是好的。问题在 PL 的 `axi_iic` 那条 I2C 通路。**

我们的设计把第二路的 I2C 接在 PL 的 `axi_iic` 上，**那条路读不到任何器件**。
改成**厂商原设计的做法**（把 PS 的 I2C1 走 EMIO，接 `P14`/`W18`）之后，
**立刻就读到了 ID**。

厂商手册第 23.2 节原话：

> **"还有一点要修改的是，将两个 IIC 都设置成 EMIO 输出，配置两个 cmos sensor。"**

**我们偏离了这句话**——PS 的 I2C1 被 LCD 触摸占着（`F20`/`F19`），
所以第二路只能退而用 PL 的 `axi_iic`。**那个偏离就是问题的来源。**

## 关于此前那批"无响应"的证据，为什么归因错了

数据本身是对的（I2C 无 ACK、DVP 无输出），**但结论"传感器坏了"越过了证据**：

- 两条证据证明的是 **"从我们这一侧够不到它"**
- 我却写成了 **"它不工作"**
- **两者在现象上一样，但原因完全不同** —— 前者是通路问题，后者是器件问题

**这是同一个错误家族：把"我的查询失败"读成"那个东西不存在"。**
（与案例集 T20/B16 那类同族。）

**防守办法**：当证据只支持"够不到"时，结论就只能写"够不到"，
**不能升级成"它坏了"** —— 尤其当还有另一条未验证的通路存在时。

## 实际改动

### Block Design

1. 断开 `cam_iic_1/IIC` → `cam_iic_1_io`（先断言该接口网**只有 2 个端点**，见 B17 的教训）
2. 断开 `processing_system7_0/IIC_1` → `lcd_touch_i2c`（同样断言 2 端点）
3. 删掉 `lcd_touch_i2c` 端口
4. 把 `processing_system7_0/IIC_1` 接到**已有的** `cam_iic_1_io` 端口（引脚 `P14`/`W18` 早已就位）
5. `axi_iic`（`cam_iic_1`）这个 cell **保留不删**，只是 IIC 主接口悬空
6. **每步后断言全局时钟网引脚数**（始终 51，从未减少）

### XDC

- 删除 `lcd_touch_i2c_scl_io`/`sda_io` 的 6 行（`F20`/`F19`）
- `cam_iic_1_io_scl_io`/`sda_io` 的 `P14`/`W18` 约束保留不变

### 为什么可以牺牲触摸屏的 I2C

**PS 代码里完全没有使用触摸屏**（只用 I2C0 驱动相机）。让出无功能损失。

## 另一个必须记住的坑：I2C 只能在引导的同一会话里访问

```
live14 内部：rst -system -> ps7_init -> ps7_post_config -> fpga -file -> ...
             它的 I2C 收发正常（303 条表全写进去）

之后新起的会话里读 I2C：ISR 读到 0x01（ARB_LOST），读值全 -1
```

**所以任何 I2C 测试都必须和 `rst -system` + `ps7_init` + `ps7_post_config` 放在同一个会话里。**
`stereo_both.tcl` 就是照 `live14_bitpair.tcl` 第 106-116 行的顺序写的。

**缺 `ps7_post_config` 那一步，I2C 就不会工作。**

## 现在的双目架构

```
相机0: PS I2C0(EMIO, T15/T16) -> 相机0  <- 已有
相机1: PS I2C1(EMIO, P14/W18) -> 相机1  <- 本次改成，与厂商一致

相机0: cmos_d_0 -> rs_slice0 -> cam_switch(S00静态) -> subset_conv_0 -> axi_vdma_0 -> mem_intercon/S00 -> HP1
相机1: cmos_d_1 -> rs_slice1 -> subset_conv_1 -> axi_vdma_2 -> mem_intercon/S04 -> HP1

帧存：相机0 = 0x10000000/0x10400000   相机1 = 0x11200000/0x11600000
VDMA 基址：vdma_0 = 0x43000000   vdma_2 = 0x44A00000
```
