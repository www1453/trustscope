# store 极性：实测确认（2026-10-23 17:1x）

> 结论：**"置位 = 采集正在填第二块，已写完的是第一块" 成立。**
> 相机 0 与相机 1 的选帧逻辑是对的。这条从"继承自相机 0 的约定、未实测"
> 升级为**已实测**。

## 方法：已知答案注入（不是统计比较）

往两块帧存（相机 1 的 `0x11200000` / `0x11600000`）的**第 719 行**各写一个不同的魔数：

```
A = 0xA5A5A5A5
B = 0x5A5A5A5A
```

立刻读回，看哪一块的魔数**先被相机数据冲掉**——被冲掉的就是"正在被写"的那块，
其与帧指针位的对应关系就是极性的定义。

选 **719 行**的理由：`measure_pass` 只采样偶数行对（0,1）(16,17)…，719 不在其中，
所以注入不会污染任何被发布的统计量。

## 结果

12 次试次里，8 次两块同时存活 `(1,1)` 或同时被冲 `(0,0)` —— 这些**不含信息**
（说明写者此刻还没扫到 719 行、或已经扫过，两种情况下两块都同状态）。
剩下 4 次是判据：

| 试次 | 指针位 | A 存活 | B 存活 | 结论 |
|---|---|---|---|---|
| 3 | **1** | 1 | 0 | 写者在 **B** |
| 6 | **1** | 1 | 0 | 写者在 **B** |
| 7 | **0** | 0 | 1 | 写者在 **A** |
| 10 | **0** | 0 | 1 | 写者在 **A** |

**两个可能方向都出现了，各自配着对应的位值：4/4 自洽、0 个反例。**

这与代码里的既有约定一致：

```
位=1 → 采集正在填第二块 → 已写完的是第一块
相机 0 :  wr0 = (CAP_FRPTR & CAP_WRBIT) ? 1 : 0;  store0 = wr0 ? CAM_BUF : CAM_BUF_B;
相机 1 :  wr  = raw & 1;                          measure = wr ? CAM1_BUF : CAM1_BUF_B;
```

## 为什么前两次测不出来（记录以免重犯）

两次都是"比较两种极性下的统计量散布"。两个原因同时成立：

1. **静止画面下两块帧存内容几乎相同**，读错了也没有差别；
2. **运动画面下运动本身的方差远大于极性造成的方差** —— 同一配置重复测得到过
   4 / 20 / 16 三个值，噪声底（12）比效应（16）还大。

教训：**"没测出差别"不等于"没有差别"。当效应小于噪声底时，正确的做法是换一个
不需要统计的判据（已知答案注入），而不是加大样本量或换统计量。**
