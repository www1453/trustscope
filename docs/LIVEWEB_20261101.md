# TrustScope 实时网页（2026-11-01）

一句话：`http://127.0.0.1:8801/` 显示相机 0 的实时缩略图、站台自己的邮箱数字和全分辨率单帧；只读 JTAG，读不到就说读不到。

## 启动
```
python dl\liveweb\serve.py --port 8801
```

（或双击 `dl\liveweb\start.bat`；`--no-board` 可在不接板时看页面，`--record` 见下。）
后台只开 **一个** xsdb 会话（`stream.tcl`），循环读：相机 0 的 160×90 缩略图（64 KB，`0x122B0000`）+ 邮箱块 `0x10F00000..+367`（368 字，一次 `mrd -value`）。没有每帧新起 xsdb。

## 实测帧率（30 MHz JTAG，2026-11-01 11:00–11:08）
| 量 | 实测 | 说明 |
|---|---|---|
| 缩略图传输 | **约 4.5–5.5 fps**（10 s 实测 4.5 fps；MJPEG 2.5 s 收到 15 帧） | 64 KB/次，单次约 130–180 ms；**≥2 fps 达标** |
| 缩略图内容变化 | 静态场景 0–3 fps | 画面不动时像素可完全不变，传输计数仍在走；不是卡死 |
| 邮箱快照 | 约每 0.15–0.25 s 一次，年龄 <0.3 s | 判定/数字跟着它更新 |
| 全分辨率帧 | **4.2–5.1 s/帧，约 0.20–0.24 fps**；首帧/争用 5.8–10.1 s | 2,764,800 B / 691,200 words；一次 `mrd`，若挂起则 `con` 恢复 |
| JTAG 全帧吞吐 | **约 540–630 KB/s，典型上限约 576 KB/s** | 单字 DAP 读的上限；争用时会掉到 320–470 KB/s |
| 邮箱块读 | 约 2 ms / 368 words | 一次块读，避免 20 次分开读 |

**576 KB/s 是硬上限**：宿主端任何全帧像素级处理（本周离线试的那些统计量）都不可能在这条通路上实时运行，只能对已存盘帧离线跑。2 fps 指的是缩略图/页面更新，不是 2 个独立 1280×720 全帧。

## 页面上的数
**判定只来自邮箱，不来自画面。** `darea ≥ limit → NG`；`diffok ≠ 1 或 regstate ≠ 1 → 无法判定`；否则 `OK`。哨兵 `0xFFFFFFFF` 按不可用处理（显示“—”），不当成大数。

- `MB_DIFF_DAREA`(23)、`MB_DIFF_LIM_USED`(223)：最大连通深组 / 实际面积门限，8×8 格。
- `MB_DIFF_OK`(180)：1 才是可比较；3 clip 门、5 新变换、6 件未完全入视野，其它值同样拒判。
- `MB_REG_STATE`(232)：0 无基线、1 已配准、2 无法判定。
- `MB_PART_PTS`(366)、`MB_PART_BX0/BX1`(115/136)：活体掩膜点数 / 板 bbox 列（8×8 格）。
- `MB_CLIP_LIME`(68)、`MB_AEC_STATE`(144)、`MB_DIFF_CELLS`(181)：饱和门限、AEC 状态、整帧粗格（诊断，不参与判定）。
- `MB_CHANTOT`(56)：必须 691200。不等于它时，画面顶部烧 `NOT A VALID QC FRAME` 红条并给警告，**不把该帧当 QC 帧**。
- 图片上的 bbox：X 总是画；Y 只在 `diffok=1 且 regstate=1` 时画，否则写 “y withheld”。（非判定帧的 Y 曾读到 2..83、明显不是板子，不能当 bbox 用。）
- 缩略图 160×90 上采样到 640×360；它按构造看不见 1–3 px 细划痕，只用于位置/运动。全分辨率帧才是细节与 `--record` 的主视图。

## 什么时候会显示 STALE / FROZEN
- **核心 halt**：页面显示 `FROZEN` / `CORE HALTED`，大判定变“无法判定”，MJPEG 换成 `CORE HALTED` 占位图。实测 halt 后 2 s 内页面如此；`con` 后自动恢复 LIVE。
- **hw_server 断开**：页面显示 `STALE` / `STREAM DOWN`，`stale_reason_code=stream_dead`，不把最后一帧当实时；实测约 11 s 后 serve.py 重启 xsdb 并自动恢复 LIVE。
- **没有新帧 / 没有板子**：`stale_no_frame` / `stale_no_board`，同样占位图。
- `--no-board` 时页面只显示 STALE，不显示任何邮箱数字（避免把旧 data 当本次读数）。

## 全分辨率帧与撕裂
全帧用一次 691,200 字 `mrd`（不人为 `stop`）。实测 4.21/4.34 s 两次读后核心仍是 Running；早先一次同类大读把 Cortex-A9 留在 Suspended，Tcl 会在“抓取前是 Running”时用 `con` 恢复，并把 `halt_restored=1`、`core_paused_ms` 写到页面上。**PL VDMA 不受 CPU 控制**，所以即使核心暂停也不阻止它继续写：5 s 直读仍可能跨过写入、出现一条撕裂线；页面固定写 `tear_suspect=1`，不假装它是原子帧。

## --record
```
python dl\liveweb\serve.py --port 8801 --record
```

每抓到一张全分辨率帧就存 `dl\liveweb\record\full_<seq>.jpg`（1280×720，quality 92）+ 同名 `.json`（邮箱字、判定、时间、撕裂/halt 标记）；`--record-every N` 每 N 张存一张。**只存全帧，不存缩略图**。录视频用下面的窗口/桌面录制，不用 `--record` 的 JPEG 序列。

先最大化 Edge 打开 `http://127.0.0.1:8801/`，然后：

## 复用了什么 / 替换了什么
- 复用 `submission/dashboard/index.html` 的深色配色、顶部/标签/徽章/表格/诚实注样式；页面不是第二套设计。
- 复用 `submission/dashboard/status.js` 的状态 schema：`source.severity`、`stale`、`stale_reason_code`、`stale_reason`、`snapshots.files[].age_s`，以及 `--no-board` 的“不显示数字”语义；`/api/status` 和 `/status.js` 都提供。
- 复用 `dl/live_thumbs.py` + `ps_fft_dual/ps_thumb_stream.tcl` 的“单会话 + 文件轮换/标记”做法（这里用原子 rename 代替 .done 轮换），复用 `dl/live_view.py` 的“快照不是视频”的诚实措辞。
- **替换** `submission/dashboard/live.html` 的单帧文件回放：旧页约 1 帧/1.5 s 且自己声明是 replay；新页是连续 MJPEG 缩略图 + 按钮全帧。旧文件没有改，仍可打开。
- 只读边界：Tcl 只用 `mrd` / `state` / `targets` / `connect` / `jtag frequency`；没有 `mwr`、`rst`、`dow`，没有写邮箱/传感器/参考。唯一的 `con` 用于“大读后核心被挂起、抓取前本来是 Running”的恢复。
