# 面板锁存：2026-10-18 的两处修正（写给下一个会话）

> 权威条目在 `skill/pitfalls/measurement-traps.md` 的 **M43**（本地副本已同步修改）。
> 本文只记"这次实测改掉了哪两句旧话"，避免下一个会话读到过期结论。

## 修正一：`ps_run.tcl` 不烧比特流（旧文写反了）

- **会烧的只有一处**：`stereo_bringup_byname.tcl:251  fpga -file`。
- `ps_run.tcl` 只做 `dow`（下载程序）+ `con`，**不重烧 PL**。
- 所以"只改程序 ⇒ 只跑 `ps_run`"是**零锁存机会**的做法；旧文把 ps_run 说成"每次都会重烧"，
  会让人误以为改程序也有风险，从而错误地减少验证次数。

## 修正二：**禁止"只给屏断电重插"**（那是热插拔）

旧文把"只给屏断电重插"列为排查第 3 步和第一动作。**在通电状态下拔插屏的电源/排线属于热插拔，不能做。**
正确的顺序是：

1. dump 帧缓冲（判断是不是屏侧问题）；
2. 读显示通道 `SR` 的 **bit16**（不是 bit12）；
3. **软件显示重初始化**：停 MM2S → `v_tc CTRL=0` → 等 300 ms → 写回 `0x03F7EF07` →
   按序重配 MM2S（几何/地址 → CR → **VSIZE 最后**）。脚本：`ps_fft_dual/ps_display_reinit.tcl`。
4. 若仍不对 ⇒ **整机冷断电再上电**（板子与屏一起断电、一起上电），然后
   `stereo_bringup_byname.tcl` + `ps_run.tcl`。
   **冷启动前先 dump 帧缓冲与 `SR` 快照**——"重启会清掉寄存器状态"这个代价，在取过证之后可以接受。

## 第二种触发形态：像素流断掉（不一定来自 VDMA）

实测（本会话两次复现）：逐帧 arm 曝光把相机 0 的 VTS 写坏

- `VTS = 0x3501`（13569 行）；
- `VTS = 0x0102`（258 行，**低于 720 行图像高度**）。

后果：传感器不再输出有效帧 ⇒ 捕获指针 4 秒只跳 1 次、`sync` 每循环空转约 950 ms、
循环掉到 ~1 fps ⇒ 屏上停在旧帧/花屏。

**注意判据**：`MB_ARM_LOST = 0`、`MB_ARM_UNREAD = 0`、`0x380E/0x380F` 连读 9 次全部相同
——**"写成功"不等于"写对了"**。这类故障只能用"回读 + 跟已知好值比较"发现
（程序里已加 VTS 自愈看门狗，每 8 次 arm 校验并重写）。

## 防它的唯一有效办法

- 只改程序 ⇒ 只跑 `ps_run.tcl`；
- 换比特流/改 BD ⇒ 才跑引导，且**收工前整机冷启动一次**；
- **演示当天禁止重烧比特流**。
