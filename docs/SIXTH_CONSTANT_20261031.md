# 第六个绝对常数（128）——判断记录与处置（2026-10-31）

> 第十一轮。采集跑到第 11 块（d28）失败，定位到 `part_min_pts_view()` 的 128 下限。
> 三个候选修法（放宽 ROI / 重取 cam1 参考 / 跳过）的判断依据记在这里，
> 以及 mean（word 151）到底是什么的一次核对。

## 1. 现场事实

```
STEP 0b: cam0_ref=809  cam1_ref=200   (今晨光弱，cam1 参考从昨晚 387 掉到 200)
cam1 地板 = clamp(200/2, 128, 400) = 128
d28 在 cam1 的掩膜 ≈ 110 点 → 110 < 128 → REGWHY_FEWCELLS（3）→ 拒判
```

**注意一个容易被误读的细节**：d28 的**相对**判据其实是过的——
110 > 200/2 = 100。卡住它的**只有** 128 这个绝对下限。
所以这次不是"cam1 看不见板"，是"cam1 看得见，但低于一条与参考无关的常数线"。

## 2. 候选一：把 cam1 的 ROI 首行 50 → 20（主机写字，零构建）

**不成立，而且是几何上被本项目自己的测量推翻的。**

main.c:2552–2566 记着这条带的来源是 cam1 自己的 dump（`dl/_cam1_view_20261030.jpg`）：

| 项 | 位置（格行） |
|---|---|
| 皮带宽亮区起点 | 源行 376..395 = **格行 47..49** |
| **板的本体** | 源行 432..680 = **格行 54..85** |
| 当前带 | 源行 400..719 = **格行 50..89** |
| 带的余量 | 板上方 4 格、下方 4 格，**"contains no room row"** |

把首行从 50 放宽到 20，新增的是**格行 20..49 = 源行 160..399 = 纯房间**——
板的本体从格行 54 才开始，**那 30 行里一格板都没有**。

所以扫描里 +30~40% 的"收益"**全部是房间/背景失配的格子**，不是板。
它正是当初那条带被造出来要消灭的东西（同段注释：房间像素一旦与背景不同就变成
"工件"，**那就是 3408**）。而 pts 对 ROI 的非单调（434/513/369/512/487/378）
也因此有了名字：**房间失配斑块随环境光变，再被"最大连通团"规则合并或竞争**。

副作用（比担心的更重）：空带不变式会破——cam1 的空带掩膜现在是 0（C1/C3 闸门
刚跑绿的那个 0），放宽后房间失配进来就不再是 0；bbox 会被房间斑块拉走；
而且这是**跑到一半改台面状态**，前 9 块 ROI=50、后 17 块 ROI=20，
给 26 块数据加一个与时间完全共线的二元协变量。

## 3. 候选二：重取 cam1 的参考（ref 200 → 300+）

**三个里最危险，而且方向是反的。**

- 地板 = clamp(ref/2, 128, 400)。ref 200 → 128；ref 300 → **150**。
  地板**变高**，d28 的 110 更难通过（除非光也同时恢复）。
- 真正的伤害：`d0.raw`/`d1.raw` 是**对参考的逐格带符号残差**。换参考 = 后半段
  17 块与前半段 9 块对的是两块不同的基准，容差图也重建。这不是协变量，
  这是**让离线分析的两半不可比**。而逐格残差正是这批 dump 的全部载荷。

## 4. 候选三：跳过、记成拒判 —— 采纳

`--stage dump` 的门要求两路 regwhy=0，cam1 拒判时门永远不开，
脚本自己会重试 3 次后记 FAIL/排除。**这是协议本来就在做的事**，不需要干预。

代价：这块板一份 dump 都不留（cam0 的 d0 也没有）。12 块划伤里少 1 块，
配对分析从 12 对变 11 对——可接受，且**拒判本身是一条测量**（在报告里属于
cam1-ROI 那一节，与 10-29 那批 13 行 coherent=0 同类）。

**不要**为了救 2–3 块板去放宽 dump 门（只许 cam0 过），那是跑到一半改采集协议。

## 5. 一个必须记录的边界：128 也不是凭空来的（但这是解释，不是代码事实）

冷搜索在不同地方给出过不同的最小证据线：一处是"重叠 428/866 点，低于 433 点
stride-1 底线、18..21 个 stride-4 采样低于 27"（main.c:4885–4886），另一处是
"923 点时 stride 4 看见约 57 点，所以底线取 48"（main.c:7698）。
**这两个数是逐案推导的，不是同一个编译期常数**——所以"128 是它们的保守代理"
是我的解释，不是从代码读出来的事实，写报告时不能当成依据。

能说的只有实测：已知能工作的最小掩膜是今晨 d23 的 152 点（diffok=1），
110 点比它低 28%，**能不能配准没有证据**。所以"把 128 调小"不是免费的：
它把一个响亮的拒判换成一个可能静默锁错的结果——而那正是 SAD 设计注释里
写明"比没有更糟"的失败方式。

后截止的固件修法不是把 128 改小，而是**让下限由搜索自己的要求逐路导出**
（用当帧的掩膜与搜索的分层采样数计算），不给它一个全局常数。

## 6. mean（word 151）——2026-10-31 中午【整节撤回，以下为纠正后版本】

**撤回原因（实测，10-31 上午）**：把 pin 从 8662 手动拉到 8721 / 12000 / 14300 /
16500，`pts0` 从 0 → 0 → 7 → 2143，而 **word 151 全程读作 290，一动不动**。

一个把曝光改到 1.9 倍而"整帧绿均值"不变的字，不能当作亮度读数用——
它要么读的不是当前帧、要么读的不是被改的那一路、要么有滞后。
**它的出处（哪一路 / 哪一帧 / 多少延迟）未经核实。**

因此：

- 本节原先写的"mean 是场景构成的混合量、构成项 ≤~50‰"——**撤回**。
  它是把一个未经验证的字当成物理量去解释，正是本项目反对的那种推理。
- 连带撤回："435→278 是构成"与"45 秒阶跃是光照"两句——它们都建立在这个字上。
  那个事件**回到"成因未命名"**。
- **替代的量**：逐路均值 `MB_CAM0_MEAN`(212) / `MB_CAM1_MEAN`(210)、
  十段行直方图(621–630)、`clip`(213)、以及 **掩膜点数本身**（它才是被门使用的量）。
  meta.json 里已经记了 hist 与 pts；`mean` 字段保留但**不得用作协变量或门**。

（以下为被撤回的原文，留作审计痕迹，不引用）

`#define MB_AEC_MEAN 151u /* camera-frame green mean, per-mille of 255 */`（main.c:1505）——
**整帧绿通道均值**，‰ 量纲。所以它确实是混合量，但成分要分开算：

- **构成项有界**：板绿 135/255 = 529‰ vs 皮带绿 198/255 = 776‰；板占画幅 ≤20%
  → 板入画最多把 mean 拉低 0.2 × (776−529) ≈ **50‰**。
  实测 482 → 435（−47‰）正好落在这个量级——**这就是构成项**。
- **剩下 150~200‰ 的摆动不是板的构成**：482 → 282 是 −200‰（−41%），
  一块占画幅 ≤20% 的板做不到。同一时刻掩膜从 507 泛化到 1936/2242、
  avg 从 8 掉到 1、NOCONV 占主导——**这是一个"场景整体变了"的事件，
  成因未命名**（2026-10-30 记录里就写着"成因未命名"，不要在这里改口）：
  可能是光照跌落，也可能有东西进了画面/遮住了画面。**两者都符合数据。**
  ⚠️ 2026-10-31 修正：我在这里一度把它写成"光照阶跃"的证据，那是我们自己
  反对过的成因归因过头——它当时被记成"未命名"是有原因的，保持未命名。

所以"435→278 是构成不是环境光"这句**不成立**：构成项最多 ~50‰（甚至可能 ≈0），
剩下 150~200‰ 是一个**成因未命名**的场景事件。
正确的表述是：

> mean 是整帧混合量 = 有界的构成项（板面积 × 板-带色差，≤~50‰）+ 无界的光照项。
> 同一台设备在"板始终在画面里"的条件下读到过 482（晚间正常）、435（今晨）、
> 282（45 秒暗态），故绝对阈值既不能跨构成、也不能跨光照期使用；同一构成、
> 同一光照期内它仍是 NOCONV 的有效辅助判别（85/85、12/801）。

## 8. 一个必须与排除一起报告的检查：排除会不会与类别相关

拒判判据是"cam1 的掩膜 < 128 点"。如果划伤板（颜色更深/面积更小/表面状态不同）
在 cam1 里的掩膜系统性更小，那么被排除的就会**偏在划伤一侧**——
排除掉的正是划伤里最难的那几块，AND 分析里划伤侧的分布会被系统性抬好。

这和 10-29 那批"类别与拍摄顺序完全混杂"是同一类错误（第 8 轮推断 C）：
**一个看起来中立的筛选，只要与类别相关，结论就不可解释。**

必做的检查（跑完立刻做，两分钟）：
按类列出被排除的板数与总数（划伤 x/12、良品 y/14），以及各自的 cam1 pts 中位。
若排除率在两类之间明显不同 → 报告里必须写明"AND 结果只在
'cam1 掩膜 ≥128 点'这个子总体内成立"，并给出两类的 cam1 pts 分布。
