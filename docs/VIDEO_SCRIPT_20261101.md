## 1. 为什么是这个顺序（十秒看懂的编排逻辑）

外部复盘给出的获奖画像里有一条最刺：**得奖的片子都把指标摆在一面墙上让评委看见，而没人靠"RTL 有多深"取胜**。所以本片不按"模块介绍"排，按**评委的疑问顺序**排：

| 段落 | 回答的疑问 | 镜 |
|---|---|---|
| ① 问题 | 这东西为谁解决什么？漏了会怎样？ | 01–02 |
| ② 三态 | 它到底输出什么？跟二值有什么不一样？ | 03–05 |
| ③ 能力墙 | 能检什么、检多少、检不了什么、检不了的去哪？ | 06–08 |
| ④ 工程可信度 | 这真的在片子上跑着吗？数在哪？还能验吗？ | 09–12 |
| ⑤ 指标墙（实时） | 现场能看见吗？ | 13 |
| ⑥ 边界与下一步 | 你们知道自己不能干什么吗？ | 14–15 |

**前三段 44 s 内必须出现"无法判定"那一帧**——这是本片唯一不可替代的主张，放在第 33 秒。

**"开场说问题"的硬口径**：第一帧画面可以从皮带上的一块板开始（这是应用现场，不是板子的产品照），但**第一句解说与第一屏字幕说的必须是漏判的代价，不是任何一个参数**。全片第一句不许出现器件名、频率、分辨率、检出率。

## 2. 台面 vs 非台面（最小化原则）

判定口径只有两类，逐镜在 §3 表的"台面"列标出：

| 标记 | 含义 | 本片有几镜 |
|---|---|---|
| **台面·皮带** | 需要皮带跑动 | 01 |
| **台面·换板** | 需要真板摆位、等稳定窗口 | 03 / 04 / 05 / 07 |
| **台面·看板** | 需要板子活着 + 浏览器 + 录屏 | 13 |
| **台面·CNN** | 需要 JTAG + 板子活着（一条命令） | 10 |
| 字幕卡 | Pillow 渲染，零台面 | 02 / 06 / 09 / 11 / 14 / 15 |
| 离线终端 | 只读仓库文件即可录，零台面 | 08 / 12（右半） |

**只要四项物理动作上台面**：皮带跑一段、换三块板（良品 / 污染 / 划痕）+ 板推半出视野那一下、看板录屏、CNN 一条命令。其余全部可以离线做。

**被砍掉的"看起来该拍"的台面镜头，以及为什么**：

| 想拍的 | 为什么不拍 |
|---|---|
| 现场演示光照一致性门（把灯调暗 1.6 倍 → 拒判） | 换灯必须重采背景 + 重取参考，会毁掉整场会话剩下的镜头；这一条用**档案数 + 字幕卡**（镜 11）说，画面不演 |
| 现场把缺角板放上去演"检出缺角" | **板上没有这条判据**（骨架 §3：离线验证、未上板）。放上去只会拍到固件的另一条判据，演它等于造假。缺角只走离线复算镜（08） |
| 现场演"面板对划痕板判无法判定" | 固件里没有"划痕撤答"这条逻辑；划痕的"不投票"发生在**主机侧扫描工具**（镜 07）。演在面板上就是假 |
| 现场重跑 41 块板人群扫描 | 一块一停、每块还要 8 s 稳定窗口，几十分钟起；人群数用**能力墙**（06）给，扫描只录 2 s 的拒答横幅（07） |
| 双目标定 / 撕裂率 / 触屏 / FCLK 实验 | 都是 10-16 那一代固件的结论，与 2026-11-01 档案不同代；剪进来会出现两代数同片 |

**旧片（`submission/video/demo.mp4`，114 s）怎么用**：只在**镜 02 标题卡**里取 **3 s 整机静帧**（压暗 40%，画面上不含任何数值）。其余一律不剪——旧片里每个数都属于 10-16 的构建，与本片 11-01 的档案数同屏就是两份文档口径打架。

### 8.3 "实时"这个词的用法（外部复盘点过名的一条）

- 可以用于：判决节拍（10 s/件）、缩略图更新（4.3–5.0 fps）、板端循环（裸机 PS 不停机）。
