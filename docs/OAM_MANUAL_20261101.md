# 工位操作与维护手册（OAM）· 2026-11-01

> 适用：本仓库这台 Zynq-7020 裸机 AOI 工位（停带式，双视路 AND 判定）。
> 交付固件戳 **`TSC1CC73517D`**（= git `34b9b47`），`MB_AVG_N`（字 408）默认 **8**。
> 所有命令都在仓库根目录执行（`C:\Users\user\Documents\trustscope`）；`xsdb` 来自 Vitis 2023.1。
> 本手册引用的每个脚本都在仓库里存在；判据取固件自己发布的字（"字 n" = 邮箱偏移 `0x10F00000 + n*4`）。

---

## 一、班前（每次开机 / 每次换班）

### 1. 红线：J10 跳线必须在外面

肉眼确认 **J10 PIN35(B20) ↔ PIN28(V12) 之间没有跳线帽**。
B20 与 V12 都是信号脚，插上就是把两个输出短路，可能烧 IO 或烧板。这一条软件看不到，只能人查；**查完才允许上电**。

### 2. 上电顺序

冷启动（断过电、换过镜像）走 1–4 全部；站台一直没断电、画面在跑时可直接跳到第 3 步。

1. 断电状态下查完第 1 条 → 给板上电，等 LCD 出画面。
2. 连 JTAG，在**同一个 xsdb 会话**里：
   `xsdb ps_fft_dual\bringup_now_20261029.tcl`
   （按名字选 A9 → `ps7_init` + `ps7_post_config` → 下位流 → 两路 sensor 表 → 两路采集跑起来。I2C 只在这个会话里可用。）
3. `xsdb ps_fft_dual\disp_fix_20261023.tcl`
   （显示 VDMA 几何：CR / HSIZE / STRIDE / ADDR / VSIZE，写完逐个回读。）
4. `xsdb ps_fft_dual\strict_load_cores.tcl`
   （`rst -cores` + 装载 `ps_ui\ps_ui.elf`；不动 PL、不动 sensor。）

### 3. 空皮带采背景

皮带清空（视野里不放任何东西）→ `xsdb ps_fft_dual\roi_bg_20261030.tcl`

判据（脚本自己判，日志 `ps_fft_dual\logs\roi_bg.log`）：
- `bg_state=1` **且** `cam1_bgok=1` → 通过；
- 否则脚本以退出码 2 结束：**记录该行，不要盲目重采**（背景里带上东西，之后每一帧都会被读成"缺料"）。

### 4. 良品板取参考

放一块确认过的良品板在工位（与生产同一摆位）→ `xsdb ps_fft_dual\ref_wait_20261101.tcl`
它发 `MB_CMD=9`，最多等 30 s，直到 `MB_DIFF_OK` 从 5（配准年轻）回到 1。

判据：
- `diffok0=1`；
- `refq0` **不是 1**（0 通过 / 1 失败 / 2 未测 / 3 声明接受）；
- `reg_state=1`。

若 `refq0=1`（颜色规则下常见：覆盖率约 1400，人群上限 173）→ 用
`xsdb ps_fft_dual\ref_take_colour_20261031.tcl` 重取：它先写 `MB_REFQ_DECL=1`，参考被"声明接受"后读 3，而不是 1。
需要两路 AND 的映射门逐条判（重叠度、相机 1 掩膜）时用 `xsdb ps_fft_dual\roi_ref_20261030.tcl`（退出码 1 目标 / 2 无参考 / 3 相机 1 掩膜未降 / 4 相机 1 参考质量）。

### 5. 确认站台可判

`xsdb ps_fft_dual\fix1_state_20261023.tcl`（只读，连读 6 次；可选参数＝采样次数）

三条判据，缺一不许开产：

| # | 判据 | 读法 |
|---|---|---|
| 1 | `FWID` 三字拼出的 12 个字符 = **`TSC1CC73517D`** | `0x31435354` 就是 "TSC1" |
| 2 | `reg_state=1` | 配准已锁 |
| 3 | `diff_ok=1` | 比较真的发生了 |

任一条不满足 → 走第二节，不要靠改参数把它"读成 1"。

> **镜像核对**：`strict_load_cores.tcl` 装的是**盘上** `ps_ui\ps_ui.elf`。若 FWID 读到 `TSC15E7C671D` 或 `TSC1FF00297A`（工作树里未提交的静态判定区 SROI 构建），那不是交付镜像——它多一个 `MB_DIFF_OK=7`（静态判定区门）。换回交付镜像再开产。

## 二、班中

### 1. "无法判定"变多时：先读码，再动手

三值输出：`MB_DIFF_VERDICT`（字 222）= 0 PASS / 1 NG / **2 无法判定**。
固件规则：拒判（没有参考 / 光变了 / 图像不可信）**一律是 2，绝不是 PASS**。

`xsdb ps_fft_dual\fix1_state_20261023.tcl 10` 连读 10 次，看 `diff_ok`：

| `diff_ok` | 含义 | 动作 |
|---|---|---|
| 3 | 图像不可信（AEC 卡住或削顶） | 看 `MB_EXP_LOCK`(508) 是否被钉、`MB_CLIP_PM`(61) 是否 >10‰。解钉：`xsdb ps_fft_dual\aec_unpin_20261031.tcl`（写 508=0，再连读 36 s 的 exp / mean / aec / clip）。实测一例：钉 8662 时 clip 12‰ → 比较全拒；解钉后 4331、clip 4‰、`aec_state` 1 |
| 4 | 亮度差出范围（增益比不在 0.5–2.0） | 灯变了 → 重采背景 + 重取参考（一.3、一.4） |
| 5 | 配准没对上（含"年轻窗口"） | 停下后**约 8 s** 才能判（3 次真实比较、每 16 帧一次）。把板放回同一位置再等，不要连续催判 |
| 6 | 工件没完整在视野里 | 重新摆板 |
| 其它（含 7） | 不是交付镜像的码 | 记录数值、上报；不改参数 |

主机侧还有一道**噪声地板门**：`python dl\repeat_20261031.py --n 5 --tag rep` 得 `N_g`；
`2·N_g ≥ 限值` 时扫描工具（`python dl\pop_scan_20261031.py --noise-floor N_g`）打印 `NO DISCRIMINATION`，
CSV 写 `refused=1 / ng=NA`，**不投票**。地板 4 对限值 8 时，"读到一个 8"不是证据。

### 2. 参考只在一个固件会话内有效（操作规则）

**只要做过任一次 bring-up、重载固件、或断电重启，就必须重采背景并重取参考**，不许沿用上一会话的参考。

实测依据：bring-up 会重写 303 条 OV5640 表，把 AEC 工作点从曝光 **8662 移到 2105**，而帧均值只从 **509 变到 501**（‰）——
亮度闸门看不出这个变化，参考却已经不在同一个工作点上。（`dl\MULTIREF2_20261101.md` 第 59 行）

### 3. 传送带卡住

1. 先看 STM32 侧心跳：**500 ms 无心跳电机自动停**（实测 501 ms）。
2. 跑一次停/落测试：
   `python dl\belt_reg_20261101.py --port COM8 --runs 5 --seconds 1.0 --duty 100`
   它逐次打印行程（格）、`MB_REG_STATE`、`MB_DIFF_OK`、`MB_DIFF_DX/DY`、`darea`。
3. 已知边界（实测）：占空比 40% / 70% 只嗡不动，**只有 100% 才带动皮带**；0.25 s 点动完全不动；
   单次 1.0 s 行程 **5 / 14 / 18.5 / 32.5 格**（2–13 mm），打滑、不可重复，但都落在配准搜索 ±49 格（±19.7 mm）内。
4. 停下后要求 `reg_state=1`、`diff_ok=1`；不满足就不要再往线上放板。
   CH340 现在在 **COM8**（不是 COM6）。

### 4. 灯变了（换灯 / 调亮度 / 开环境光）

重采背景 + 重取参考（一.3、一.4），**不是调阈值**。
判据：参考与活帧亮度差 >10% 应拒判（实测 1.6× 差 → 假残差 62 格，限值 8；1.15× 差仍可接受）。

## 三、维护

### 1. 灯与皮带

- **灯**：显微镜 LED60 环形光，12 V，亮度按取参考时的那一档固定。
  画面整体变暗或削顶，先读 `MB_CLIP_PM`(61)、`MB_AEC_MEAN`(151)、`MB_AEC_STATE`(144)，再决定解钉或换灯；
  **换灯后必须重采背景 + 重取参考**。
- **皮带**：空载 1.0 s / 100% duty 应能看到位移（5–32.5 格）。不动先查 STM32 心跳与 COM8。

### 2. 备份 / 恢复（改任何文件之前）

```
python dl\backup.py save <改动名> <文件或目录> [更多…]   # 写 backups\<时间戳>__<改动名>\，SHA-256 记进 MANIFEST.txt
python dl\backup.py list                                  # 现有备份与各自的文件数
python dl\backup.py verify <时间戳目录名>                 # 校验备份本身与 MANIFEST 是否一致
python dl\backup.py restore <时间戳目录名>                # 回写并按哈希逐个校验；回写前自动另存 pre-restore-of-…
```

`restore` 会**覆盖**当前文件，回写后自己校验哈希——"拷过去了"不等于"文件对了"。

### 3. 核心挂死（画面停 / 日志报 CORE HALTED）

按顺序执行，一步都不许跳：

```
xsdb ps_fft_dual\bringup_now_20261029.tcl
xsdb ps_fft_dual\disp_fix_20261023.tcl
xsdb ps_fft_dual\strict_load_cores.tcl
```

然后回到 **一.3 / 一.4 / 一.5**：重采背景、重取参考、核对 FWID。
（这三步就是"一个固件会话"的边界：换了会话，上一份参考作废。）
