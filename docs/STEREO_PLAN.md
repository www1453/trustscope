## 一、硬件事实（已核实）

**板上装的是黑金双目摄像头模块 AN5642**（两颗 OV5640），插在 J10。
**当前设计只接了其中一路**（`cmos_*_0` / `IIC_0_0`），第二路完全闲置。

厂商文档第 23 章原文：

> 「单目摄像头工程我们使用 2 个 VDMA……双目就**需要 4 个 VDMA**」
> 「这里使用 **HP0 和 HP1** 端口，2 × 64bit × 150MHz，完全满足 2 路视频输入输出的带宽要求」
> 「还有一点要修改的是，将**两个 IIC 都设置成 EMIO 输出**，配置**两个 cmos sensor**」

**两颗传感器各自独立的 I2C 与独立的复位** —— 双目最经典的"同地址冲突"坑，厂商已解决。

## 四、双目能给出什么精度（先算再做）

```
视差      d = f_px · b / z
深度分辨率 ∂z/∂d = z² / (f_px · b)

取 z = 150 mm（工作距离）
    b = 60 mm（AN5642 两传感器的基线，**待实测确认**）
    f_px = 1920（1280 px 覆盖 100 mm 视场）
⇒ ∂z/∂d = 150² / (1920 × 60) = 0.195 mm / 视差像素
⇒ 亚像素配准 0.1 px → 理论 ~0.02 mm；工程实际预期 ~0.1–0.5 mm
```

**能测的**：元件高度、缺件、翘曲、连接器是否到位（**装配级三维**）。
**不能测的**：划痕深度（~10 µm 量级）—— 那是共聚焦/干涉仪的活，不是双目的。

> **这条"不能测什么"必须写进报告** —— 它体现的是判断力，而不是掩饰。

## 五、双目 + 环形光的配合（含一个真实的失效模式）

**环形光对 PCB 有利**：PCB 的反照率纹理（绿油/白丝印/铜盘/元件体）在左右两幅图里长得一样，
**正是立体匹配最需要的**。我早前说过"环形光让立体匹配更难"，**那句只对空白金属成立，对 PCB 不成立**，此处更正。

**但有一个真实失效模式**：

> **镜面高光是视角相关的。** 焊点、金手指、光面元件在左右相机里的高光位置不同，
> 破坏了立体匹配"同一点在两幅图里长得一样"的假设 —— **偏偏失效的地方就是焊点。**

| 区域 | 匹配 |
|---|---|
| 绿油/丝印/焊盘/元件体（漫反射） | ✅ |
| 焊点/金手指（镜面） | ❌ |

**对策（按成本）**：
1. **交叉偏振片**（光源前一片 + 镜头前一片，正交）—— ¥20–40，最便宜
2. **穹顶光**替代环形光 —— 把点状高光摊成柔光，两视角趋于一致
3. 匹配算法内做**高光剔除**（左右一致性检查）—— 纯软件

**环的摆放**：套在**其中一台镜头**上，或**居中于两台之间**。居中时两台看到的照明对称性最好。

原先以为"加第二个 ov5640 + VDMA"就够。侦察后看清实际是：

1. 第二个 `alinx_ov5640` 实例 + 时钟/复位接入

# 十一、第二次侦察结果（2026-10-15）：**没有空闲主端口**

`stereo_recon2.tcl` 已跑（只读）。关键输出：

```
cell mem_intercon_cap
  NUM_MI = 1                                   <- 只配了 1 个主端口
  NUM_SI = 1
  /mem_intercon_cap/M00_AXI  <->  /mem_intercon_cap_M00_AXI   <- 已连接、已占用
cell mem_intercon_disp
  NUM_MI = 1
  /mem_intercon_disp/M00_AXI  <->  /mem_intercon_disp_M00_AXI <- 已连接、已占用
```

**结论：第二路采集不能"接上去就行"。** 按原方案必须把 `mem_intercon_cap` 的
`NUM_MI` 从 1 改成 2 —— **那是动互连本体**，比加一个 IP 重得多、也更容易出错。

> 我第一次侦察查的是 `ps7_0_axi_periph/M*`（**AXI-Lite** 互连），
> 而第二路采集要加的是 **`mem_intercon_cap`（内存互连）** —— **查错了对象**。
> 与 B13/B14 同族：判断依据选错了。

## 所以换一条路线：用 `axis_switch` 复用现有采集链路

原方案 = 第二个 VDMA + 改互连端口数。
替代 = **两路视频流汇到一个开关，复用现有的那一个 VDMA**：

```
alinx_ov5640 (cam1, cmos_*_0) ──┐
                                ├── axis_switch (2->1) ──> 现有 axis_subset_converter_0
alinx_ov5640 (cam2, cmos2_*)  ──┘        ↑                          │
                                   PS 用一位 GPIO 控制选哪路          v
                                                           现有 axi_vdma_0 (S2MM)
                                                                    │
                                                          SEG_..._HP1_DDR_LOWOCM
```

| | 原方案（第二个 VDMA） | **axis_switch 方案** |
|---|---|---|
| 改互连 `NUM_MI` | ✅ 必须 | ❌ **不用** |
| 新增 VDMA | ✅ 要 | ❌ **不用** |
| 地址分配 | ✅ 要 | ❌ **不用** |
| 复用现有采集链路 | ❌ | ✅ 完全复用 |
| 两路同时采集 | ✅ 可以 | ❌ **交替**（不能同时） |

**代价可接受的理由**：**我们的工件是静止的。**
测一个不动的工件，交替采两路等价于同时采 ——
**这正是"停带式"的同一个思路：把"同时性"要求换成一个"时序"要求，工程上便宜得多。**

**不成立的情况**：若工件会动（例如在运行的传送带上），两帧之间的间隔会引入运动差异，
那时必须回到"停带"或"第二个 VDMA"。
