# 大模型协作记录

## 一、项目与协作范围

本项目面向裸 PCB 外观缺陷检测，由团队完成需求分析、硬件搭建、检测方案设计、数据采集和实物验证。系统以 ALINX Zynq-7020 为板端检测平台，结合相机、显示面板、传送带及电机控制模块，实现图像采集、自动停带、缺陷框选和合格性判断。

本记录以团队提供的协作材料为依据。原始调试记录覆盖 **2026年9月25日至10月27日**；本文于2026年11月4日整理，并依据团队后续说明补充核心方案及分工。后续补充不视为上述日期范围内的原始实验记录。

**团队是项目方案的提出者、实施者和最终决策者。大模型主要承担资料查询、代码检查、问题排查建议、部分辅助代码与脚本生成，以及文档和展示素材整理。** 模型输出作为候选建议，由团队结合代码、实验条件及实物结果决定是否采用。

## 二、团队独立思考与完成的核心工作

以下核心方案来源及分工依据团队本次说明整理。

1. **明确检测任务。** 团队选择裸 PCB 作为检测对象，确定采集、传送控制、板端检测和结果展示相结合的实现目标。
2. **设计检测方法。** 团队提出以良品图像为参考，先对齐待测图像，再按网格比较亮度差异，并根据相连异常区域的规模判断是否不合格。
3. **自制并保存数据。** 团队拍摄良品与缺陷样本，保存图像，确定样本身份、摆放条件和参考板。数据集用于参考建立、调试及验证；仅采集数据并不等同于进行了神经网络训练。
4. **搭建与联调硬件。** 团队完成相机、开发板、显示面板、传送带和电机控制模块的安装、接线与现场操作，并调整拍摄位置及成像条件。
5. **验证和决定改进方向。** 团队通过好板复测、换板、位置变化及缺陷样本测试检查方案，决定参数、代码修改和新增功能是否采用。

当前检测方法可概括为：

> 拍摄并保存良品参考图 → 获取待测 PCB 图像 → 图像配准 → 网格亮度比较 → 相连异常区域统计 → 不合格判定与异常框选。

团队当前描述的异常区域门槛为“8个格子以上”。正式技术报告应与当前固件核对比较条件究竟为 `>= 8` 还是 `> 8`，并说明单格亮度差阈值和连通规则。配准用于补偿一定范围内的位置及角度变化，不表述为任意歪斜均可对齐。

## 三、人机分工

| 工作 | 团队承担的内容 | 大模型辅助内容 |
|---|---|---|
| 需求与总体方案 | 确定检测对象、目标和硬件方案 | 查询资料、帮助比较实现条件 |
| 核心检测思路 | 提出良品参考、配准、网格差异和相连区域判定方法 | 检查逻辑盲区、提出边界情况和验证建议 |
| 数据与实验 | 采样、编号、摆板、操作设备、确认真值 | 协助编写统计脚本、整理数据及分析可能原因 |
| 软件实现 | 集成工程、检查修改、联调并确认功能 | 审查代码，提出或生成部分局部修正及辅助脚本 |
| 参数与方案取舍 | 根据样本及实测结果作出决定 | 给出候选参数分析和实验设计建议 |
| 交付材料 | 确认事实、审核并确定最终提交版本 | 整理交接文档、润色视频稿、生成示意图片 |

原始记录涉及智能体修改代码、生成诊断脚本和执行部分工具操作，因此不能将 AI 的参与写成“只检查文字、未参与任何代码”。这些辅助实现与团队提出核心方案是两个不同层面的贡献，应分别说明。

## 四、协作过程与提示词组织

团队向大模型提供当前问题、代码或日志、现场现象及限制条件。模型提出检查方向或候选修改后，团队核对其与工程的关系，再进行必要的实物测试。实验结果不支持模型判断时，保留原记录并修正结论。

工作流程为：

> 团队提出问题并提供证据 → AI 辅助检查与提出建议 → 团队审核 → 按授权开展局部修改或离线分析 → 团队现场验证 → 决定采用、回退或继续调查 → 保存记录。

提示词宜包括现场证据、具体任务、验收条件、停止条件、时间或构建预算以及操作边界。已有测量可作为背景，但如果数据新鲜度、版本或测量方法存在疑问，仍应复核。

以下为依据实际协作方式整理的**示例提示词，不是原始对话逐字引文**：

> 请检查我们已有的参考图对比检测程序。重点检查配准后的坐标、有效区域、网格差异及相连区域统计是否一致。给出具体代码位置、触发条件和验证步骤；无法从材料确认的内容请标明，不自行改变判定阈值或宣称硬件验证通过。

> 这是好板与缺陷板的本次测量结果。请检查字段定义、参考版本和样本标签是否一致，分析哪些结论有数据支持、哪些仍需补测。提出修改前先说明预测现象和验证方法。

若提交材料要求真实提示词及模型回答，应附可核查的会话导出或原始任务书。示例提示词和事后总结不能代替真实对话记录。

## 五、代表性问题及纠正过程

以下案例摘要来自团队提供的原始协作记录。本次文字修订未获得其对应的完整仓库、提交历史、技术报告和全部实验日志，因此保留为“原记录所述”，不作独立复核结论。详细数值及引用保存在随附原始记录中。

| 案例 | 原记录中的问题 | 纠正与检查方法 | 团队的判断职责 |
|---|---|---|---|
| 相机匹配区域 | 全画面匹配混入桌面、地面等背景，影响对板面几何关系的判断 | 限定板面区域，再用独立方法复核 | 确认目标区域与拍摄条件，不直接采纳模型首次估计 |
| 多帧平均评估 | 用空间差异统计量推断时间噪声改善，比较口径不一致 | 区分空间残差与帧间噪声，在相同条件下比较 | 根据测量对象限制结论范围 |
| 参考质量检查 | 读取集合缺少检查所需字段，缺失值导致流程拒绝继续 | 补齐字段，并区分读取故障与参考质量不合格 | 核对板上实际状态、检查修正效果 |
| 新统计量探索 | 部分候选指标在正常样本复测中也产生较大响应 | 先做正常样本基线检查，再决定是否扩展实验 | 判断新增指标是否具有区分价值，不直接接入最终判定 |
| 批量测试流程 | 首个基线样本已暴露问题，流程仍继续运行 | 增加人工复核及停止条件 | 及时终止无效实验，修正测试安排 |
| 共享资源与样本标签 | 多工具访问、并发改文件及样本转述造成状态歧义 | 串行使用板上调试资源，明确文件写入者，现场确认样本编号 | 负责设备操作、标签真值及实验条件确认 |

这些记录说明模型建议需要检查，不能说明某一种检测方法普遍无效，也不能用少数样本推导准确率。并发操作与掉线同时出现可作为排查线索，但仅凭时间重合不能确定因果关系。

## 六、采用建议的边界

- **方案与阈值由团队确认。** 模型可以辅助分析，但未经确认不改变正式判定条件。参数选择应尽可能区分调试样本与独立验证样本，避免用同一批样本调参并证明效果。
- **现场事实由操作者确认。** 更换板件、复位和拍摄条件不能仅由文字转述推定完成。
- **板上操作明确授权和版本。** 烧写、复位及更换参考可能影响实验状态，应按实际工程记录影响范围。模型执行过的授权操作如实记录。
- **候选指标先验证再接入。** 先检查正常样本重复测量的变化，再评估缺陷响应；是否满足要求由应用容差与数据决定，不将“必须相差一个量级”作为普遍标准。
- **结论与证据对应。** 区分建议、已修改、已编译、已仿真和已上板验证，不以编译通过代替功能验证。

## 七、证据保存与记录要求

每次重要协作尽量保存日期、问题、实际提示词、模型回答、团队判断、采用的修改、验证结果及相关文件。代码位置应同时绑定版本或提交号，避免文件改动后行号失效。

原始记录列有 E1—E6 的文件及提交索引，可作为补充证据清单；提交前应核实文件存在、版本对应、数据定义一致。未入库文件可以在另行归档并提供来源、版本或校验值后作为证据，不能简单认定“未被Git跟踪就没有证据”。仅有会话描述、没有原始输出的数值应注明来源和限制。

原稿引用的比赛条款编号、技术报告章节及任务书引文，应与实际提交版本逐项核对。没有提供全文的材料，本记录不声称已经核实。

## 八、协作总结

团队围绕裸 PCB 检测独立思考并确定核心方法，完成硬件搭建、数据采集、系统集成和实验验证。大模型用于辅助检查已有方案与代码、提出排查建议、生成部分辅助实现，以及整理交付材料。最终设计取舍、参数确认、实验判断和作品提交由团队负责。

对于模型给出的错误或证据不足的判断，团队依据实际测量修正或放弃；对被采用的建议，保留其来源、修改内容及验证结果。上述分工既说明团队的主体贡献，也保留 AI 实际参与工作的范围。
