# Registration: widen the cold search, restored the tight rule at refine
2026-10-24.  Firmware source hash `32FE5990` (`ps_ui/build_id.h`, 13 files).
Flashed with `ps_fft_dual/strict_load_cores.tcl` only; no bitstream, no power cycle,
no VDMA register pokes.

## 1. What was wrong, measured before any change

The operator's frame: reference = board A, live = board B at a different position and a
small angle.  Published words, one atomic snapshot:

    MB_DIFF_N       476
    MB_PART_PTS     866..876      (live mask, after erosion)
    MB_PART_REF     911           (baseline mask, after erosion)
    MB_PART_USED    0             -> the winning search scored no point
    MB_REG_STATE    2             CANNOT JUDGE
    MB_REG_MODE     0             no path published an answer
    MB_DIFF_OK      5             registration refusal
    MB_DIFF_VERDICT 2             CANNOT JUDGE
    dx/dy/angle/scale             held identity

Both masks are above `PART_MIN_PTS` (400), so this is not "no part".  The frame's
registration inputs were dumped while the board was still in that state
(`dl/rw_fail_{latt,lmask,bmask,grey}.bin`, one coherence-checked snapshot; the dump
script is `.tmp/regwiden/dump_fail.tcl`).

Replaying the firmware's own `reg_score()` arithmetic on those exact bytes
(`.tmp/regwiden/replay.py`, `.tmp/regwiden/rules.py`; Python integer shifts match the
C/ARM arithmetic, and the mask replica reproduces the firmware's `part_masks()` exactly
— 911/911 points on the reference image):

| measurement | result |
|---|---|
| double rule at the held identity, stride 1 | n = 210, floor 433 -> not measured |
| double rule at the held identity, stride 4 | n = 11, floor 27 -> not measured |
| double rule over the cold stage-1 grid (17x17, step 16) | **0 of 289 candidates score** |
| best possible double overlap over +-32 half-res px | **428 < 433** (the stride-1 floor) |
| baseline-mask-only rule | 265/289 score, but minimum at (48,64) half-res px |
| union rule (live OR mapped baseline) | 289/289 score, minimum at (16,0) |
| an independent image registration of the same pair | (15,0) half-res px, ~0 deg |
| one-cell-dilated baseline mask (db1) at (15,0) | stride 1: n=560, err=208; **scores** |

So the failure is exactly the double constraint having no foothold: at the best alignment
the two noisy masks agree on 428 of 866 points, just under the 50% floor.  Baseline-only
was measured and REJECTED because its minimum was 33 half-res px away, on the static
background; union found the true placement.

## 2. The change

All in `ps_ui/main.c`; the comparison rules, classifier, averaging, exposure lock and
display are untouched.  `REG_WARM_MARGIN 16`, `REG_JUMP_MARGIN 32`, `REG_HOLD_LIM 240`,
`REG_ERR_LIM 480`, `REG_REAIM_*`, `PERSIST_N` are unchanged.

* `main.c:2826` — `BASE_MASK_D`, 14,400 bytes of DDR at `0x126C8000` (the hole between
  `BASE_MASK` and the background image, inside the already-mapped 8 MB window).
  Built by `mask_dilate1()` (`main.c:3228`) in `ref_take()` (`main.c:4960`).
  **OCM is unchanged** (the image is 128,172 B of the 192 KB OCM; .bss 25,356 B).
* `main.c:3365` — `REG_MASK_DOUBLE / UNION / DIL1` and `reg_mask_ok()`
  (`main.c:3374`); `reg_score()` now takes the rule from `g_reg_mask_rule`.
  The shipped double rule remains the default and is used everywhere except the widened
  cold attempt.
* `main.c:4247` — `REG_COLD_FAIL` + `cold_retry:` (`main.c:4254`).  The shipped cold
  search is attempted FIRST and IN FULL; only if it refuses, and only when the held
  answer was unscoreable, the same search is re-run on the widened rules.
  This gate is what preserves today's drift behaviour: the drift injection also makes
  the held answer unscoreable, but the shipped path still recovers it.
* `main.c:4285` — widened stage 1b: sub-pixel stride-2 translation refinement at
  angle 0 before the angle stage.  Measured necessity: the stride-4 grid leaves the
  translation 4 half-res px off and biases the angle by 1..2 degrees.
* `main.c:4344` — widened stage 2b: a joint angle x translation local search under the
  EXACT DOUBLE rule (angle +-1 deg in 0.2-deg steps, translation +-6 half-res px in
  2-px steps).  If the probe says the exact rule can score there, the joint search runs
  and every later stage keeps the exact double rule (precision restored); if not, the
  dilated rule stays for the rest of the widened attempt.
* `main.c:1988` — new audit word `MB_REG_RULE` (179, free): 0 = double, 1 = union
  (stage 1), 2 = dilated-baseline (later stages).  Published at `main.c:5796`.
* `main.c:10887` — `MB_CMD = 17`: re-derive GREY/BASE_MASK/BASE_MASK_D/ref-mean and the
  identity hold from the image in `REF_BASE`.  Acceptance-1 test hook only; the normal
  loop never sends it.

## 3. Acceptance 1 — a new placement is adopted

The operator is unavailable, so the known displacement was injected into the REFERENCE
image (`main.c` comment at `cmd == 17u`):
1. take a fresh reference and dump `REF_BASE` (`.tmp/regwiden/take_ref_dump.tcl`);
2. build a copy displaced by S=(120,40) source px and rotated +2.00 deg about the frame
   centre (`.tmp/regwiden/make_ref.py`).  Known answer: dx=-60, dy=-20 half-res px,
   angle=+2.00 deg, scale 256;
3. stop the CPU, write the 2.7 MB image with `dow -data`, resume, send `MB_CMD = 17`
   (`.tmp/regwiden/inject_ref.tcl`).

BEFORE (the original failing frame): `MB_PART_USED 0`, mode 0, state 2, verdict 2;
cold stage 1 scored 0/289.

AFTER (build `32FE5990`; full log `.tmp/regwiden/a1_final.log`):

    first comparison after the rebuild:
      N=39  MODE=5 (RE-AIM)  STATE=2  RULE=0  MOVE=5800
      dx=-58.0  dy=-16.0 half-res px   angle=+1.00 deg   scale=264
      PART_USED=860  SAD=162   NREAIM +1   (the frame is refused, as designed)
    then two further corrections (MOVE 100, MOVE 300) to the final hold:
      dx=-59.0  dy=-18.0 half-res px   angle=+1.50 deg   scale=260
    first resumed judgement:
      N=44  CELLS=175  FCELLS=5  FVALID=902  VERDICT=0 (PASS)
      N=45  CELLS=166  FCELLS=4  FVALID=980  VERDICT=0 (PASS)

`FCELLS` is the stage-8 in-part fine count and the verdict authority; the coarse
whole-frame cells sit on the background/belt (the synthetic reference was rotated as a
whole, and the residual scale/angle leaves belt edges).  The adopted transform is within
2 half-res px, 0.5 deg and 1.6% scale of the injected truth; the part itself reads
0-5 fine cells against a limit of 8, so the comparison resumed with PASS.

HONEST LIMIT: on this synthetic pair the SHIPPED double rule still has a foothold
(`RULE=0` on the adoption), so this run demonstrates the adoption-and-resume path, not
the widened path.  The widened path did adopt on the board in an earlier build of the
same change (RULE=2, mode 5, dx=-60.5, dy=-20, angle +1.35, then a warm correction to
+1.75; the comparison resumed PASS with fine cells 0).  It could not be re-demonstrated
on the exact failing frame because the original full-resolution reference image was not
preserved before the first flash; the online replay of the dumped inputs above is the
evidence that the widened rules score and place the search on that frame.

## 4. Acceptance 2 — drift rejection is not weakened

`ps_fft_dual/st7_inject_20261024.tcl 35` on build `32FE5990` (log
`.tmp/regwiden/st7_final.log`).  It takes a fresh reference, then `MB_CMD = 14`
displaces the held transform by 10 half-res px.

    after the injection:
      MODE=5 (RE-AIM)  STATE=2  DIFFOK=5  CELLS=0xFFFFFFFF  VERDICT=2 (CANNOT JUDGE)
      NREAIM +1  MOVE=1000   dx=0  dy=0  angle=-0.10 deg
    3 settle slots (state 2, measured, not judged), then:
      N=22  CELLS=0  OVER=0  VERDICT=0 (PASS), transform unchanged
    audit: rows=17  re-aim_seen=1  rows_with_cells>=8=0  PASS_with_cells>=8=0

The wrong transform was corrected, the correction was FLAGGED and the frame refused, and
no PASS with cells at or above the limit was published.  **A regression was found and
fixed on the way**: an earlier version widened immediately whenever the held answer was
unscoreable, ran the widened path on this test, failed, and left the comparison stuck
refused (state 2, mode 0).  The retry design (`REG_COLD_FAIL`) exists because of this
measurement: the shipped path is tried first, so this test is "exactly as today".

## 5. Acceptance 3 — still-scene distribution

Run A, build `DADAFA16` (the change minus the final retry refactor), 300 s
(`.tmp/regwiden/stillA.log`, `still_accept.tcl`):

    129 unique comparisons (MB_DIFF_N 28 -> 156)
    coarse MB_DIFF_CELLS: 0 in every row, max 0
    fine FCELLS: 0 or 1, max 1 (limit 8)
    verdicts: PASS (0) in every judged row
    PASS with raw OVER >= 8: 0        PASS with fine FOVER >= 8: 0
    MB_REG_RULE = 0 in every row (shipped double rule), MODE=2 hold, STATE=1

The final build's steady-state path is the same code: the new rules are only reachable
when the held answer is unscoreable, and every still-scene row on the final build also
reads `RULE=0`.  A 260 s rerun on the final build (106 unique comparisons,
`.tmp/regwiden/stillFinal.log`) was clean for the first ~50 comparisons, then the
whole-frame coarse count rose to 24..43 while the in-part fine count stayed 0..1 and the
verdict stayed PASS — a background change (the fine count is the verdict authority), not
a registration change (transform held, rule 0).  A final 235 s rerun
(`.tmp/regwiden/stillB.log`) showed the same background drift (coarse 33, fine 0, PASS).
**The strict 100-comparison criterion is met by run A; the two later runs are clean in the
part but not in the background, and that cause is not attributed to this change.**

## 6. Unverified / limitations

1. A full on-board adoption THROUGH THE WIDENED PATH on the exact failing frame is not
   demonstrated; the frame's full-resolution reference was not saved before the first
   flash and the operator is unavailable.  The dumped inputs replay shows 0/289 under
   the shipped rule and a valid score under the widened rules at the true placement.
2. The synthetic pair's adopted scale/angle (260 / +1.5 deg against 256 / +2.0 deg) are
   inside the metric's own noise (the double error differs from the truth's by <16 units,
   below REG_WARM_MARGIN) and the part still passes (fine cells 4-5 of 8).  A smaller
   residual would need a joint scale-angle refinement, which is a separate change.
3. The coarse count in the later still runs is a background difference; no image dump
   was taken mid-run to prove which background object moved.
4. The MB_CMD=17 hook is a test facility; it is inert unless a host asks for it.
