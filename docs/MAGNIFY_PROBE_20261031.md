# 收窄视场：厂商序列找到了，cam1 上已经跑通（2026-10-31 18:3x）

## 1. 第一次尝试失败（已回滚）

只改窗口 + 增量（`0x3814/15=0x11`、窗口收成 1280×720），图像坏成**横向条带 + 右侧错位重影**。
回滚用项目表格里那条 720p 序列（18 个写），图像恢复正常（有图为证）。

**失败的教训**：1:1 裁剪不是"改窗口"，它换的是整个读出模式，`0x3820/21`、HTS/VTS、
`0x3618/3612/3708/3709/370C`、以及 AEC 的 `0x3A02/03`、`0x3A14/15` 都必须一起变。

## 2. 厂商资料在哪里

`ps_fft_dual/vendor/camera_doc/YX70171-OV5640摄像头-190509/其他参考资料/OV5640_camera_module_software_application_notes_1.3_Sonix.pdf`
（100 页，Sonix 的模组应用手册）。第 66 页就是**一条 1:1 裁剪模式**：

```
page 66:  x 336..2287  y 434..1522   1920x1080   inc 0x11/0x11   HTS 2500   VTS 1120   0x3820/21 = 0x41/0x26
page 71:  x 0..2623   y 250..1705    1280x720    inc 0x31/0x31   HTS 1892   VTS 740    0x3820/21 = 0x41/0x27
```

**差别里最关键的一位是 `0x3821`：`0x26` 是 1:1，`0x27` 是抽取。** 第一次失败就是漏了它。

## 3. 按同一套算术缩到 1280×720

| 寄存器 | 厂商 1920×1080 裁剪 | 本次 1280×720 裁剪 | 依据 |
|---|---|---|---|
| 0x3820 / 0x3821 | 0x41 / 0x26 | 0x41 / 0x26 | 直接沿用（1:1 位） |
| 0x3814 / 0x3815 | 0x11 / 0x11 | 0x11 / 0x11 | 直接沿用 |
| 窗口 x | 336..2287（1952） | 672..1951（1280） | 居中于 2624 |
| 窗口 y | 434..1522（1089） | 616..1335（720） | 居中于 1952 |
| HTS 0x380C/D | 2500 = 1952+548 | **1828** = 1280+548 | 保持同样的消隐 548 |
| VTS 0x380E/F | 1120 = 1089+31 | 1200（固件本来写这个） | 运行时值 |
| 0x3810/11, 0x3812/13 | 0x0010, 0x0004 | 同 | 直接沿用 |
| 0x3618/3612/3708/3709/370C | 04/2B/64/12/00 | 同 | 直接沿用 |
| 0x3A02/03, 0x3A14/15 | 0x0460 | 0x04B0（=VTS 1200） | 与 VTS 一致 |

## 4. 结果（cam1，只动它）

- 29 个写、0 个失败；
- 回读：`0x3820=0x41`、**`0x3821=0x26`**、`0x3814/15=0x11`、窗口 0x02A0/0x079F/0x0268/0x0537 全部到位；
- 图像：**干净**（行均值差 0.56，无条带无重影），与回滚后的图在构图上是同一场景；
- 统计：`mean=407 clip=0`，`pts=518`、`diffok=6`（刚改模式，需要重新收敛）。

**一个没有做到的确认**：我试过用相位/相关法证明"新图 = 旧图中心 2×"，**没有分辨力**
（新/2 与旧中心半幅 NCC 0.579，随机平移的对照 0.589，两者分不开）。所以"视野真的只剩一半"
目前只有**寄存器回读**（E1）支持，没有场景级证据。**真正的确认必须来自实验数据本身**：
划痕在图像里的像素宽度应当从 1–3 px 变成 2–6 px。
