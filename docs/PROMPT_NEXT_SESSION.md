## 2. 任务 A：融合的 bug（已经定位到，差修复）

### 现场证据（不要重新测，直接采信）
| 配置 | MEAN |
|---|---|
| 单曝光，long=10000 | **17** ✓ |
| 融合开，long=10000 / short=1538 | **5** ✗ |

**5 恰好等于 1538 行短曝光的亮度。**

### 代码事实（`ps_ui/main.c`）
- 融合只重写 `>= FUSE_CLIP (248)` 的通道，其余通道**保留 long 的值**（`RESCUE` 宏，约 line 1046）；
- 所以若融合输出看起来像 short ⇒ **渲染当作 "long" 的那个缓冲区，装的是短曝光相位采的图** ⇒
  **`g_short_phase` 的翻转与缓冲选择差一帧**。

### 修法方向（不要盲改）
每帧"哪个缓冲装哪次曝光"的关联，必须与**该帧采集之前**写入的曝光一致，而不是之后的。
需要检查的位置：`g_short_buf` 的赋值、主源缓冲（`g_long_buf` / `g_cam`）的赋值、以及 `g_short_phase ^= 1` 这三者的**时序先后**。

### 验收判据（三条同时满足才算修好）
```
1. 程序自报 long exposure at/over clip = 0 (0.00%)
2. CLIP_PM < 10‰
3. MEAN 在 80–100 之间（与同一时刻的单曝光 MEAN 相当，不能低一半）
```

### 调试纪律（今天在这里翻车过）
- **不要靠看画面反推**，而要**在代码里打印每帧的 `g_short_phase` 与所选缓冲索引**，从串口/mailbox 读出来对；
- 改完**必须 `Select-String` 确认那一行真的变了**（今天有两次"以为改了其实没改"：PowerShell 转义吃掉补丁、工作目录错导致绝对路径找不到）。

## 3. 任务 B：缺陷定位（坐标 + 尺寸）

### 已有基础
- `measure()` 已在全分辨率 `g_cam`（1280×720）上按 stride 8 抽样，**已算出强边缘计数** `MB_EDGES (148)`；
- 判据：水平梯度 `d >= 40` 计为一个强边缘点（划痕/缺件/异物的共同特征）。

### 要做的（最省算力的粗定位，不做完整连通域）
```
1. 在采样循环里，把强边缘点累加到一个 32×32 的网格计数数组（g_edge_grid[32][32]）
2. 每帧结束后扫描该网格，取计数最大的 3–5 格
3. 每格换算成毫米坐标：cell_px = (1280/32) = 40 px；mm 坐标 = 格坐标 * 40 * (mm_per_px)
4. 尺寸估计 = 该格及相邻格的强边缘点数 × 采样间距换算出的物理长度
5. 通过新邮箱字发布：MB_DEFECT_N（数量）、MB_DEFECT_X/Y/W/H（第一个缺陷，像素坐标）
6. 面板或上位机显示
```

### 必须先定的量
- **mm/px（像素当量）**：放一把钢尺在视野里，量 100 mm 对应多少 px ⇒ 这是所有"缺陷尺寸"的物理意义来源；
- **没有它，只能说"多少像素"，不能说"多少毫米"** —— 交付文档必须写清这个换算。

### 验收判据
在 PCB 上人为制造一个已知缺陷（划一刀 / 拆一个电容），确认：
```
1. MB_DEFECT_N 从 0 变成 ≥1
2. MB_DEFECT_X/Y 落在缺陷的实际位置附近（±1 格 = ±40 px）
3. 尺寸估计与实际尺寸同一数量级
```

## 4. 必须遵守的流程纪律（今天用一整天代价换来）

### 4.1 只改程序 ⇒ 只跑 `ps_run`
```
只改程序（main.c 等）  ⇒  xsdb ps_run.tcl          ← 不烧 PL，屏不受影响
改了 BD / 换比特流     ⇒  才跑引导 + ps_run         ← 会烧 PL，之后屏可能锁存
```
**烧比特流的只有一处**：`stereo_bringup_byname.tcl:251  fpga -file $BIT`
**`ps_run.tcl` 不烧比特流**（只有 `dow` 下载程序）。

### 4.2 屏显示异常 ⇒ 只给屏断电
面板**没有保持/重绘机制**，重烧 PL 后可能锁存一帧垃圾。
**动作：给屏断电重插。不要重启板子**（重启会清掉寄存器状态，让后续判断失去依据）。

### 4.3 判断"寄存器写进去了没有" ⇒ 读寄存器，不要看画面
今天在这一点上错了四次（把"画面变亮/变暗"当成写入成功/失败），而真实情况是：
程序写与主机写**都是好的**，画面暗是因为场景/曝光。

### 4.4 改完必须验证文件真的变了
```powershell
Select-String -Path ps_ui\main.c -Pattern '<你改的那一行>' | ForEach-Object { $_.Line.Trim() }
```
**不要相信脚本打印的"成功"。**

### 4.5 场景会变，数值不可跨时刻比较
曝光、照明、板子位置任一变化 ⇒ `MEAN`/`CLIP`/`FOCUS` 都不可与上一次比较。
**⇒ 每次调参必须在同一次会话内连续测量。**

### 4.6 硬件对应关系（已验证，别再猜）
```
I2C0 (0xE0004000) → **左**相机（面板 LEFT CAM）
I2C1 (0xE0005000) → **右**相机（面板 RIGHT CAM）
```
判定方法（一次实验定死）：给两条总线设 6 倍差异的曝光，**哪个视图亮就是哪条**。

### 4.7 邮箱字（部分）
```
MB_VIEW=86   MB_ZOOM=147   MB_FOCUS=135   MB_EDGES=148
MB_CLIP_PM=61   MB_BRACKET=58（启动时被清零，主机写无效）
MB_TOUCH_OK=87   MB_TAP=92   MB_DEFECT_*（待新增）
```
**注意：程序启动会清零邮箱** ⇒ 主机写的"启动模式字"在程序读到之前就没了 ⇒
**要改这类行为只能改代码**，不要在主机侧反复尝试。
