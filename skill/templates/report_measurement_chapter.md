# 模板 · "试过了、量过了、失败了"的测量章节

> **适用场景**：你实现了两个新判据，测了，**都没成**。现在要写报告。
>
> 这件事只有三种写法，其中两种是错的：
>
> | 写法 | 后果 |
> |---|---|
> | 删掉这一节，当作没做过 | 下周会有人（可能是你）再试一遍，再失败一遍 |
> | 留着"未来工作：加一个 XX 判据（待验证）" | **这是错的**：它已经不是未来了，它被证伪了 |
> | **原地改写：已实现、已测量、已失败，并写清为什么** | 唯一诚实的写法，也是唯一对别人有用的写法 |
>
> 本模板来自本项目的第十五章：两个"便宜的修法"在一天之内被实现、测量、失败，
> 章节因此从"未来工作"改写成"试过了、失败了"。

---

## 一、章节骨架（七节）

```markdown
## 十五、第二次测量：两个便宜的修法都失败了（<日期>）

### 15.1 这一轮测的是什么，证据是哪几份
   一句话 + 表格：每一份证据 = 文件 + 产生它的命令 + 时间戳。
   （评审不需要相信你，只需要能重跑。）

### 15.2 工作点：这个 sweep 支持的两个点
   把"限值 8 / 限值 10"各自的 漏检率 / 误报率 / 置信区间 并排列出。
   **不要只报一个点**：一个点看起来像选择，两个点才看起来像测量。

### 15.3 第一次验收：第一个摆位就是零
   null 的定义（同一个对象、同一次摆位、正确答案已知）、实测读数、以及判据。
   这是整章最重要的表：**如果 null 就已经越线，后面所有数据都不必采集**。

### 15.4 原因：两张掩模不是同一种输入建的
   根因，带**机制**，不是"可能是 XX"。本项目：参考掩模由单帧建、实时掩模由 8 帧平均建，
   所以两者的边界量化噪声本来就不同 —— 统计量在量这件事，不是量缺陷。

### 15.5 <修正名>：修法与重测 —— 极差好了一点，轮结局更坏
   同一张表，修前/修后两列。**中位数变好而尾部变坏是完全可能的**，
   只报中位数就是选择性引用。

### 15.6 两类缺陷的后果：角缺 0/3、划痕 1/6，原因在掩模的语义里
   把"这个统计量抓不到这类缺陷" vs "这类缺陷在这个工序不存在"分开写。

### 15.7 下一个设计：按颜色对手分割，比较四个顶点（**设计，不是结果**）
   明确标注这是设计，还没有数据。标题里就写清楚。

### 15.8 流程教训：第一次摆位就是零
   一条规则 + 它是在哪次失败里产生的 + 它现在是哪个脚本里的哪一行。
```

## 二、四张必须有表

| 表 | 列 | 为什么必须有 |
|---|---|---|
| **证据表** | 文件 / 产生命令 / 时间 / 用什么读的 | 没有它，本章是叙事而非记录 |
| **null 表** | 摆位 / 每一档阈值的读数 / 判据 | 这是"判据能不能用"的唯一证据 |
| **修前修后表** | 指标 / 修前 / 修后 / 变好还是变坏 | 防止"只看中位数" |
| **判决表** | 缺陷类别 / 抓到的数量 / 漏检率 | 让"失败"有一个可比的形状 |

## 三、写作纪律（每条都对应一次真实返工）

1. **数字后面跟来源**。`825`（stage L，`a3_null_20261027.tcl`，image `2E8B1A84`）
   —— 比"大约八百多"有用一百倍，也比"825"本身有用，因为它可核对。
2. **"已经跑过板子"要说清是哪一版固件**。本项目用镜像里自带的构建哈希
   （`fwid` 两个字）回答"板子在跑哪一版"，而不是靠"我记得烧过"。
3. **撤回的结论单独成段，不要悄悄改掉**。写法：

   ```markdown
   > **结论作废**：<原句>
   > 原因：<新证据，带数值与命令>
   > 影响：<哪些后续判断建立在它上面>
   > 已排除：<假设编号 + 一句话>
   ```

4. **"未验证"单列一节**，一行一个，写清"需要什么证据才能升级"。
   没有这一节，整章的可信度会掉回"作者说自己成了"。
5. **不要用"优化后性能提升明显"这类话**。写出：量的是什么、量了几次、
   两臂跨不跨过门槛。**没有预注册效应量的 A/B 只能说"未复现"，不能说"没有效果"。**

## 四、这一章写完之后的自检

- [ ] 章节标题里有没有"已实现/已测量/已失败"的事实，而不是"改进"？
- [ ] 每一个数字能不能在 `data/` 或 `report/` 里找到产生它的文件？
- [ ] null 表在不在？如果 null 已经越线，正文有没有明确写"因此没有再采集 population"？
- [ ] 修前/修后表里有没有一格是**变坏**的？（全绿通常说明只挑了指标）
- [ ] "未验证"一节覆盖的是不是**读者最关心的那件事**，而不是三个容易的？
- [ ] 删掉这一章之后，下一个人会不会重复这次失败？如果会，说明"为什么失败"没写够。
