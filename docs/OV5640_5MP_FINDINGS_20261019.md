# OV5640 5 MP（2592×1944）可行性核查（2026-10-19，全部离线）

## 1. 三个结论

| 问题 | 结论 | 证据 |
|---|---|---|
| 传感器能否 2592×1944 | **能**（原生 5 MP） | `CV-5021G2规格书.pdf` p4、`OV5640_Camera_Board_(C)_User_Manual_CN.pdf` p1 明写 QSXGA 2592x1944 |
| 厂商 C 代码有 5 MP 表吗 | **没有** | `ov5640.c` 只有两张表：800×600（L230–233）、1280×720（L273–276） |
| **数据手册里有 5MP 寄存器序列吗** | **有** | `OV5640 Auto Focus ... R2.12.pdf` **p18** 起：`0x3808=0x0a, 0x3809=0x20`（2592）、`0x380a=0x07, 0x380b=0x98`（1944） |

**⇒ 5 MP 不需要换模组，需要的是"组装一张表"。**

## 2. 已经抽出来的东西

`dl/ov5640_5mp_table.h` —— **139 条**，直接可用作 C 数组：

```
{0x3808, 0x0A}, {0x3809, 0x20},   // DVPHO = 2592
{0x380A, 0x07}, {0x380B, 0x98},   // DVPVO = 1944
...
{0x538B, 0x98},
```

生成脚本 `dl/extract_5mp_table.py`（可重放）；原文 `dl/ov5640_5mp_pages.txt`。

## 3. 但这不是一张"能直接推"的表 —— 两个缺口

| 缺口 | 说明 | 影响 |
|---|---|---|
| **缺 PLL/系统时钟**（0x3035/0x3036/0x3108） | 这些寄存器在同一份文档的**另一个模式块**里（p16），5MP 块里没有 | **决定像素时钟**；推错会没有图或帧率错 |
| **缺 DVP 输出配置** | 该文档是 **MIPI 接口**版本；0x4740（vsync 极性）、0x4300（输出格式）等要沿用我们现在 1280×720 那份 DVP 表的值 | 不配就是"有数据但格式不对" |

**所以：5MP = 139 条（新）+ 从现有表挑出的 PLL 与 DVP 配置**，需要一次上板调通。

## 4. 硬件侧的真实约束（读源码得到）

`alinx_ov5640.v`（214 行）**没有行缓冲**：8 位→16 位打包 → 4096×18 异步 FIFO → AXI-Stream。
**它与分辨率无关**，此前的"黑盒行缓冲可能不支持 2592"的判断已撤回。

真正的约束是**像素率 vs AXI 时钟**：

| 配置 | 像素率 | FCLK0=50 MHz 够吗 |
|---|---|---|
| 1280×720 @19 fps | 17.5 Mpx/s | ✅ |
| 2592×1944 @15 fps | 75.6 Mpx/s | ❌ 会溢出 |
| **2592×1944 @5 fps** | **25.2 Mpx/s** | ✅ **够** |

⇒ **5 MP 在现有硬件上可行，帧率约 5 fps**，而停带检测的节拍预算是 0.5–2 秒，够用。

## 5. 仍必须上板才能知道的一件事

**镜头 MTF**：5 MP 采样 0.025 mm/px，但若镜头在该尺度已糊，检测极限不会从 0.48 mm 掉到 0.1 mm。

判据（一次上板，一张图）：**量边缘 10–90% 过渡宽度**
- ≤2 px ⇒ 镜头够，5 MP 有意义；
- 6–8 px ⇒ 镜头是瓶颈，应换镜头而不是加像素。

## 6. 改动清单（若决定上 5 MP）

| 项 | 现在 | 改为 | 难度 |
|---|---|---|---|
| 传感器表 | 720p（303 条） | 5MP 139 条 + PLL + DVP 配置 | 中（需上板调） |
| VDMA HSIZE/stride | 3840 | 7776（24 位） | 低 |
| 帧存 | 2.76 MB | 15.1 MB/帧，四帧 60 MB | 中 |
| MMU 窗口 | 15 MB | ≥64 MB | 中 |
| 渲染缩放 | ÷2 | ÷4.05 | 低 |
| AXI 时钟 | 50 MHz | **不改**（5 fps 下够） | — |
| 相机 IP | — | **不改** | — |

## 7. 边界

- 139 条是**从 MIPI 版应用笔记**抽的，DVP 适配未验证；
- PLL 取值未确认，5 fps 是带宽估算不是实测；
- 镜头 MTF、实际帧率、曝光时间均**未测**；
- 提取脚本的"块边界"靠"下一个 DVPHO 写"判断，**可能截断或混入相邻块**——上板前应逐条核对前 20 条与末 10 条。

## 8. 两个缺口已填（2026-10-19 下午）

### 缺口 1：PLL —— 找到了

应用笔记 **§4.1.4 "YCbCr 5M Capture @ 7.5fps"**，就在 5MP 块的前几行：

| 寄存器 | 我们 720p 表 | **5MP 需要** | 说明 |
|---|---|---|---|
| `0x3108` | 0x01 | **0x02** | system divider |
| `0x3035` | 0x11 | **0x11**（相同） | PLL |
| `0x3036` | 0x46 | **0x54** | PLL |
| `0x3037` | 0x13 | 0x13（沿用） | PLL root/pre-divider |
| `0x3824` | 0x04 | 0x04（沿用） | PCLK divider |

### 缺口 2：DVP 输出配置 —— 在我们的表里，但要**改回来**

| 寄存器 | 我们 720p 表 | 笔记 5MP 块 | 结论 |
|---|---|---|---|
| `0x4300` | **0x60（RGB565）** | 0x30（YUV422 YUYV） | **保留我们的 0x60** |
| `0x501f` | **0x01（ISP RGB）** | 0x00（ISP YUV422） | **保留我们的 0x01** |
| `0x3820` | 0x41 / 0x47 | 0x40 | 按我们的 |
| `0x3821` | 0x00 | 0x06 | 按我们的 |

**⇒ 5MP 表 = 笔记的 139 条（时序/模拟） + 覆盖 4 个格式寄存器为我们现在的 RGB565 + 覆盖 PLL 三项。**

### 新发现的第三个差异：笔记的 5MP 是 **YUV422**，不是 RGB565

- 对**检测**：YUV422 的 Y 就是亮度，反而省掉 HLS 里的亮度转换；
- 对**显示**：颜色会不对，需要转换或直接显示灰度；
- **保留 RGB565 是可行的**（两种格式都是 2 字节/像素，DVP 带宽相同）。

### 帧率

笔记标的是 **5M @ 7.5 fps**（37.8 Mpx/s），而我们 50 MHz AXI 只能吃 25 Mpx/s（≈5 fps）。
⇒ 上板后需要**加大 VTS 把帧率压到约 5 fps**，或把 FCLK0 提到 75 MHz。
