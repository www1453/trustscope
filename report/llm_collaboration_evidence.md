## 1. 工作是怎么组织的：任务书即合同

人给任务书，不给步骤。能用的任务书有六段，缺一段就有一条对应的失败。

| 段 | 内容 | 实例 |
|---|---|---|
| 现场证据 | 已量到的事实，明说「不要重新论证」 | 单曝光 MEAN 17 对融合开 5；相位窗 sync 69.6 对 0.0 ms |
| 任务 | 一个可判定的问题，不是方向 | 「相机 1 能否否掉相机 0 的单视误报」 |
| 验收判据 | 编号、可失败、全部成立才算完成 | clip 0、CLIP_PM < 10‰、MEAN 80..100 |
| 杀死判据 | 写数据之前写好什么结果让方案作废 | D1–D4；零 < 1 格、缺角 ≥ 3 格 |
| 预算 | 硬上限，用完即停 | 2 次 HLS 改动 + 2 次构建；一次 15 分钟板时 |
| 纪律 | 禁令，不是建议 | 一次一个 xsdb 客户端；判据看 MB_FWID0..2 不看 MB_MAGIC；不烧比特流、不断电；一次只让操作者做一个物理动作 |

三段原文：

> 「这是一条**有硬预算、有停止判据**的任务，不是开放式优化。提示词把『不追什么』也写死了。」「阶段 0 的门：对账不到 95%，不许进入阶段 1。」——`dl/w6/PROMPT_PERF_PUSH.md`（2026-09-25 写，`c55e2f7` 入库）

> 「验收判据（三条同时满足才算修好）」；末尾给了回退命令 `git checkout ecc81be -- ps_ui ps_fft_dual`。——`dl/PROMPT_NEXT_SESSION.md`（`d5da7a2`，2026-10-18）

> 「The hypothesis dies if any of these is measured: D1 … D4」；实现的门是「implementation, only if all four pass」。——`dl/XCHECK_20261026_protocol.md`（`e3ec73e`，2026-10-26），写于取数之前，事后没有改判据。

有效的三件：现场证据已量过，子代理不必重测；判据编号且能失败（`MEAN 80..100` 这样的数写出来，含糊的「修好」就通不过）；杀死判据先于数据，于是「不实现」是合法结论——那次 15 分钟的双目窗口只量到 V1/V2，结论就是不实现（`dl/XCHECK_20261026.md` §0）。

失败的两种：只给目标不给零——验收脚本按固定 54 摆位自动前进（`dl/host_qc/accept_range.py:75`），第一个摆位就是零却没人读，到第四块板操作者按了 Ctrl+C；只给问题不给物理前提——那次窗口要的污染板与遮光板不在台面上，半个任务注定「未测」，不是执行失败，是任务书写漏了现场条件。

## 2. 自我纠错记录（六条）

每条四段：主张 → 推翻它的测量 → 修正 → 事后的规则。每条里的「主张」就是当时模型给出的回答；本记录不复述对话原文——仓库里没有对话日志，复述就是编造，能核对的只有结论句、文件与提交。技术报告 13.12 另记三处撤回，本记录不重复。

**E1 相机基线（2026-10-26）。** 主张：整幅面板区域 SIFT+RANSAC 得近平移 (+23,−4) px、比例 1.019，于是「两台相机近似重复，没有可用基线」。测量：整幅里同时有地板、桌腿和板，三个深度，单应描述不了，RANSAC 拟合的是**地板平面**；限制到板框后比例自相矛盾（1.27 x / 1.14 y）；独立的绿色斑块测量给出板心移动 (+190,−4) px。修正：板上平面单应 103 内点、**RMS 1.12 px**（板宽 448 px 的 0.25%），板心视差 **+177.2 / −5.5 px**；密边缘相关峰在 ±24 px 搜索内落在预测的 (0,0)。规则：**每一对真实图只用板的外接框做 ROI，永不整幅**；两个独立映射都通过才认。证据：`dl/XCHECK_20261026_protocol.md:215-231`、`dl/XCHECK_20261026.md:51-54,72-84`（`e3ec73e`、`78762d1`）。

**E2「多帧平均没有收益」（2026-10-26）。** 主张：单变量 A/B 只写 `MB_AVG_N` 1↔8，在 `MB_DIFF_SIGMA` 上 N=1 两次读 38.1/37.5、N=8 三次读 34.6/41.1/42.4，互相穿插，于是平均无可分辨收益。测量：这个量是**被判格有符号差的空间散布**，新参考之后被空间插值残差（1.6–2.8 灰）主导，不是帧噪声；stage 2 的 7.2→4.4 是在另一个统计量、另一块参考上量的；而那份参考与活帧摆位差 **40.4 px**（dx16 646 / dy16 −288），插值残差只会更大。修正：效果没在这个统计量上被测到，不等于不存在；平均保留（`MB_AVG_CNT` 8）。规则：**一个 A/B 只在它量的那个统计量上说话**；对比两侧必须是同一个量——同一参考、同一摆位。证据：`dl/NG_GOODBOARD_20261026.md:29-35,150-166,191-193`（`1efa33d`）。

**E3 一个永远通不过的闸门（2026-10-27）。** 主张（意图）：干净参考必须通过参考质量检查，这是它的零。测量：操作者跑 `accept_range.py --profile full`，背景采纳、参考取好，脚本却拒绝开始——「MB_REFQ_STATE=None (?): the reference's own surface is not clean enough」；同一时刻直接读板：STATE=0、DARK=37。原因：`take_reference()` 用 `d.value("refq_state")` 取值，而 `refq_state` 不在 `ROW_WORDS`（`dump()` 真正去读的集合）里；不在集合里的字读成 `None`；闸门判 `refq != 0`，`None` 失败。修正：`ROW_WORDS` 加进 `refq_state` 等六个字（main.c 544..552），值同时进每一行——**修的是一个元组**。守卫：`accept_range_selftest.py` 加静态用例（每个 `d.value("x")` 必须在读表里），`--check` 把读不到的字命名为 **PLUMBING fault，而不是板故障**（`accept_range.py:475-482`）。规则：**闸门读的字必须在它自己的读集里**；故障从外面看像坏板时，先查读表。证据：`897b390`（17:16）、`f77ea4e`（17:20）、`dl/host_qc/accept_range.py:131-135,425-482`。

## 3. 智能体工作流本身

**并行的是离线的一半。** 帧一旦落盘，分析、重放、拟合就与板子无关：stage Q 的全部数字离线算出，E4 第三行（拟合四边形）的零值没有一次碰过板子。两个 agent 只能在不同文件上并行（E6）。

**串行的是板子，以及板子的状态。** 三条理由：① 同一条电缆只能有一个客户端（E6）；② 一次烧写强制一份新参考，而新参考清空学到的容差图（`ps_ui/main.c:12596`、技术报告 13.13②）——「先改固件、再测总体」不可交换，改一次就要重学一遍；③ 参考是一次性状态：41 行 sweep 共用一份参考（`part_ref` 全 940、`part_ref_changed` 全 0），中途换参考整批作废。瓶颈不是算力，是**操作者的物理动作**：一次一块板。

**子代理报阻塞的三种形状。** 未测就写未测：`dl/XCHECK_20261026.md` 的结论是「E2 for V1 and V2 only」，V3/V4 明写没测，所以什么都没实现。列一张「需要板子才能验」的表：`dl/host_qc/README.md` §9 有 20 项，每项一列「怎么查」、一列「预测/风险」。把前置条件做成拒绝：`accept_enter.py` 在零不合格时拒绝继续。

**反复出现的失败模式：代转一个没有发生的物理动作。** 两次，都有文件。① 2026-10-25，`STAGE_H` §5.3——两次请求污染板都被代转，测量结束时相机里仍是一块干净的好板；只能记 **NOT ESTABLISHED**，既不是 PASS 也不是 NG，因为「这一块是不是那块污染板」不能从图像分辨（`dl/STAGE_H_20261025_registration_accuracy.md:170-182`）。② 同一天，`u1_seat2.csv` 先被记成单元 #2、又被代转记成 #4，操作者最后确认它是单元 #1 的第二次摆位（`dl/STAGE_I_20261025_tolerance_map.md:118-126`）。反制：**摆位只在操作者确认之后才记一行**——`accept_enter.py` 一块板一次 Enter、一行（`:19-23`）；sweep 的标签盲问，先要标签再显示读数（`dl/SWEEP_20261027.md:211-218`）。

还有一条上下文纪律：当晚的严重事故（删掉全局时钟、错误测量、板上跑飞）都发生在上下文接近上限时，所以**用到一半就交接**（`AGENTS.md` 第六节）。

## 4. 模型不被允许决定的事

四件事保留给人或给测量，理由不是「不信任模型」，而是代价不对称：

| 不允许 | 理由 | 落在哪里 |
|---|---|---|
| 改阈值 | 一个阈值同时是好板与缺陷板的函数，改它等于同时改两侧；只能从总体直方图选 | 30 灰与 8 格来自三组总体（13.3）；BG_MASK_THR 24 = 空皮带 p99+1（13.5） |
| 把统计量接进判定 | 接进去之后一次失败就是产线误杀，且分不清是统计量还是阈值 | publish-only，`diff_verdict()` 不读它们一个字（`ps_ui/main.c:2513`，`4f1948b`） |
| 烧写、断电、换比特流 | 烧写强制新参考、清空学到的状态，等于销毁正在被引用的条件 | 提交信息写 NOT FLASHED（`75a65dc`）；双目窗口的固件由另一个 agent 在窗口前烧好（`XCHECK_20261026.md` 首段） |
| 没测零就跑总体 | 54 摆位的账（E5）：零比缺陷大时，总体里没有新信息 | `accept_enter.py:117-126`；技术报告 15.8 |

## 5. 可迁移的部分

**任务书模板（六段）**：现场证据（明说不要重测）→ 一个可判定的问题 → 编号验收判据 → 杀死判据（写于数据之前）→ 硬预算 → 禁令式纪律，外加一条回退命令。少哪一段对应一种已知失败：少零 = E5；少杀死判据 = E4 第三行那种「看起来应该可以」的设计；少回退 = 改动没法撤回。

**五条判据纪律。**

1. **先测零，再测总体。** 零是最便宜也最有决定性的一行：不需要缺陷板、不需要排队，只需要把参考板放回原处、人走出画面。它只有两个数和一个 `if`。
2. **结论不得强于证据。** 这条写在 `ps_ui/main.c:2513` 的注释里，也写在每一章的「未验证」节里：一个结论只能说到证据允许的那一层，说不清就标「未验证」。
3. **永不为了让测试通过而调阈值。** 配准的置信闸门 `REG_CONF_LIM` 192 在 13.6–13.8 三次改动里没动过；E4 第三行的设计按预注册判据作废，没有调参去凑。
4. **失败写成撤回，不是删掉。** 技术报告 13.12 的三处撤回、第十五章整章的否证，都在正文而不在附录。
5. **报告里的一个数，仓库里要有一个文件；被 `.gitignore` 忽略的文件不算证据。** 这条来自写作过程：把每个引用路径喂给 `git ls-files`，一条命令就发现报告 15.4 称为「committed sweep」的 41 行 CSV 从未入库（同一条命令还查出另外几份未跟踪），已在 `95c1a5f` 补齐——成本一条命令。
