# 模板 · 上板bring-up 清单（电气 + 软件两条线）

> **适用场景**：一块新板子/新模块第一次上电；或者一块**曾经好使**的板子突然不出图。
>
> **这份清单的形状比内容更值钱。** 具体引脚、具体寄存器是每个项目自己的；
> 但"先断电阻测 → 再认脚 → 头 30 秒守着 → 用一个**硬件级**计数判断死活"
> 这个顺序，在任何带外部模块的板子上都成立。
>
> 本项目的完整实例（AN5642 相机模块，逐步骤带万用表档位与预期读数）见
> `dl/CAMERA_BRINGUP_CHECKLIST.md`。这里给的是可以搬到别的板子上的骨架。

---

## 一、上电前：只做三件事，都不通电

- [ ] **认脚，不要信丝印。** 用厂商文档 + 万用表通断档，把"这个座子的第 N 脚是什么"
      逐个确认一遍，写进一张表。丝印错、文档版本错、排线反接各踩过一次。
- [ ] **短路检查。** 电源与地之间电阻档：不能是 0 Ω。这一步对准的是最常见的失效模式
      （模块内部短路，或上一次插反留下的损伤）。
- [ ] **方向检查。** 每一个双向/输出引脚，先写清"谁驱动谁"。两个输出对顶 =
      烧 IO 或烧模块。本项目把这条写成了一张表（16 个相机数据脚必须是 INPUT、
      I2C 必须是 BIDIR、复位必须是 OUTPUT），并在**每次构建后**用生成的引脚报告核对。

> **判据**：这三件事做完之前，电源开关不要碰。做完之后，把它写成文件（不是记在脑子里）——
> 下一个接手的人需要它。

---

## 二、首次上电：头 30 秒人不要走开

- [ ] 手放在电源开关上，上电，**看电流**（或至少看指示灯的行为是否与预期一致）。
- [ ] 30 秒内出现异常（电流飙升、发热、异味、指示灯乱闪）⇒ **立刻断电**，回到第一节。
- [ ] 30 秒内一切正常 ⇒ 才开始接调试器。**不要**"先接上 JTAG 看看"再上电。

---

## 三、软件侧：让"它到底活没活"变成一个数字

顺序是这样，**不能跳**：

1. **先确认目标是对的。** 调试器列出的 target 编号会漂移
   （正常 1=APU / 2=CPU；DAP 出错时 1=DAP / 2=芯片）。
   所以脚本第一句必须是断言，不是假设：
   ```
   if {![string match "*Cortex-A9*" [targets]]} { error "wrong target" }
   ```
2. **先读一个已知答案。** 读芯片 ID / 版本寄存器，与文档值比对。
   对不上就停 —— 后面的所有读数都不可信（案例 M14：探针坏了却被用来判定"目标坏了"）。
3. **接外部模块之前，先让内部通路出数。** 本项目用 PL 里的 PCLK 计数器：
   `CPU 读一个计数 → 有没有在涨`。**黑屏时的第一动作就是看这个计数**，
   它把"图没出来"分成"根本没有像素时钟"和"有像素但通路不对"两类，
   而这决定了接下来查硬件还是查软件。
4. **I2C 这类有状态的通道，必须在同一个会话里初始化完再用。**
   本项目：`rst -system` + `ps7_init` + `ps7_post_config` **同一会话**里访问 I2C；
   缺 `ps7_post_config` 或换一个会话，读回全是 `-1`/ARB_LOST。
   **"读不到"不是"器件坏了"**，先检查你会话的状态。
5. **批量读内存/寄存器的单位要写清。** 本项目 `mrd -bin -file` 的长度参数按**字**（32 位）计，
   不是字节 —— 传字节数会得到一半的数据，而它**不会报错**。

---

## 四、重烧比特流 / 换固件：这一步最容易"把好板子弄成坏板子"

- [ ] PL 当前是空的吗？判据不是"我觉得"，而是三者之一：刚冷启动 / 刚 `rst -system` /
  刚烧过同一份比特流且没跑固件。
- [ ] **不要**把 `reset` 和 `burn` 串在同一条命令里 —— reset 失败时 burn 仍会执行。
- [ ] 烧完读回一个 PL 寄存器，确认 PL 真的在（不是全 `F`）。
- [ ] 屏/面板类输出：显示异常时**先给面板断电**，不要给整机断电（面板会锁存最后一帧）。

完整版见 `../checks/PRE_BURN_CHECKLIST.md`（每一条都对应一次真实事故）。

---

## 五、永远留一条退路

- [ ] 有一份**已知可用**的比特流/固件，放在一个不会被构建覆盖的目录里，带哈希。
- [ ] 改任何东西之前备份，回写后**校验哈希** —— "拷过去了"不等于"文件对了"。
- [ ] 恢复之后不要相信脚本打印的 `reverted`：**读回哨兵值**。

## 失效条件

- 纯仿真、无外部模块的项目：第二节、第三节的 3–5 步大部分用不上。
- 板子已经**长期稳定运行**、只改纯软件：只需要第四节（重烧纪律）与第五节（退路）。
- 本清单**不覆盖**安全规范（绝缘、接地、高压）—— 那属于你们实验室自己的规程。
