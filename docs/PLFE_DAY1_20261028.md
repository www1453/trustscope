# PL front-end integration, day 1: the two unknowns are settled, and the third says it does not fit

**Date:** 2026-10-28
**Scope of this document:** steps 1-4 of the brief's order, done; step 5 answered —
**implementation failed at placement because the device is out of slices**, so there is no
WHS to read and no bitstream; steps 6-7 therefore never happen.

> **READ `dl/PLFE_DOES_NOT_FIT_20261028.md` FIRST.** It is the outcome. This document is how
> the two gating unknowns were settled on the way there, and everything in it is still true.

## 0. The one-paragraph answer

The interface RTL exists and simulates bit-exact; the tear bracket is **measured at 88.0 ms**
against the 18.43 ms the front end needs, so the timing assumption that gated the whole
integration **holds with 4.8x margin**; the block design now contains the front end on a
dedicated **HP2** port and passed its own validation gate with **0 ERROR messages** and the
global clock net **gaining** pins (62 -> 68); and the firmware carries the identity mechanism
with `MB_PLFE_ON` defaulting to **0 = bypassed**. What is NOT done is the part that needs a
human and a bitstream: loading it, and showing the same boards get the same verdicts.

## 2. Step 2: the AXI wrapper, simulated before anything touched the block design

| file | what it is |
|---|---|
| `dl/pl_frontend/pl_fe_axi_lite.v` | AXI4-Lite control slave, 12 registers |
| `dl/pl_frontend/pl_fe_rd.v` | AXI4 read master: the named store -> one GREEN byte per pixel, raster order |
| `dl/pl_frontend/pl_fe_wr.v` | AXI4 write master: one 32-bit word per statistic, production order |
| `dl/pl_frontend/pl_fe_top.v` | the three + `pl_fe_core`, and the identity handshake |
| `dl/pl_frontend/tb_pl_fe_top.v` | the known-answer test |
| `dl/pl_frontend/run_xsim_top.ps1` | `XSIM_TOP_ALL_OK` in one command |

**One AXI4 master port, not two.** The read master drives AR/R and the write master drives
AW/W/B: the five AXI channels are independent, so a single interface carries both with no
arbitration and no second interconnect in the block design. Both HP2 and HP3 are free and
only HP2 is used.

**The identity mechanism, implemented as specified.** One write to `TRIGGER` carries
`{seq[31:16], store[1:0]}`; the PL latches both on the same clock, reads THAT store, and
echoes `seq` with its statistics. `done` is asserted only when the read completed, no AXI
response was an error, the core reported no overflow or misalignment, and the word count
equals the geometry's own number (46,800). The PS demands `done=1 && seq_echo == loop_seq`
at `avg_sample()`; anything else runs the existing 936,000-read pass unchanged. A failed
identity can only be **slower, never wrong**.

### The simulation result (measured)

```
XSIM_TOP_ALL_OK
  all 464 statistics words byte-equal to a second, un-wrapped pl_fe_core fed the same picture
  read  range exactly [store_base, store_base + 2,764,800)   (on the 128x72 test frame)
  write range exactly [stats_base, stats_base + 1,856)
  9303 cycles for 9216 pixels  -> 1.009 px/clk
  EN=0: 0 AR transactions issued
  AXI read error:       done=0, err=1, seq_echo still published
  trigger while busy:   dropped (trig_drop=1), first pass still completes
  second trigger:       seq_echo follows the new seq
```

**Two silent bugs the simulation found, both fixed and named in the source headers:**

1. The read and write FIFOs updated their fill counters in **two separate non-blocking
   assignments**, so a push and a pop in the same cycle **lost the push**. The counter
   drifted, `v_ready` deasserted with an empty FIFO, and the pass deadlocked with the core's
   result FIFO full. It presented as "the write stopped at 350 of 464 words".
2. The read master presented its pixel **one cycle late**, because `s_data` was registered
   while the group register moved on the same edge.

**A negative control that needed to be stronger, and why that matters.** Corrupting one green
byte by ±1 in the transport was **not visible** in the statistics: the block divides by 9 and
by 25 **with truncation**, so a one-count change in one of nine taps usually disappears. The
control that works perturbs 16 consecutive beats by a large amount and is rejected with 15
mismatched words. Anyone writing a weaker test for this block would be measuring nothing.

## 4. Step 4: the block design

`ps_fft_dual/plfe_bd_edit.tcl`, run under AGENTS.md's rules, and **its own gate passed**:

```
BASE  |errors=0 |clk_pins=62 |hp2=0 |periph_num_mi=18
HP2   |enabled -> 1
CELL  |created pl_fe_top_0        (module reference; m_axi/s_axi inferred as interfaces)
HP    |created plfe_hp            (1x1 AXI interconnect)
CLK   |FCLK_CLK0 -> plfe_hp aclk/S00/M00, pl_fe_top_0/clk, AND processing_system7_0/S_AXI_HP2_ACLK
RST   |proc_sys_reset_0/peripheral_reset -> pl_fe_top_0/rst  (active high, same domain)
LITE  |ps7_0_axi_periph NUM_MI 18 -> 19, M18_AXI -> pl_fe_top_0/s_axi
ADDR  |SEG_pl_fe_top_0_reg0 = 0x40000000, range 0x1000
AFTER |errors=0 |clk_pins=68 |hp2=1
GATE  |PASS
SAVE  |saved
```

**The first two attempts FAILED the gate and correctly saved nothing.** The first failed on
`/processing_system7_0/S_AXI_HP2_ACLK` — the PS block exposes each HP port's clock as a
**pin**, not an interface, and the ERROR list, not an assumption about which ports carry a
clock, is the authority (casebook **B18b**). The gate is what kept a half-modified block
design off the disk.

**HP2, not a tap on `mem_intercon_cap`.** That interconnect already fans **five** masters
into HP0. Mixing ~150 MB/s of statistics reads into HP0 would put them in contention with the
VDMA that fills the very stores the tear gate is judging.

## 5. Step 5: synthesis and implementation — IT DOES NOT FIT

**`place_design` FAILED: 13,300 slices in the device, 9,677 available, 10,126 required by the
unplaced instances — short by ~449 slices (4.6 %).** LUTs 41,092 of 53,200 available capacity.
This is an area failure, so **WHS was never reached** and the +0.037 ns question stays open
downstream of it. Full analysis, the four options left to the owner, and the restore:
**`dl/PLFE_DOES_NOT_FIT_20261028.md`**.

**The front end plus its whole AXI wrapper, synthesised as its own out-of-context block
(measured, `two FFT.runs/design_1_pl_fe_top_0_0_synth_1/`):**

| resource | used | notes |
|---|---|---|
| **Slice LUTs** | **2,711** | against the 1,863 floor for `pl_fe_core` alone: the wrapper costs **+848 LUT** |
| **Slice Registers** | **1,577** | against the 571 floor: the wrapper costs **+1,006 FF** |
| **Block RAM Tile** | **0** | the promise that matters at 138.5 of 140 holds |
| **DSPs** | **0** | and at 219 of 220 |

Baseline it must be added to (copied aside **before** the new runs could overwrite it, because
these two files are the only evidence for the "before" side):
`dl/pl_frontend/baseline_impl_20261024/` — **WHS +0.037 ns**, WNS +0.908 ns, LUT 36,513,
FF 58,900, BRAM 138.5 of 140, DSP 219 of 220.

Projected totals from those two measured halves: **LUT 39,224 (73.7 %)**, FF 60,477 (56.8 %),
BRAM 138.5 (unchanged), DSP 219 (unchanged) — **plus** the 1x1 AXI interconnect and its two
automatic protocol converters, which live in the top level and are not in either number. The
integration note's honest expectation was 75-78 % LUT; that is where this is heading.

**Read WHS first.** Hold cannot be fixed by slowing a clock; a hold failure stops the work and
`safe_bitstreams/BIT_20261024_fp1.bit` goes back on the board.

### One false alarm, recorded because it will happen again

The top-level `report_utilization` straight after `synth_design` reads **0 LUTs, 0
registers**, and synthesis finished in 91 seconds instead of ten minutes. That looks like an
empty netlist and it is **not**: this project synthesises every IP out-of-context, so the
top-level RTL netlist contains stubs ("done synthesizing module 'design_1_axi_vdma_0_0'
(0#1)") and the logic is linked in from the OOC DCPs during `link_design`. The authoritative
numbers are the **placed** ones. The build was killed on the false alarm and relaunched from
the completed synthesis; **`reset_run impl_1` had deleted the whole `impl_1` directory**,
which is why the two baseline reports were copied out before any of this started.

## 6. The firmware: the identity mechanism, and a word-number defect it exposed

`ps_ui/main.c` now carries (built, `TSC1 EAA4676C`, layout checks pass):

* `MB_PLFE_ON` (word **575**), host-written, **default behaviour 0 = bypassed**: a boot with
  no host script runs exactly the shipped path.
* `plfe_name_store()` at the store selection, immediately after `tear_sig_capture()`: one
  register write naming `{loop_seq, store}`, and it refuses unless the PL's ID word reads
  `0x504C4645` ("PLFE").
* `plfe_try_sample()` inside `avg_sample()`, **after every existing guard** so the same loops
  are sampled either way: it demands `done`, `seq_echo == loop_seq` and `VALUES == 46,800`,
  invalidates the cache over the statistics buffer, then feeds `AVG_LATT_SUM`, `FINE_SUM`
  and `AVG_CELL_SUM` exactly as the PS loops do. The PL's `ARR_RANGE` is produced and not
  accumulated, because `avg_sample()` does not use it. **The fallthrough is the shipped
  936,000-read pass, unchanged.**
* The statistics buffer is `0x12AC0000` (187,200 bytes), chosen because it is above the
  highest address this firmware otherwise uses (`0x12AB0FFF`) and inside the MMU's
  cacheable `0x12800000 + 3` section mapping.

**THE WORD-NUMBER DEFECT IN THE BRIEF, WHICH IS NOW FIXED.** The integration note reserved
**572** for `MB_PLFE_ON` and established 572-600 as free by scanning every `#define MB_*` in
`ps_ui/main.c`. That is **one namespace**. `dl/host_qc/qc_mailbox.py` already declares
**572 = `eg_margin`, 573 = `eg_roi`, 574 = `ref_avg`** (the stage-L line, absent from this
firmware). Writing tick counts to 573/574 would have made `accept_range.py` print them as
"cells the range statistic judged" and "frames the reference mask is a mean of" — **garbage
in a diagnostic, presented authoritatively**, which is the failure this project keeps paying
for. The six words now live at **575-579 and 582**, free in `dl/mb_free.py` *and* in the host
map; all six are declared in `qc_mailbox.py` in the same change as the firmware that writes
them, and `python dl/host_qc/check_words.py` passes.

| word | name | direction |
|---|---|---|
| 575 | `plfe_on` | HOST: 1 = permit the front end (default 0) |
| 576 | `t_brk` | PS: tear-bracket ticks (measured 88-100 ms) |
| 577 | `t_brkn` | PS: how many times `t_brk` was written |
| 578 | `plfe_used` | PS: loops served from PL statistics |
| 579 | `plfe_st` | PS: last PL STATUS word |
| 582 | `plfe_vals` | PS: last PL VALUES word (must be 46,800) |

## 7. The station: what I did to it, and what it reads now

**I changed the station's firmware and then changed it back.** Timeline, all measured:

| time | what | `MB_FWID` | state |
|---|---|---|---|
| 16:11 | start of session | `TSC1 904A1527` | ready=1, PASS, mean 505-509, ref 659, bg_state=1 |
| 16:34 | bracket-instrumented firmware loaded (`rst -cores` + `dow`) | `TSC1 4711380A` | ready=0, mean 847, ST_CODE 255 |
| 16:41 | shipped firmware rebuilt from backup and reloaded | `TSC1 904A1527` | ready=0, mean 756, ST_CODE 255, PART_REF 984, bg_state=0 |
| ~17:05 | settled | `TSC1 904A1527` | **ready=1, verdict PASS, mean 513, ST_CODE 2, PART_REF 904, bg_state=0** |

Two things to say plainly:

1. **A firmware-only reload does NOT preserve the station.** The brief says a bitstream load
   destroys the reference; a `dow` without `rst -system` does too, more subtly:
   `MB_PART_REF` moved 659 -> 984 -> 904, and only `ref_take()` writes that word, so a
   reference was taken at some point after my first read. `MB_ST_CODE = 2` says the boot
   self-test's **background** check fails and `MB_BG_STATE = 0` says the background is not
   valid. The verdict currently reads PASS and the exposure is pinned at 8698, but **the
   background is not captured and the reference is not the 659 the brief quotes.**
2. **The operator step is therefore required before any A/B** — clear the belt, `MB_CMD=12`,
   a good board, `MB_CMD=9` — and it is required for the *firmware* build too, not only for a
   bitstream.

## 8. What is NOT done, and exactly what stops it

| item | state | what it needs |
|---|---|---|
| WHS with the front end and the wrapper | **build running** | nothing but time; read WHS first |
| a bitstream that loads | not attempted | the WHS result, then `write_bitstream`, then the operator |
| `MB_PLFE_ON=1` producing the same verdicts on real boards | **not attempted** | an operator, a healthy station, and boards |
| the `cam` A/B at 12 windows per arm | **not attempted** | the same, plus the host script |
| DDR contention from ~150 MB/s of HP reads | **not measured** | the same A/B; the bracket is wide enough that it is not expected to bite |
| the bracket on a healthy 168 ms station | **inferred ~56 ms** | a re-measure after the operator restores the station |

**Nothing here is blocked by a defect.** The two things that could have stopped the
integration — an interface that could not be written, and a tear bracket too short for an
18.43 ms read — are both settled, the second by measurement.

## 9. The order for day 2, in one place

   If it is negative: stop, reload `safe_bitstreams/BIT_20261024_fp1.bit`, write it up.

   the station (clear belt -> `MB_CMD=12` -> good board -> `MB_CMD=9`) **first**, because the
   load destroys both the reference and the background anyway.

   control arm and it must be taken with the NEW bitstream, because the bitstream is what
   changed.
4. Only then `MB_PLFE_ON = 1` and interleave A/B at **12 windows per arm** on `MB_T_CAM`
   (word 73), which resolves 1.4 ms; the loop total cannot carry the claim (79% pooled
   spread). `plfe_used` (578) must be climbing, or the arm is not testing what it claims.
5. The verdict check: same boards, same verdict, same `DAREA`. A hardware front end that
   changes a verdict is a bug, not a faster answer.
