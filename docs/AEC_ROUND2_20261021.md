### 7.4 顺带修掉的两个真问题（都不是"调参"）

1. **步长不对称 → 只会走、不会停**：加亮 ×9/8（+12.5%）配压暗 ×7/8（−12.5%），
   一个来回乘出 (9/8)(7/8)=63/64，每轮掉 1.6%。控制器只要交替，就必然缓慢漂走，
   **这不是噪声，是算术**。改成 ×9/8 与 ×8/9（乘积为 1）。
2. **反向没有迟滞**：实测这个场景的裁切千分比在相邻两次评估之间就会 4↔11 跳
   （高光斑，不是光照变化）。12.5% 的步长下，这点噪声足以让"加亮→过裁→压暗→过暗→加亮"
   永远循环。现在**换向要连问两次**（同向不受影响），板上能看到 `dec=9`（扣住）随后才动作。

### 7.5 没做成的 / 要记的

- **state 3 没在板上触发过**。用 `MB_CLIP_LIM=1` 去逼它，结果控制器压暗到 727 后裁切自己掉到 0，
  够不到地板；反而暴露一个边界 bug：`lim/2` 在 lim=1 时等于 0，`clip>=0` 恒真，
  加亮分支永远进不去。已改成 `(lim+1)/2`。
- **mean==0（全黑）会被判"已收敛"**：这是上一轮"量具坏了不许加亮"的护栏的副作用。
  镜头盖住时它不会去加亮。这条仍是待修项，且正好是触发 state 3 的另一条路。
- 面板现在用 ASCII 显示 `AEC OK / ADJ / STUCK` + `CANNOT ADJUST`；
  中文"我调不动"需要重生成字模（`dl/gen_cn_font.py` 的 MSGS 加一条），本轮没做。
