# 烧录前检查清单（强制）

> 来源：2026-10-19 的实际事故。同一天内连续两次在**运行中的设计**上重烧比特流，
> 面板锁成条纹，只能整机冷启动恢复。事故记录见 `pitfalls/measurement-traps.md` M44。
>
> **这份清单不是建议。任何一次烧录之前，逐条打勾；有一条不满足就不要烧。**

## 烧录前

- [ ] **PL 当前为空**。判据不是"我觉得它是空"，而是三者之一：
  - 刚**整机冷启动**（断电→等 10 秒→上电）；
  - 刚执行过 `rst -system`，**且**目标是对的（`targets -set -filter {name =~ "*Cortex-A9*#0"}` 先选）；
  - 刚烧过同一份比特流且没有跑任何固件。
- [ ] 如果刚刚还在跑固件/出图：**先 `rst -system`，等它返回，再烧**。
- [ ] 不要在**一条命令行里**串联 "reset; burn" —— reset 失败时 burn 仍会执行，
      事故就是这样发生的（B/M44）。
- [ ] 烧录前确认目标：`[targets]` 里含 `Cortex-A9`；不含就停。

## 烧录后

- [ ] 读回 `v_tc` 或任一 PL 寄存器，确认 PL 真的在（不是 `0xFFFFFFFF`）。
- [ ] 如果屏幕是条纹 / 花屏且不恢复：**不要再烧一次**。
      那是面板锁存，软件救不回来 —— 整机冷启动。
- [ ] 记录：本次烧录前 PL 的状态（冷启动 / rst -system / 已在运行）。

## 一句话

**"重烧"这个动作本身不危险；危险的是在"设计还在跑"的时候重烧。**
每次烧之前问自己一句：**现在 PL 里是空的吗？凭什么这么认为？**
